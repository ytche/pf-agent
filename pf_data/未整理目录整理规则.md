# 未整理目录内容整理规则

> 适用于从 `未整理` 目录向已有分类目录合并规则内容的后续工作。

## 1. 适用范围

- 处理 `pf_data/phase1/pf_rules_md/` 下 `未整理 → <来源书>` 中的 Markdown 文件。
- 当前已完成试点：`未整理 → 惧怖冒险HA`。
- 后续规则书（如 `未整理 → <其他书>`）按本规则执行。

## 2. 核心原则

1. **先读后分**：必须阅读文件内容，理解条目类型后再决定目标位置，禁止直接按文件名搬家。
2. **每本规则书独立聚合**：条目型内容（专长、背景特性、物品、仪式、专精等）一律按"每本规则书一份聚合文件"组织，**不**将不同来源书的条目合并到同一聚合文件。详细判断流程见 §4.0。例外：货品服务/炼金/毒药类内容（§4.2）、已有核心权威页面的内容（§4.2、§4.6）。
3. **先查目录再创建**：通过 `md_mapping.json` 的 `toc_path`、目录结构、文件名三种方式定位目标文件，禁止一见没有同名文件就新建。
4. **去重**：写入前用标题名或隐藏标记 `<!-- <来源>-source:<md名> -->` 检查目标文件，已存在则跳过。
5. **保留原文件**：所有写操作在副本目录 `pf_data/phase1/pf_rules_md_organized/` 上进行，禁止修改原 `pf_data/phase1/pf_rules_md/`。
6. **来源必标**：每一条合并进目标文件的内容都必须标注来源。
7. **禁止重建副本目录**：整理脚本必须增量写入，不得删除或重建整个 `pf_rules_md_organized/`；若需重跑，应仅删除目标文件中的自身内容后重新追加。
8. **整理完即提交**：每整理完一个规则书，必须提交一次 Git，保存该规则书的整理结果、脚本与报告文件。

## 3. 来源标注规则

### 3.1 格式

```markdown
> 来源：<书名>，<页码>（如有），未整理 → <L2来源书名> → <L3标题>
```

示例：

```markdown
> 来源：惧怖冒险（Horror Adventures）HA，82页，未整理 → 惧怖冒险HA → 专长
```

### 3.2 位置

- **必须标注在每一项的标题下一行**，不允许在段落末尾统一标注。
- 职业变体：标在变体名称标题下一行。  
例：
  ```markdown
  ## 死亡德鲁伊DEATH DRUID（德鲁伊变体）

  > 来源：惧怖冒险（Horror Adventures）HA，页码见原书，未整理 → 惧怖冒险HA → 变体/职业选项 → 德鲁伊
  ```
- 种族替换特性：标在特性名称下一行。
- 专长：标在专长名称下一行。
- 物品：标在每个物品条目标题下一行。
- 天赋职业奖励：标在 `**<种族>天赋职业奖励**` 标题下一行。

### 3.3 章内子块标注层级

- **独立条目**：标在标题下一行（按 §3.2）。
- **章内子块**（同一物品/专长/法术下的延伸部分，如"炼金配方"、"变体选项"、"特殊说明"）：不需独立标注，归属继承自所属条目。
- **章/小节级聚合**：当一个聚合文件内含多条同质条目（如 `AM_物品.md` 中贝尔克泽恩物品、矮人魔啤各为一个子节），使用**章级 `> 来源：...`** 标注一次即可，子节内条目不必重复标注。
- **跨页合并的小节**：当源书聚合文件被合并到核心页（如 §4.2 AM_物品 → page_212），使用 `## <来源书> 特有 <子分类>` 作为小节分隔，不需重复 `> 来源：...` 标注（小节标题已表明归属）。

## 4. 分类处理规则

### 4.0 源书聚合原则

> **每本规则书均独立一个 `<来源书>_<类型>.md` 聚合文件**；通用与源书特有条目都按来源书聚合，**不**将不同来源书的通用条目合并到同一聚合文件。
>
> 说明：
>
> 1. 专长、背景特性、物品、仪式、专精等**条目型内容**一律按"每本规则书一份聚合文件"组织，例如 `专长/反派法典VC_专长.md`、`专长/炼金术手册AM_专长.md`、`专长/闹鬼英雄手册HHH_专长.md`。
> 2. 同一类型不允许出现"通用聚合文件"（如把 HH/HHH/AM 的通用专长也写进 `反派法典VC_专长.md`），即使是通用条目也只属于其原书。
> 3. 源书归属通过 `<!-- <来源>-source:<md名> -->` 隐藏标记和 `> 来源：...` 行内标注共同区分。
> 4. 例外：少数内容（毒药、炼金药、货品服务等）若已有 CRB/ACG/APG 等核心规则书的权威页面（如 `装备_魔法物品/货品服务/page_212.md`），按 §4.2 货品服务规则追加到该页面，不创建源书聚合文件。
>
> 反例（禁止）：把 HH 的"战斗活力"专长合并到 `反派法典VC_专长.md`。
> 正例：HH 的"战斗活力"专长应单独写入 `专长/治疗者手册HH_专长.md`。

### 4.4 行尾换行符处理

脚本追加内容到目标文件时，必须保持与目标文件一致的换行风格，避免在 diff 中产生大量"换行符变化"噪声：

1. **读取检测**：用 `read_bytes()` 检查目标文件是否含 `\r\n`（CRLF）。含则视为 CRLF，否则视为 LF。
2. **写入保持**：用 `write_bytes(content.encode('utf-8'))` 写回，不要用 `write_text()` 走默认转换。
3. **拼接归一化**：合并多源内容时（如撤回流程提取的块可能来自不同文件），先用 `normalize_to_nl(text, target_nl)` 归一化到目标文件风格（先把所有 `\r\n` 与 `\r` 转为 `\n`，再按目标风格转回）。
4. **结尾处理**：追加前确保目标文件以换行符结尾，追加内容以换行符开头。
5. **示例**：
  ```python
   def read_text(path: Path) -> tuple[str, str]:
       raw = path.read_bytes()
       has_crlf = b'\r\n' in raw
       return raw.decode('utf-8'), ('\r\n' if has_crlf else '\n')
  ```

### 4.5 标题解析通用规则

解析条目标题时需处理以下变体，按顺序应用：

1. **跨行加粗标题**：`**浓缩烧瓶（Focusing\nFlask）`** → 先预合并为单行。
2. **单行加粗标题**：`**浓缩烧瓶（Focusing Flask）`** → 标准模式。
3. **纯文本标题（无 `**` 标记）**：`瞬间炼金（Instant Alchemy）` → 用纯文本正则匹配。
4. **纯文本跨行**：`瞬间炼金（Instant\nAlchemy）` → 合并后用纯文本正则匹配。

**处理流程**：

1. 先将相邻行按"加粗未闭合"或"标题起始后未结束"的条件预合并。
2. 再用加粗模式 `^\*\*[^*]+\*\*` 优先匹配。
3. 未匹配再用纯文本模式 `^[^*\s].*（English Name）` 兜底。
4. 子条目过滤：长度过短、无中英名结构、无元数据的行应跳过。

### 4.6 单源书多聚合文件

- 例：AM 创建了 6 个聚合文件
  - `专长/炼金术手册AM_专长.md`（7 条专长）
  - `职业/核心职业/炼金术手册AM_神话炼金.md`（神话道途能力 + 神话物品）
  - `装备_魔法物品/魔法物品/炼金术手册AM_自发炼金术.md`（炼金流程与工具）
  - `装备_魔法物品/魔法物品/炼金术手册AM_强化人造人.md`（人造人改装）
  - `装备_魔法物品/魔法物品/炼金术手册AM_装备.md`（兽人武器、卡塔佩什吸毒用具）
  - `装备_魔法物品/魔法物品/炼金术手册AM_真菌移植物.md`（真菌眼、延展藤蔓）

**原则**：

- 命名空间：均使用 `<来源书>_` 前缀，避免污染其他类型目录。
- 位置：按内容类型归入对应目录（专长进 `专长/`、物品进 `装备_魔法物品/魔法物品/`、神话道途进 `职业/核心职业/`）。
- 拆分依据：按"读者查找路径"决定——专长按 §4.0 专长目录，物品子分类按 §4.1/§4.2 装备目录，神话道途按职业目录。
- 例外：若某子分类无合适目录，可放 `规则/<来源书>_<类型>.md`（§4.1 独立规则行）。

### 4.7 职业子类别 → 目标页面映射

> 整理"未整理"目录下的规则书时，若条目属于某个职业的子类（天赋/巫术/奥能/秘示域/血统/狂暴之力/传世名作等），§4.1 仅给出按内容类型选择目录的总原则，**具体职业的子类条目落到哪个 page 文件**需查询独立的映射表。

**映射表位置**：`pf_data/phase1/class_subcategory_mapping.md`

**使用流程**：

1. 在源书聚合文件 / 新整理的源条目中判断"职业+子类"归属。
2. 查询 `class_subcategory_mapping.md` §1 定位目标文件路径（已知职业的全部子类映射均登记在内）。
3. 追加前用 §2 的隐藏标记 `<!-- <来源>-source:<源文件名>:<条目名> -->` 去重（与 §10.2 脚本去重逻辑一致）。
4. 文件级移动 / 删除 / 合并操作记录到 `class_subcategory_mapping.md` §3 审计日志，方便回溯文件历史。

**与本规则的关系**：

- §4.1 给出"按内容类型选目录"，§4.7 给出"具体职业子类的目标 page"；两者必须配合使用。
- 整理每本新规则书前，**必须**先查 `class_subcategory_mapping.md` §1 确定目标文件；无对应条目时新建并在映射表 §1 增加记录。
- §1.4 文件状态图例（✅ 已存在 / ⚠️ 待迁移合并 / ⚠️ 未整合 / ❌ 暂无）帮助快速识别目标文件是否已就绪。

**典型场景**：

- 盗贼天赋 → `职业/核心职业/盗贼/page_62.md`
- 女巫巫术 + 庇护主法术 → `职业/基础职业/女巫/page_92.md`
- 魔战士奥能 → `职业/基础职业/魔战士/page_83.md`
- 野蛮人狂暴之力 → `职业/核心职业/野蛮人/page_36.md`
- 吟游诗人传世名作 → `传世名作汇总.md`（根目录聚合）
- 术士血统 → `职业/核心职业/术士/page_64.md`

**迁移判定规则**（基于 §4.7 + §6 技术约束）：

当某条目在 §1 标为 ⚠️ 待迁移合并时，整理脚本应：

1. 先将根目录（或错位目录）的旧内容合并到目标文件（保留 `> 来源：...` 标注）。
2. 在目标文件中追加本规则书的新条目。
3. 删除旧文件（仅当确认内容已完整合并且带隐藏标记），删除动作在 §3 审计日志留痕。

## 5. 特殊来源书

### 5.1 怪物种族来源书（如怪物法典MC）

- 该书各章节均为**怪物种族**，非玩家可选种族。
- 其种族变体、职业变体、专长、法术、物品等规则是否应合并到玩家种族/职业目录，**需单独确认**。
- 在方案明确前，暂不自动合并进 `种族/核心种族/` 或 `职业/` 下玩家职业的已有页面；可暂存到 `规则/<来源书>_...` 或单独分类目录。

## 6. 技术约束

1. **目标文件定位**：优先使用 `md_mapping.json` 的 `toc_path` 反向索引，其次按目录和文件名模式搜索，最后才新建。
2. **目录优先级**：同一文件名若同时存在于根目录和分类目录，优先使用 `职业/种族/装备_魔法物品/专长/法术/规则` 下的副本。
3. **去重标记**：每个源文件写入一次隐藏标记 `<!-- <来源>-source:<md名> -->`。
4. **加粗标题解析**：处理物品/专长/职业变体时，需识别跨行加粗标题；避免把统计标签（灵光、价格、先决条件等）误判为条目标题。
5. **增量写入**：脚本只能追加或修改目标文件，不得重建 `pf_rules_md_organized/`。**例外**：当源书聚合文件已**完全合并**到核心权威页（如 §4.2 货品服务 `page_212.md`）时，原聚合文件可删除。删除前需确认所有内容已带 `<!-- <来源>-source: -->` 标记成功合并，并在报告文件中记录删除动作。
6. **脚本修改后的重跑原则**：脚本的来源标注逻辑修改后，可使用隐藏标记 `<!-- <来源>-source: -->` 反向定位进行增量重跑，**不必重置整个 `pf_rules_md_organized/`**。仅当修改的是全局去重/合并策略时，才需评估是否需要重跑。撤回错误合并的流程见 §14。

## 7. 验证清单

每次整理完成后检查：

- 原目录 `pf_data/phase1/pf_rules_md/` 未被修改。
- 所有被合并的目标文件均出现 `> 来源：` 标注。
- 标注位于每一项标题下一行，而非段落末尾。

## 9. 重复记录与全局去重

### 9.1 重复发现时的处理原则

在整理过程中，若发现待整理内容已存在于 `pf_rules_md_organized/` 的其他位置（例如某来源书的法术已出现在 `法术/` 下、某物品已出现在根目录等）：

1. **保留两边**：新整理的文件与已存在的文件均保留，不得删除或清空任何一侧。
2. **记录不删除**：将重复情况记录到 `pf_data/phase1/未整理目录重复记录.md`，不在整理脚本中执行去重删除。
3. **等待全局去重**：单个规则书整理阶段不解决跨文件重复问题；待大量规则书完成初步整理后，再统一制定并执行全局去重策略。

### 9.2 重复记录文档

- **文件位置**：`pf_data/phase1/未整理目录重复记录.md`
- **记录内容**：
  - 来源书名称；
  - 新位置（本次整理生成的目标文件路径）；
  - 已存在位置（`pf_rules_md_organized/` 中已存在的文件路径）；
  - 重复项的简略列表（法术名、物品名、变体名等）；
  - 重复原因与备注。
- **更新时机**：每发现一处跨文件重复，即在该文档中追加一条记录。

### 9.3 去重策略候选（全局阶段使用）

全局去重阶段可从以下策略中选择或组合：

- **以聚合目录为准**：以 `法术/`、`专长/`、`装备_魔法物品/` 等聚合目录为权威来源，从种族/职业文件中删除重复段落。
- **以种族/职业文件为准**：以按来源书/种族/职业组织的文件为权威来源，删除或清空聚合目录中的旧文件。
- **索引引用**：建立索引文件，明确各条规则的“主位置”与“引用位置”，保留两侧但避免内容重复维护。

## 10. 整理执行流程（人工分类 + 脚本执行）

对于从 `未整理 → <来源书>` 合并到 `pf_rules_md_organized/` 已有分类页面的规则书，采用"先人工阅读分类，再脚本批量执行"的模式：

### 10.1 人工阅读与分类

1. 按 `toc_path` 或目录顺序读取该来源书下的全部 Markdown 源文件。
2. 若 Markdown 格式混乱（标题跨行、加粗嵌套、中英混排等），可通过 `md_mapping.json` 中对应条目的 `html_file` 字段，读取原始 HTML 文件辅助辨认结构。HTML 回退解析的详细流程按需加载 `整理规则_详情/12_HTML回退解析.md`。
3. 逐条判断规则类型（种族替换特性 / 职业变体 / 专长 / 物品 / 独立规则 / 仪式等）。
4. 对属于具体种族、职业或物品子类型的条目，确定：
  - 目标职业/种族/物品子目录；
  - 目标文件在 `pf_rules_md_organized/` 中的已有路径；
  - 条目标题在原文中的定位子串（用于脚本拆分）。
5. 将判断结果写入脚本配置表（如 `SECTIONS` 列表），包括源文件、条目名、英文名、职业/分类、目标路径、定位子串。

### 10.2 脚本批量执行

1. 读取源文件，根据定位子串确定每个条目的起始行与结束行（下一条目起始前）。
2. 检查目标文件是否已存在该条目：
  - 优先使用隐藏标记 `<!-- <来源>-source:<源文件名>:<条目名> -->` 判断；
  - 对已知跨文件重复项，可额外用标题或英文名检索并跳过。
3. 在条目标题下一行插入来源标注，格式见第 3 节。
4. 将处理后的条目追加到目标文件（注意 §4.4 行尾换行符）。
5. 生成本次整理的报告文件 `<来源>_reorganization_report.md` 和计划文件 `<来源>_reorganization_plan.json`。
6. 发现的跨文件重复写入 `pf_data/phase1/未整理目录重复记录.md`。

### 10.3 为什么采用人工分类 + 脚本执行

- 目录结构只给出书名/章节名，不能自动推断条目属于哪个职业/种族；
- Markdown 源文件标题格式不统一，跨行、加粗、中英混排常见，完全依赖正则容易误判；
- 由人判断归属和目标文件，脚本负责重复性拆分与标注，可在准确率与效率之间取得平衡。

### 10.4 脚本与配置要求

- 每个来源书应独立一个整理脚本，如 `organize_<来源缩写>.py`。
- 脚本内配置表应清晰可维护，便于后续重跑、补录或修正目标位置。
- 禁止脚本删除或重建 `pf_rules_md_organized/`；只追加或修改目标文件（例外见 §6.5）。
- 增量重跑原则：脚本的来源标注逻辑修改后，可使用隐藏标记 `<!-- <来源>-source: -->` 反向定位进行增量重跑，**不必重置整个 `pf_rules_md_organized/`**。仅当修改的是全局去重/合并策略时，才需评估是否需要重跑。撤回错误合并的流程按需加载 `整理规则_详情/14_撤回流程.md`。

## 16. 整理后文档格式整洁性

> 整理后写入目标文件的内容必须保持 Markdown 语法正确、段落整洁，**禁止**出现杂乱的文本、段落或失效的语法。
>
> 详细规则按需加载：`pf_data/phase1/整理规则_详情/16_文档格式整洁性.md`
>
> 本节仅列出核心要点，完整的 6 个子节（§16.1-§16.6）与检查清单见上述详情文件。

**核心要点**：

- **段落整洁**（§16.1）：标题独占一行、段落之间用空行分隔；禁止把多条独立条目挤在同一行或同一段；禁止在标题行尾或正文中夹杂 `![[图片]]` 占位符。
- **表格语法**（§16.2）：表格必须有 `| --- |` 分隔行；每行 `|` 数量一致；禁止"只有表头无分隔行"的伪表格；表格内换行用 `<br/>`（不支持真实换行）。
- **加粗/斜体配对**（§16.3）：`**...**` 与 `*...*` 必须成对出现，禁止未闭合残段；跨行加粗 `**xxx\nyyy**` 写入前必须预合并。
- **标题层级合理**（§16.4）：聚合用 `#`、条目录入 `##`、子条目用 `###`；禁止跳级或反向嵌套；同级标题前后保留空行。
- **HTML 标签清理**（§16.5）：禁止出现未处理的 `<P>`/`<DIV>`/`<SPAN>`/`<FONT>`/`<HR>` 等标签；实体符号用 `html.unescape` 还原；异常标签时按 §12 回退 HTML 源重新解析。
- **列表与代码块**（§16.6）：列表标记前后保留空格；代码块用三反引号 ` ``` ` 包裹并标注语言；禁止未闭合的代码块或列表。

**自动校验**（建议在脚本中实现，整理完成后必跑）：

- 检测未配对的 `**` / `*` 数量（奇数即为异常）。
- 检测 Markdown 表格是否含分隔行（`^\\|.+\\|$` 后必须跟 `^\\|?\\s*[-:]+\\s*\\|`）。
- 检测每行 `|` 数量在表格块内是否一致。
- 检测未闭合的代码块（反引号数量必须为偶数）。
- 检测残留 HTML 标签（`<(P|DIV|SPAN|FONT|HR|IMG)\\b` 不应出现）。
- 检测标题跳级（如从 `##` 直接到 `####`，中间缺少 `###`）。
