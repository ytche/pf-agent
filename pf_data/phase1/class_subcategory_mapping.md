# 职业子类别映射表

> 整理"未整理"目录下的规则书时，若条目属于某个职业的子类（天赋/巫术/奥能/秘示域/血统/狂暴之力/传世名作等），按本表确定目标文件路径。
>
> **与 `pf_data/未整理目录整理规则.md` §4.1 配合使用**：
> - §4.1 列出"按内容类型决定目录"（专长→`专长/`，物品→`装备_魔法物品/`，等）
> - 本表细化"具体职业的子类条目落到哪个 page 文件"
>
> **使用流程**：
> 1. 在源书聚合文件 / 新整理的源条目中判断"职业+子类"归属
> 2. 在 §1 查到对应目标文件
> 3. 追加前用 §2 的隐藏标记 `<!-- <来源>-source:<源文件名>:<条目名> -->` 去重
> 4. 文件级移动 / 删除 / 合并操作记录到 §3 审计日志

## 2. 隐藏去重标记（与 §4.1 配合）

所有追加到目标文件的条目都应带以下隐藏标记以便增量重跑：

```markdown
<!-- <来源>-source:<源文件名>:<条目名> -->
```

例：

```markdown
<!-- THH-source:变体_选项/盗贼1.md:斯科扎尼老千 -->
## 斯科扎尼老千（Sczarni Swindler）【盗贼变体】
...
```

`条目名` 部分可省略（仅写 `<!-- THH-source:变体_选项/盗贼1.md -->`），但写全更便于排查。

## 4. 维护规范

1. **新建聚合页面**：发现 §1 标为"❌暂无"的子类时，先建立聚合页面（命名 `<职业><子类别>汇总.md` 或定位对应 page），再写入条目，最后回到本表把状态改为 ✅。
2. **发现目标错误**：发现某条目被错误聚合到本表之外的位置，先在 `pf_data/phase1/未整理目录整理问题记录.md` 记录，再执行撤回（按 §14 撤回流程），撤回动作在本表 §3 留痕。
3. **批量整理前必读**：每整理一本新规则书，**必须**先查本表 §1 确定每个职业子类条目的目标文件路径，再开始脚本编写。
4. **跨文件重复**：发现同一子条目同时存在两个目标文件，先记录到 `pf_data/phase1/未整理目录重复记录.md`，**不**在本表删除/合并，需全局去重阶段统一处理。
