## V001. 变体相关文件中的非变体章节被误识别为 `class_archetype`

- **发现时间**：2026-07-22
- **问题归类**：规则识别 / 数据格式
- **严重程度**：需要人工校验（影响变体计数、`feature_subtype` 准确性、检索质量）
- **状态**：已修复

### 1. 问题描述

在抽查 `class_name == 女巫` 的 chunk 时，发现 6 个“四季/自然”庇护主主题（`寒冬/早春/林地/深秋/盛夏/荆棘`）和 1 个 `女巫庇护主主题` 被标记为 `class_archetype`，而不是 `feature_subtype='patron'` 的 `class_feature`。

进一步按规则扫描全部 `class_archetype` 后，发现共有 **64 条** 以“中文（English）：”结尾的同类误识别，涉及 **15 个职业**。这些条目本质上是“变体下的职业能力”“庇护主主题”“动物伙伴选项”等，却进入了变体索引 `class_archetype_index.json`。

> **注意**：64 条是按“标题以冒号结尾”这一强模式扫描的结果。女巫还有一条 **`女巫庇护主主题（Witch Patron Themes）（BotC）`** 也误标为 `class_archetype`，但标题不带冒号，未被该模式命中。把它算入后，总共有 **65 条** 误识别。这说明问题不仅限于“变体”标题，也不限于“冒号结尾”格式。

### 2. 根因分析

问题出在标题提升 + 变体识别两条规则的叠加：

1. **`promote_bold_headings` 对加粗标题的过度提升**
   - 源文件中常见格式：`**中文（English）：正文**` 或单独一行的 `**中文（English）：**`
   - `promote_bold_headings` 只要标题里含英文（`has_signal` 命中 `[A-Za-z]`），即使标题以冒号结尾，也会把它提升为 `##`/`###` heading。
   - 这导致大量“能力名（English）：”行被错误地提升为独立 heading。

2. **`looks_like_archetype_title` 在变体文件中的弱规则**
   - 规则 3：在变体相关文件（路径/CHM TOC 含“变体”）中，只要 `level <= 3` 且标题带 `中文（English）` 括号，就视为变体。
   - 被第 1 步错误提升的能力标题，几乎都会命中这条弱规则。

3. **`classify_component` 缺少“冒号结尾 = 非变体”的兜底**
   - 当前 `classify_component` 只在祖先面包屑命中 `feature_section_hints`（如“庇护主”“巫术”）时才拒绝变体。
   - 如果源文件本身没有这些章节标题（如 `全变体未整合.md` 把四季庇护主直接平铺在变体表后面），就会被判为 `class_archetype`。

4. **源数据重复导致 chunk 重复**
   - `基础职业/女巫/全变体未整合.md` 中，每个四季/林地庇护主主题出现了两次，生成完全重复的 `class_archetype` chunk。

###### 宫廷猎人为什么整个变体都崩了？

源文件 `page_104.md` 中宫廷猎人的标题格式是：

```markdown
<!-- UI-source:page_1437.md:宫廷猎人 -->
```

- 标题是加粗行，不是 `##` heading；

### 5. 共性问题模式

误识别条目标题通常符合以下模式之一：

| 模式 | 示例 | 本质 |
|---|---|---|
| 能力名（English）： | `寒霜炸弹（Frost Bomb，Su）：` | 变体下的 `class_feature` |
| 通用职业字段（English）： | `阵营（Alignment）：`、`本职技能（Class Skills）：` | 变体调整说明 |
| 庇护主/血承/领域主题（English）： | `寒冬（Winter）：`、`林地（Woodlands）：` | `feature_subtype='patron'` 的 `class_feature` |
| 动物伙伴/选项（English）： | `海狸（Beaver）：`、`枭（Owl）：` | 变体下的子选项 |

### 5. 为什么现有验收脚本没有发现

- `verify_all_classes.py` 只检查 `expected_variants/*.json` 中的变体是否出现，**不检查是否多出了不应出现的变体**。
- `verify_class_attribution.py` 的阈值只关注“未知职业”数量，不区分 `class_archetype` 与 `class_feature`。
- 缺少 **negative test**：即“这些标题不应作为 `class_archetype` 出现”。

### 6. 建议修复方向

优先修复脚本，而不是在源文件里逐个改标题：

1. **在 `looks_like_archetype_title` 中增加“冒号结尾”过滤**
   - 若标题以 `:` 或 `：` 结尾，且不含 `【X变体】`/`〔X变体〕` 等强变体信号，直接返回 `False`。
   - 真实的变体标题不会以冒号结尾。

2. **增强 `classify_component` 的“通用能力字段”黑名单**
   - 标题含 `阵营`、`本职技能`、`语言`、`法术`、`武器和防具擅长` 等通用字段时，优先判为 `class_feature`/`class_overview`，不再走变体分支。

3. **识别“庇护主主题/血承/领域”等 feature_subtype**
   - 对 `四季/林地/寒冬` 这类标题，若上下文是女巫且文本为法术列表，应标记为 `feature_subtype='patron'` 的 `class_feature`。
   - 可复用 `WitchProcessor.infer_feature_subtype()` 的现有规则，但需要在分类阶段就命中。

4. **去重**
   - 对 `全变体未整合.md` 中完全重复的四季/林地庇护主块，在分块后合并或去重。

5. **补充 negative 验证脚本**
   - 新增 `verify_no_false_archetypes.py`，断言上述 64 条标题不再以 `class_archetype` 出现。

### 8. 验证方法（修复后）

```python
import json
import re

false_patterns = [
    # 通用能力字段
    r'阵营\s*[（(][A-Za-z][^）)]*[）)]\s*[：:]',
    r'本职技能\s*[（(][A-Za-z][^）)]*[）)]\s*[：:]',
    r'语言\s*[（(][A-Za-z][^）)]*[）)]\s*[：:]',
    r'法术\s*[（(][A-Za-z][^）)]*[）)]\s*[：:]',
    r'武器和防具擅长\s*[（(][A-Za-z][^）)]*[）)]\s*[：:]',
    # 女巫庇护主主题
    r'^(早春|盛夏|深秋|寒冬|荆棘|林地)\s*[（(][A-Za-z][^）)]*[）)]\s*[：:]',
]

errors = []
for line in open('vectorization_prep_profession/chunks.jsonl', encoding='utf-8'):
    c = json.loads(line)
    if c.get('component_type') != 'class_archetype':
        continue
    title = c.get('title', '')
    if any(re.search(p, title) for p in false_patterns):
        errors.append((c['class_name'], title, c['doc_id']))

assert not errors, f'仍有 {len(errors)} 条误识别：{errors[:10]}'
```

### 9. 复用场景
