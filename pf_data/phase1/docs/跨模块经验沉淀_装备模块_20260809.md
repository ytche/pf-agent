## 一、开工前机制（Prepare 阶段）

### 1.1 范围决策拍板制——跨模块内容归属先拍板再勘探
① **内容**：装备范围三项移交决策全由**用户拍板**（2026-08-08）——KN161 科技指南/科技装备 9 文件本期不纳入（语义归未开工科技模块，D1）、KN162 `规则/` 下装备规则件 ~7 文件首期排除（归规则模块，D2）、KN163 根级 `P&P-药剂与毒药.md` 实为**法术内容非装备语义**（全库 MD5 唯一判定，剔除移交法术模块——移交只登记**不重跑 spell pipeline**，KN136 冻结）。
② **落地**：**「内容语义归属 ≠ 文件所在目录」**——跨模块内容先判定语义再定归属，判据用 MD5 唯一性等客观证据；移交冻结模块一律只登记不重跑（KN136）。

### 1.2 散件 MD5 全库比对再定性——勘探期数量先证后信（KN164）
① **内容**：勘探期曾报告「根级 84 装备散件」→ 全库 MD5 比对（143 候选）证明**全部为副本**（10 与 `装备_魔法物品/` 同源、131 与 `未整理/` 同源、2 唯一但非装备语义）→ 84 误报修正为 0，P3 散件批次取消，输入收敛为 297 文件（与 M1a 对账一致）。
② **落地**：**勘探期报告的文件数量必须先过 MD5 全库比对再定性**（专长 E5 反向陷阱：根目录副本「均为重复」假设要逐页验证；装备正向陷阱：散件「全为新内容」假设要逐文件证伪）——同一证伪方法，双向使用。

### 1.3 目录驱动词表第三次落地——slot 13 = CHM TOC L4（KN168）
① **内容**：奇物 slot 13 位置词表（腰部/躯体/胸部/眼部/脚部/手部/头部/头饰/颈部/肩部/腕部/戒指/无）= **CHM TOC L4 权威词形**（用户拍板 D5「wondrous_item 单类 + slot 枚举字段」）；神话冒险 page_633 另有 15 行槽位说明（含盾牌/法杖/武器）。

## 二、实现时机制（解析器设计）

### 2.1 C 形态 CHM 大页切块——61 个 chm_page 文件 + 行级对账（KN166）
① **内容**：page_206~234 等 61 个 CHM 原始大页（星壳嵌套标题/双栏价格表/裸标题混合形态），按物品切块——`fix_equip_table_cr.py` 前置清洗（E9 页 page_729 裸 CR 83 处最重灾区优先）+ 切块器 TDD（奇物 13 位置逐页正负例）+ **价格表行级对账 0 静默丢失**。
② **落地**：**大页切块的召回验证必须是行级对账**（源表数据行 ↔ chunk 逐行，种族 §4.3 行级对账的装备实战）；E9 裸 CR 清洗（KN159 家族：表格单元格裸 `\r` 腰斩）在切块前先做，防切块器被 CR 腰斩形态误导。

### 2.2 专属表短路规模化——技能 7 前缀 → 装备 88 前缀（KN165）
① **内容**：`_EQUIP_SOURCE_OVERRIDES`（rel 前缀精确匹配，88 前缀）+ `_EQUIP_PAGE_BOOK_MAP`（C 形态页→书精确映射）+ verify 侧同源 import——技能 3.1 教训（557/557 系统性失实）在装备的第二次落地，规模从 7 前缀扩到 88 前缀**验证了模式可扩展**。
② **落地**：专属表短路 + 同源表 + verify import 单点数据源（技能 §3.2）已闭环成「汇聚类目来源书归属标准件」——新模块直接复制此结构（禁 copy 抽公共层另行评估），禁行区不变：providers.py 不注册目录进 DIRECTORY_ABBR_MAP（子串匹配禁止）。

### 2.3 守卫位置 = 可达性——守卫挂错分支形同虚设（KN173）
① **内容**：价格阶梯行（`普通（Standard）价格：1gp`/`精制品（Masterwork）价格：50gp`）被拆成「普通」「精制品」伪条目——变体词表守卫 `_BARE_VARIANT_LABELS` 只挂 TAIL 全角括号分支，**但阶梯行组3 以 `价格：` 词表标签开头，字段链分支先行开条目，守卫不可达**。修复 = 守卫提前到 TAIL 字段链分支之前 + EN 半角括号分支同款补位。
② **落地**：**守卫不是「有」就行，挂载分支顺序决定是否可达**——同族两陷阱：守卫挂太晚被前分支消费（KN173）、守卫挂公共函数没调用点执行（种族 §2.6 M13 死守卫）；新守卫必须 trace split 分支序（种族元教训 8「形态被哪层消费」）。

### 2.4 修复连带效应——修一个守卫，扫全库连带面（KN171）
① **内容**：修 seed_01 效果字段误切（`_CANONICAL_KEY_SET` 收窄正文守卫）**连带** EXTRA「描述」失去正文守卫——描述值完整进字段、正文无剩余 → **全库 59 空 text 中 43 个归因此回归**。修复 = 三形态全拦（行首星壳 `**描述**：` 预判剥壳挂 text / 无星裸行 sink / 无星冒号守卫）。
② **落地**：**任何守卫收窄/新增，必须全库扫描「被连带字段的形态分布」**（该字段的合法正文形态是否被新守卫误吞）；空 text 增减是连带效应的第一信号（修复后 59→14，全定性）。

## 三、产出/修复时机制

### 3.1 空 text 语义三分——缺陷 / 结构化白名单 / 表行字段载荷（KN171/175/177）
① **内容**：装备空 text 三种语义并存：①缺陷家族（KN171 描述进字段，已修复）②结构化字段完整形态白名单 14（KN175：毒药家族字段承载正文、equipment_intro 章首仅标题）③**C 形态价格表行 chunk（gear 78 + wondrous_item 26：title+价格可检索，text 空是设计形态）**——检索端命中空 text 表行时以 title+价格作答，**不得因 text 为空剔除**。
② **落地**：**「空 text = 缺陷」是 KN085 家族的正确率一半——表行 chunk 以字段值为检索载荷**（检索载荷在字段不在 text 的形态族）；空 text 豁免白名单逐条定性登记（闸口 `--max-empty` 按白名单校准），与缺陷家族分账登记。

### 3.2 伪条目家族负例三件套 + 全库扫描残留 0（KN178 家族 3）
① **内容**：星壳字段标签行伪条目家族 3（`**战役用途**：`/`**制造**：`/`**工艺**：` 正文段落误开条目）——TDD 4 负例（超游神器战役用途/SoS 制造DC/亡灵杀手制造条件行/GLUE 机械章鱼正例）→ 重跑 5437→5379（家族 2 54 + 家族 3 6 = 60 伪条目清除，真条目零丢失）→ **全库扫描 `title ∈ {战役用途,制造,工艺,施法者等级,灵光}` 残留 0** + 页面级对账无回归。
② **落地**：伪条目家族闭环标准件 = 负例 TDD（含正例防误伤）+ chunk 净变化全归因 + **全库 title 残留扫描 = 0**（不能只信 pytest）+ 页面级 est↔got 精确对齐（超游神器 est 5 = got 5）。

### 3.3 剥壳规则顺序依赖——调用点定于 normalize 步骤 7（A-2）
① **内容**：A-2 text 星壳清理规则集 `_strip_star_glue_artifacts`（R1a/R1b 三连星对、R2a/R2b 粗体块粘连、R3a/R3b 空壳行、R4b 6星尾壳）调用点**定于删除线壳步骤 7 之后**——`**~~` 剥 `~~` 后**二次生成空壳行**（page_234 实测），顺序错了规则互相打架。
② **落地**：**剥壳/清洗规则是链式顺序敏感的**（专长 E4 拆行产物过下游守卫同族）——新规则挂 normalize 链时注明「定于步骤 N 之后的理由」，TDD 覆盖链上先后两规则同框用例（page_234 空壳行由步骤 7→R3 二次生成即其测试）。

## 五、验收/审计时机制（M6 独立复测审计）

### 5.1 审计判定口径——「剥尽成对标记后仍剩星 = 真残渣」（M6）
① **内容**：M6 独立复测审计自写脚本全量重扫产物 + 源数据逐条核验，判定口径「**剥尽成对标记后仍剩星 = 真残渣**」——把行内残留星壳分为：脚注/译注星（原文合法标记，~50 行 PF 原版 `*` 脚注）、断行开壳孤星（源数据缺陷 5 行）、字段星壳残渣（~8 条）——A 类真实缺陷面 64 条（1.2%）**用户拍板方案 A 修复闭环**（A-1 字段剥壳 24 + A-2 text 真壳 ~40），B 类原文合法保真**登记不修**（防词表腐化，同 KN185 口径）。
② **落地**：**审计发现的缺陷处置有两条路：用户拍板修复（方案 A）或登记不修（B 类保真）**——「原文合法 vs 缺陷」的判定先立标准（剥尽成对标记）再分类；修复面 = format/metadata 剥壳规则 + verify 同构断言 + TDD 9 seeds，公共层零改动。

### 5.2 dry-run 全合法 ≠ 可剥——剥壳必须查下游切分器依赖（KN189）
① **内容**：R4a（四星括号内嵌套 `（****X****）` 剥壳）dry-run 判「76 处全合法可剥」**系误判**——全库命中全部是 `_RE_ISG_TITLE` 的 `（?\*\*\*\*` **切分器依赖结构**（ISC 章节标题/无前缀条目头），剥壳后 category/条目识别断裂（seed_19/20/25/49 回归）→ 整个移除，命中形态登记不修。
② **落地**：**「可剥壳 = 剥后产物不破坏任何下游依赖」——剥壳前必须回答「这个形态被谁消费」（种族元教训 8）**；dry-run 只证「壳可剥」，不证「剥后仍可解析」；命中形态若是切分器结构，登记不修而非强剥。

### 5.3 后处理业务字段回填——BackfillSlotByPage 先例（KN190）
① **内容**：M6 后产物检索核对（用户驱动）发现奇物 11 位置页（page_223~233）479 条 wondrous_item 中 **326 条（约 68%）slot missing**（纯描述条目无「位置：」字段链）——用户拍板 A1（例外保留自声明 parsed 优先）+ B1（三态内 parsed）→ **`BackfillSlotByPage` 后处理**（POSTPROCESSORS 内建，公共层零改动）：`_EQUIP_PAGE_SLOT_MAP` 11 项 doc_id 精确映射回填 missing（**精确匹配非前缀**，防聚合书子串误命中），有值条目一律不动，幂等；verify 新增检查 5.5（同源 import）：11 位置页 slot missing=0 + 页内对应性 + **例外白名单 7/7 负向断言**（防未来覆盖误伤）。闭环：326 回填与登记数一致、5385 chunks 不变、位置页有值率 100%、pytest 1187、verify 九检查。
