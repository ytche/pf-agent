## 七、初步结论与子方案建议

### 7.1 关键发现

- **251 个 chunk（95.4%）是散文型/纯散文型**，无字段标签 —— 当前 pipeline 把章节总览/前置说明（如 `神话法术 (Mythic Spells)`）误纳为 spell chunk，是 ~3% 覆盖率的**根因**
- **9 个 chunk（3.4%）是标准字段区型**：实测**全部已被现有 parser 正确解析**（parsed 字段数 7~9：school/spell_level/casting_time/components/range/target/duration/saving_throw/spell_resistance），如 `晋升之术` / `流逝荣耀` / `不死身` 等
- **2 个 chunk（0.8%）是单字段型**：``心有灵犀` (26 字)、`谋杀指令`（缺字段区）—— 个案边界
- **1 个 chunk（0.4%）是表格型**：本身就是 `神话法术` 章节说明（首部 3280 字），非单个法术表格

### 7.2 建议子方案

**不可修（结构性）**：

- C3 散文型 **251** chunk —— 这些是章节总览/规则说明（如「神话法术 / 学习神话法术 / 施放神话法术」等整页说明），**不是 spell chunk**。应在 SpellProcessor 入口判定：无任何字段标签时跳过 metadata 抽取，标记 `field_status` 全 `missing` + KN「MA 散文型非 spell chunk」。或更激进：在 `split_into_items` 阶段用 chunk 长度/结构特征排除。
- C5 表格型 **1** chunk —— 章节说明页，复用同上策略
- C2 单字段型 **2** chunk —— 个案检查后大概率归入 KN

**已正确解析**：

- C1 字段区型 **9** chunk —— 不需要修复；当前覆盖率统计已计入

### 7.3 风险评估

- 散文型 chunk 当前被记为 spell chunk（field_status 已写入），若简单删除会破坏 `chunks.jsonl` 4138 不变量；正确做法是 SpellProcessor 跳过 + 仍产出 chunk 但 field_status 全 missing + KN 登记
- 若选择"在 split_into_items 阶段排除"，需要验证其他 18 本来源书没有类似章节说明页被一并误删
- F4 的**实际修复子集 ≈ 0 chunks**：C1 已正确解析，C2/C3/C5 都是结构性不可解析内容，建议**整体登记为 KN 而非修复**

### 7.4 推荐动作

- **不建议做 parser 修复**（C1 已对，C3 结构性不可解析）
- 建议在 pipeline 加**章节说明页排除规则**：title 不在法术名/章节名白名单 + text 字段标签数 < 阈值 → 标记为 `non_spell_chapter_overview` 并 KN 登记
- 预期效果：MA school/casting_time 等覆盖率从 3.4% 降至真实值（如 9/12 = 75%），反而**提升** A 层 school 真实覆盖率

### 7.5 与 F1~F5 的关系

- F4 与 F1/F2/F3 **无依赖**：F1~F3 是字段值修复，F4 是 chunk 边界问题
- F4 的"修复"不增加 parsed 数量，反而通过排除噪声让统计更准确
- 是否推进 F4 由用户决定；本 census 报告已为决策提供数据基础
