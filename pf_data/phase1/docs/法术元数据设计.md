# PF 1e 法术元数据设计

> 状态：设计稿 — 待排班审核，下个模块（CategoryPipeline 重构）时落地  
> 作者：K2.7  
> 日期：2026-07-25

---

## 1. 背景

一期向量化 pipeline 的 `SpellProcessor` 当前从 chunk text 中提取了 3 个元数字段：

| 字段 | 覆盖率 | 说明 |
|------|--------|------|
| `school` | **54.3%**（设计稿基于 Phase 1 4352 chunk 误标 100%；F5 实测 2246/4137） | 4 种 fallback 格式 + 紧凑格式提前解析；空值多为 prose 介绍页/索引页/非标准格式 |
| `spell_level` | **56.0%**（F5 实测 2315/4137；F3 修复后提升） | 同上；F3 剥离"领域 N"残留 + 复合职业 `/` 拆分 |
| `descriptor` | **6.0%**（F5 实测 249/4137） | `【善良】【酸】【火】` 等描述符标签；PF 数据中描述符本身稀少 |

但一个法术的描述信息远不止这三个字段。chunk text 中已包含施法时间、成分、射程、目标、持续时间等字段标签与值，但仅作为纯文本保留，未被解析为结构化元数据：

```
当前： {school: "咒法", spell_level: "诗人3，牧师3，德鲁伊3", descriptor: ["善良"]}
缺失： {casting_time, components, range, target, area, effect, duration, save, spell_resistance}
```

**目标**：将上述字段解析为结构化元数据，使下游检索可对这些维度做精确过滤和排序。

## 2. 法术元数据字段定义

### 2.1 总览

| # | 字段名 | 中文标签 | 类型 | 出现率 | 优先级 | 备注 |
|---|--------|----------|------|--------|--------|------|
| 1 | `school` | 学派 | `string` | 53.4% | ✅ 已有 | 4 种 fallback 格式已覆盖 |
| 2 | `spell_level` | 环位/等级 | `string` | 67.5% | ✅ 已有 | 与职业名捆绑，需拆分策略 |
| 3 | `descriptor` | 描述符 | `list[string]` | 嵌入 school 行 | ✅ 已有 | 从 `【】` 提取 |
| 4 | `domains` | 领域 | `list[dict]` | — | 🟡 P1 | `{name, level}`，常与 `spell_level` 混排 |
| 5 | `subdomains` | 子领域 | `list[dict]` | — | 🟡 P1 | 同上 |
| 6 | `casting_time` | 施法时间 | `string` | **68.2%** | 🔴 P0 | |
| 7 | `components` | 成分 | `string` | **69.9%** | 🔴 P0 | V,S,M/DF,F 等 |
| 8 | `range` | 射程/距离 | `string` | 26.1% | 🔴 P0 | 见 §3 歧义分析 |
| 9 | `target` | 目标 | `string` | **67.1%** | 🔴 P0 | |
| 10 | `area` | 区域/范围 | `string` | 17.9% | 🟡 P1 | 部分法术没有区域 |
| 11 | `effect` | 效果 | `string` | 44.8% | 🟡 P1 | 部分法术没有效果 |
| 12 | `duration` | 持续时间 | `string` | 56.4% | 🔴 P0 | |
| 13 | `save` | 豁免 | `string` | **68.8%** | 🔴 P0 | 含 DC 后处理 |
| 14 | `spell_resistance` | 法术抗力 | `string` | 41.1% | 🔴 P0 | |

> 出现率 = chunk text 中包含该字段标签的比例（基于 4352 个法术 chunk 统计）。  
> 优先级标记仅反映解析紧迫性，「已有」表示当前已解析到 metadata 的字段。

### 2.2 字段详解

#### school（已有）
- **解析方式**：`_infer_school` — 4 种 fallback 正则
  1. `**学派：**`（紧凑格式内联）
  2. `**学派**：`（块标题格式）
  3. `| 学派 |`（表格格式）
  4. `【学派】`（源头格式）
- **标准化**：`_normalize_school_name` — 统一名称（咒法系 → 咒法）
- **示例值**：`"咒法"`, `"塑能"`, `"变化（变形）"`

#### spell_level（已有）
- **解析方式**：`_infer_level` — 2 种 fallback
  1. `**等级：**`（紧凑格式内联）
  2. `**等级**：`（块标题格式）
- **原始格式**：`"诗人3，牧师3，德鲁伊3，圣武士3，女巫3"`
- **拆分规则**：
  - 输出为 `[{"class": "诗人", "level": 3}, ...]` 的列表
  - 复合职业按 `/` 拆分：`术士/法师 3` → `[{"class": "术士", "level": 3}, {"class": "法师", "level": 3}]`
  - 拆分后按固定顺序归一化（如 `术士` 在 `法师` 前）
  - `XX领域 N` / `XX子域 N` 从此处剥离，写入 `domains` / `subdomains`
  - 分隔符兼容半角逗号、全角逗号、顿号、无空格
  - 纯数字时 `class` 为 `null`

#### descriptor（已有）
- **解析方式**：从 `【】` / `[]` 提取，映射为英文枚举
- **映射机制**：维护 `spell_descriptors.json` 注册表，未知描述符保留原文
- **示例值**：`["good", "acid", "fire", "mind-affecting"]`

#### subschool（需新增）
- **解析方式**：从 `school` 原始行的 `(...)` 中提取
- **白名单机制**：维护 `spell_subschools.json` 注册表，未知子学派保留原文
- **示例值**：`"创造"`, `"魅惑"`, `"变形"`

#### domains / subdomains（需新增）
- **中文标签**：`领域` / `子领域`
- **解析方式**：
  - 在 `spell_level` 原始文本中识别 `XX领域 N` / `XX子域 N` 模式
  - 从 `spell_level` 列表中剥离后，单独写入 `domains` / `subdomains`
- **值结构**：`[{"name": "黑暗领域", "level": 2}, ...]`
- **示例值**：
  - `domains: [{"name": "黑暗领域", "level": 2}]`
  - `subdomains: [{"name": "暗夜子域", "level": 2}]`

#### casting_time（需新增）
- **标签变体**：`施法时间` / `施放时间`
- **解析策略**：在 chunk text 中使用正则 `**施法时间[：:]\*\*([^**]+)`（紧凑格式）或 `**施法时间**：([^\n]+)`（块格式）
- **示例值**：`"1个标准动作"`, `"1轮"`, `"10分钟"`

#### components（需新增）
- **标签变体**：`成分` / `法术成分` / `组成部分`
- **解析策略**：同 casting_time 模式
- **值结构**：`V，S，M/DF（鸽子之心）`，可进一步拆分为 `{verbal: true, somatic: true, material: "鸽子之心", focus: "..."}`
- **示例值**：`"V，S，M/DF（鸽子之心）"`, `"V，S，F（一段精巧的金链条）"`

#### range（需新增）
- **标签变体**：`射程` / `距离`（紧凑格式中标签是 `**范围：**`，但语义是 distance）
- **解析策略**：
  - 紧凑格式：从 `**范围：**` 到下一个 `**` 之间的值
  - 注意与 `area` 的区分（见 §3）
- **标准化建议**：统一为 `尺` 单位
- **示例值**：`"近距（25尺+5尺/2级）"`，`"接触"`, `"个人"`, `"长距（400尺+40尺/级）"`

#### target（需新增）
- **标签变体**：`目标`
- **解析策略**：同 casting_time 模式
- **示例值**：`"一个生物"`, `"你的动物伙伴"`, `"自愿活着的生物或接触到的一个生物/等级"`

#### area（需新增）
- **标签变体**：`区域`（较少见，部分格式用 `范围` 标签但值为区域语义）
- **解析策略**：
  - 优先匹配 `区域[：:]` 标签
  - 次选匹配 `范围[：:]` + 值包含区域关键词（爆发/锥状/弥散/扩散/半径）
- **示例值**：`"10尺半径爆发"`, `"以自身为中心的30尺爆发"`, `"锥状喷射"`

#### effect（需新增）
- **标签变体**：`效果`
- **解析策略**：同 casting_time 模式
- **示例值**：`"一把魔法音波鞭"`, `"以你为中心的20尺半径的球体"`

#### duration（需新增）
- **标签变体**：`持续时间`
- **解析策略**：同 casting_time 模式
- **示例值**：`"立即"`, `"1分钟/级（可取消）"`, `"1轮/等级"`, `"永久 (D)"`

#### save（需新增）
- **标签变体**：`豁免` / `豁免检定`
- **解析策略**：
  - 紧凑格式：值为 `**豁免：**` 到下一个 `**` 之间的内容
  - 可附加解析：`"强韧通过则无效"` → `{type: "强韧", result: "通过则无效"}`
- **示例值**：`"意志通过则无效（无害）"`, `"反射通过则部分生效"`, `"无"`

#### spell_resistance（需新增）
- **标签变体**：`法术抗力` / `抗力` / `SR`
- **解析策略**：同 casting_time 模式
- **标准化建议**：统一为 `"可"` / `"不可"` / `"可（无害）"`，可标准化为 boolean
- **示例值**：`"可"`, `"不可"`, `"可（无害）"`, `"见下文"`

## 3. `范围` 字段歧义分析

### 3.1 背景

PF 1e 法术描述中，中文译者使用 `范围` 作为 2 个不同英文概念的共同译名：

| 英文概念 | 英文标签 | 含义 | 中文标签 | 示例值 |
|----------|---------|------|----------|--------|
| **Range** | `Range` | 射程/距离 | 范围/射程/距离 | "近距（25尺+5尺/2级）" |
| **Area** | `Area` | 区域/范围 | 范围/区域 | "5尺爆发范围" |

### 3.2 数据分布（4352 chunks 统计）

| 语义 | 数量 | 占比 | 说明 |
|------|------|------|------|
| 纯射程/距离 | 581 | 13.3% | 值含 近距/中距/远距/接触/尺/个人 |
| 纯区域 | 0 | 0% | 本数据中没有 `范围` = 纯区域的情况（区域值都用 `区域` 标签） |
| 混合（同一行同时含距离+区域值） | 45 | 1.0% | 如 `范围：**60英尺**目标：**锥形弥漫**` |
| 语义不明确 | 28 | 0.6% | 值为 自身/个人/0英尺 等边界值 |
| 未出现 `范围` 标签 | ~3700 | 85% | 紧凑格式中字段不存在或包在不同标签下 |

### 3.3 关键发现

1. **在标准紧凑格式中，`范围` 100% 对应 Range**：`**范围：** 近距（25尺+5尺/2级）**目标：** ...`
2. **`区域` 是独立字段**：当 spell 有 Area 值时，译者使用 `区域` 标签（与 `范围` 并列）
3. **歧义主要来自 3 个源文件**：
   - `MC-怪物志`：使用 `范围：**X**法术范围：**Y**`（第一个=Range，第二个=Area）
   - `page_854`：表格格式 `范围 接触区域：从接触点起，弥漫半径2哩`
   - `元素大师手册EMH` / `Spell TG`：使用 `范围：**圆柱形（20尺扩散，10尺高）**`（Range 被省略，直接写 Area）

### 3.4 解析策略建议

```
规则 1：优选匹配 `区域[：:]` 标签 → 写入 metadata.area
规则 2：次选 `**范围：**` 标签 → 根据正则判断
  2a：值包含 近距|中距|远距|长距|接触|尺|英尺 → metadata.range
  2b：值包含 个人|自身 → metadata.range（特殊射程）
  2c：值包含 爆发|锥状|弥散|扩散|半径 → 从 range 中提取到 area
规则 3：`法术范围：` 是 MC-怪物志 特例 → 单独处理 -> metadata.area
规则 4：表格格式 `范围 X区域：Y` → 拆分为 range=X, area=Y
```

## 4. 解析挑战

### 4.1 紧凑格式（Inline Compact）— 约 70% chunks

最主流格式。一行内包含所有字段，用 `**` 包围标签：

```
**学派：** 咒法（治疗）【善良】**等级：** 诗人3...**施法时间：** 1个标准动作**成分：** V，S...
```

**解析方式**：`_fix_inline_compact` 已将其展开为多行块格式。metadata 解析器应取**展开后 text**作正则匹配。

### 4.2 块格式（Block Format）— 约 15% chunks

每个字段独立一行或一段：

```
**学派**：咒法（治疗）【善良】
**等级**：诗人3
**施法时间**：1个标准动作
```

**解析方式**：直接行级正则 `**XX**：value`

### 4.3 表格格式（Table Format）— 约 10% chunks

`任务与战役`、部分 page_xxx 文件：

```
| 学派 | 咒法（治疗） |
| 等级 | 诗人3 |
```

**解析方式**：目前 `_fix_inline_compact` 不处理表格格式。`page_854` 格式最怪异（`范围 接触区域：从接触点起，弥漫半径2哩`），需要独立的后处理。

### 4.4 格式差异摘要

| 维度 | 紧凑格式 | 块格式 | 表格格式 |
|------|---------|--------|---------|
| 占比 | ~70% | ~15% | ~10% |
| 标签形式 | `**标签：**值` | `**标签**：值` | `| 标签 | 值 |` |
| 字段完整性 | 全部字段 | 部分缺失 | 完整 |
| 解析难度 | 易（已有展开器） | 易 | 中 |
| 含 `范围` 歧义 | 极少 | 无 | 有 |

### 4.5 特殊问题

1. **spell_level 与 class 捆绑**：`"诗人3，牧师3，德鲁伊3"` — 需拆分算法处理 `/` 分隔的混合职业（`"法师/术士 3"`）
2. **无 DC 值**：豁免字段通常为文本格式 `"强韧通过则无效"`，不包含 DC 数值（DC 在源数据中由法术的 spell level + caster stat 动态计算）
3. **间断性缺失**：约 15-20% 的法术 chunk 因源数据格式问题缺少某些字段（`豁免：**无**` 等合法空值不算缺失）
4. **MC-怪物志 特例**：在同一行使用 `范围` 和 `法术范围` 两个标签，需区分处理

## 5. 实现后评估指标

### 5.1 验收标准

| 指标 | 当前 | 目标 | 说明 |
|------|------|------|------|
| 字段覆盖率（综合） | 3/14 | 10/14 | 排除 area/effect 部分 P1 字段 |
| 单字段解析准确率 | ~80%¹ | >95% | 非空且值正确的比例 |
| 紧凑格式字段召回 | 3 字段 | 10 字段 | 一行内全部解析 |
| 块格式字段召回 | 3 字段 | 10 字段 | |
| 表格格式字段召回 | 3 字段⁰ | 8 字段 | 表格格式字段不全 |

> ¹ school / level / descriptor 的准确率估计值，未精确统计。  
> ⁰ 当前 `_infer_school` 的格式 3 (`| 学派 |`) 可覆盖表格格式。

### 5.2 不变量

1. **不删除已有字段**：`school`、`spell_level`、`descriptor` 的解析逻辑不可改变
2. **不破坏 text 结构**：metadata 提取不能修改 chunk.text 内容
3. **格式 fallback 链不缩短**：`_infer_school` 的 4 种 fallback 保持优先级不变
4. **空值保留原字符串**：当字段值为 `"无"` 时不应转为 empty，保留原文
5. **所有 66 个测试保持通过**：`test_per_file_chunk_counts.py` 的断言不能因新增 metadata 字段而失败

## 6. 落地计划（建议）

### Phase A：块格式先行（~1 天）
- `casting_time`、`components`、`duration` 3 个无歧义字段
- 直接正则匹配 `**XX：**\s*([^**]+)` 和 `**XX**：\s*([^\n]+)`
- 只需修改 `spell.py` 中 `infer_metadata` 方法

### Phase B：范围相关（~1 天）
- `range`、`target`、`area`、`effect` 4 个字段
- 先完成 `target`、`effect`（无歧义）
- `range` 按 §3.4 规则实现
- `area` 先只处理 `区域：` 标签，暂不处理 `范围` 标签中的嵌入式 area

### Phase C：豁免与抗力（~0.5 天）
- `save`、`spell_resistance` 2 个字段
- `save` 的标签变体最多（`豁免` / `豁免检定`），注意兼容
- `spell_resistance` 考虑加标准化 boolean 转换

### Phase D：表格格式支持（~1 天）
- `page_854` / `任务与战役` 等表格格式文件的字段提取
- 可能需要 `_fix_table_format` 新函数

## 7. 维护者笔记

- **元数据嵌入时机**：在 `infer_metadata(self, chunk, item)` 中调用各字段的提取函数，与 `_infer_school` 等并列
- **不移动已有代码**：`_infer_school`、`_infer_level`、`_infer_descriptors` 保持原位，新增字段的提取函数放在 `SpellProcessor` 类的对应方法中
- **测试规范**：每个新增字段至少 1 个单元测试，覆盖紧凑格式和块格式
- **输出格式**：`metadata` 为 dict，新增字段名采用 snake_case，值与 text 中一致（不做标准化转换，除非 §3.4 的 range/area 拆分）
