## 一、为什么强调"阅读与语义理解"

本阶段**不是模式计数**——机械可数的（链接数、标题候选、断行英文名行数、表格行数、字段标签命中）由 k3 的机检脚本产出 `scan_report.md`，不占用你的上下文。

你的核心价值是机检做不到的事：

1. **读懂条目**：每类形态至少完整读 2~3 个条目，理解"一个背景特性条目由哪些部分组成、边界在哪、标题和正文怎么衔接"，而不是数正则命中。
2. **判定文件性质**：这个文件是基础分类页？来源书章节？缺陷页？典范/坐骑/宇宙独立页？（→ `doc_role`，见 §三.1）
3. **陷阱定性**：发现异常模式时，判断"这会坑到解析器吗、怎么坑"，给出业务定性而非模式描述。
4. **格式簇建议**：判断"这个文件的写法和哪几个文件是同一类"，给出可归正则表达的簇特征。

**反例**（专长模块真实教训）：只数 `**` 命中数就当条目数，漏掉断行标题的条目；看到表格就当条目表，把修饰词调整表当成专长条目。背景特性的**断行英文名 226 行**意味着按单行正则统计会少算大量条目——必须"真的读了"。

### 3.3 已知坑（机检实测，勘探时逐文件核对）

1. **断行英文名（226 行）**：三种形态——
   - 标题跨行：`**基本背景（****Basic ` + `Traits****）******`（page_152 开头）
   - 需求字段值跨行：`柯莱什或卡蒂亚（Kelesh or ` + `Qadira）`（卡蒂亚QJotE）
   - 出自行页码跨行：`出自《Andoran, Spirit of Liberty pg. ` + `18》`（安多安ASoL）
   - **定性记录**：哪些是标题断行（解析器必须合并）、哪些是字段值断行（无需合并）
2. **链接陷阱（37 处）**：`](http` 密集——`内海诸神ISG_背景特性.md` 25 处（KN023 同型风险，链接后正文可能缺失）；ISG 28.8KB 是最大来源书文件，务必抽样读链接上下文
3. **表格块（3 文件 60 表格行）**：`炼狱血脉BoF` 36 行 / `背景特性17` 16 行 / `page_152` 8 行——判断表格是条目表（产条目）还是对照表（如背景特性加值汇总，不产条目）
4. **删除线壳**：`**~~缺陷~~**` + `**~~~~**` 空壳（缺陷页形态）
5. **【PFS】标记**：PFS 禁用提示（如"PFS中不可使用缺陷系统"）不是条目
6. **译者行（7 行）**：`译者：xxx` 不是条目
7. **`**类型**：` 字段与正文缩进**：形态 B 的字段行和正文在同一段流里，注意字段行不吞正文

- **红线**：HTML 只用于看懂结构，勘探结论描述的是 md 现状；触发过回溯的文件在 `traps` 里加 `"html_consulted": true`

## 四、交付物：per_file.jsonl

**每批写回一个文件**：`vectorizer/exploration/trait/per_file_BNN.jsonl`（NN=批号，对齐批次清单），每行一个文件：

```json
{
  "file": "背景特性/page_152.md",
  "batch": 1,
  "size_kb": 18,
  "doc_role": "basic_page",
  "title_forms": [
    {"pattern": "**中文名（英文名）【书缩写】**：正文", "count": 42, "note": "星壳流式；章节标题同形态"}
  ],
  "field_layout": "无字段行",
  "field_labels_seen": {},
  "trait_type_tags": ["魔法"],
  "estimated_count": 42,
  "count_basis": "完整阅读后逐条计数；断行英文名标题已合并计1条",
  "first_entry": "大气裔",
  "last_entry": "XXXX",
  "traps": [
    {"kind": "断行英文名", "example_line": "L1-2", "risk": "标题跨行，单行正则漏计", "html_consulted": true},
    {"kind": "表格双语分行", "example_line": "L80-90", "risk": "表格行被拆"}
  ],
  "dedup_note": "与各来源书文件的核心条目可能重复（基础页为权威版）",
  "format_cluster_hint": "基础页星壳流式",
  "notes": "读完后的任何语义层面观察，一两句即可"
}
```

**字段硬要求**：

- `estimated_count` 必须配 `count_basis`（用什么依据数的），空口数字视为未交付。
- `doc_role` 五选一（§3.1），不确定时标 `mixed` 并在 `notes` 说明。
- `title_forms[].pattern` 要**可归正则表达**（"**加粗开头、（英文）收尾"这种），禁止"看着像标题"。
- `traps` 里的 `kind` 用稳定词表（断行英文名/链接陷阱/表格双语分行/译者行/PFS图标/重复条目/非条目表格/无标题正文/出自行跨行/删除线壳/其他），新类型用"其他：xxx"并在 notes 描述。
- `trait_type_tags`：形态 B 文件记录 `**类型**：` 字段出现过的所有类型值；形态 A 文件记录文件所属分类（战斗/信念/魔法/社会/派系/种族/地区/宗教/装备/宇宙）。
- 没有条目的文件（纯散文/纯对照表）：`estimated_count: 0`，`count_basis` 写明"通读全文，无独立背景特性条目"。

## 五、红线

1. **只读源数据**，只对 `vectorizer/exploration/trait/` 有写权限；不改任何 `pf_rules_md_organized/` 文件。
2. **逐批交付**：跑完一批立即写 `per_file_BNN.jsonl`，不要攒多批合并写。
3. **行数自检**：每批写完自查 jsonl 行数 == 批次清单中该批文件数，缺一补一。
4. **不猜不省**：读不完的大文件（如 ISG 28.8KB）至少完整读开头 3 条 + 中间 2 条 + 结尾 1 条 + 全文结构扫视，并在 `count_basis` 写明抽样方式。
5. **机检不重复做**：链接计数、标题候选统计等由 k3 脚本负责；你只需在 traps 里**定性**（"这个链接模式会导致什么后果"），不用精确计数。
6. 遇到和 §3.2 假设冲突的形态，**以你读到的为准**并写进 notes——假设就是用来被推翻的。
