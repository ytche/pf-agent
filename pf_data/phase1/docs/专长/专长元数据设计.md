## 一、设计原则（参考 PR #1 骨架改造）

PR #1（137d0ef）确立的分层与富化模式，专长元数据设计全盘沿用：

| PR #1 模式 | 落地 | 专长元数据影响 |
|---|---|---|
| **骨架通用字段**：`chm_toc_path` 作为 Chunk dataclass 顶层字段，由 FileProcessor 模板方法统一填充（`base.py:84`），类目模块零负担 | 专长不重复设计来源路径富化，`chm_toc_path` 直接可用 | 元数据字段表不含来源路径类字段 |
| **类目特有字段进 `metadata` dict**（`base.py:42` 注释"类目特有字段存这里"） | 专长全部特有字段放 `Chunk.metadata`，不入骨架 | 本文档 §二 字段表全部是 metadata 键 |
| **富化 Provider 纯富化、不进来源书链**：`MdMappingTocProvider.resolve()` 恒返回 None，直接写 chunk，避免激活 `CHMTocPathProvider` 子串误匹配（实测 "PA" 误中 "PATHFINDER"） | 专长后续 source_spec 若查 `md_mapping.json` 的 `book_source`，必须走同一模式 | 富化不得改变已冻结模块（spell）的来源书判定 |
| **共享资源路径常量**：`MD_MAPPING_JSON = Path(__file__).resolve().parents[3] / "md_mapping.json"` | 专长类共享资源（如需要）沿用此定位方式 | 不硬编码绝对路径 |
| **三钩子模板方法**：`build_chunk` / `resolve_source` / `infer_metadata`（`base.py:93-106`） | 专长元数据推断全部在 `infer_metadata` 钩子内实现 | 与格式解析（format 层）分离，format 只管产出条目 dict |

**字段命名风格**（沿用骨架）：snake_case、默认空串、`field(default_factory=list)` 列表默认空。

### 2.2 任务链字段（故事/任务专长体系，来源标签频次 50 上下）

勘探显示存在独立"任务链"字段族（专长目标/即时收益/完成收益/进阶先决条件/进阶奖励/基础奖励），来源书是任务专长（Quest Line）体系，**字段结构化为三阶段**：

| key | 中文规范标签 | 别名聚合 | 说明 |
|---|---|---|---|
| `task_goal` | 专长目标 | 专长目标 50 / 目标 10 | 阶段 1：任务目标 |
| `task_reward` | 完成收益 | 完成收益 50 / 即时收益 50 / 完成奖励 10 / 协同收益 2 | 阶段 2：即时收益 + 完成收益（合并为任务完成奖赏） |
| `advanced_reward` | 进阶奖励 | 进阶奖励 15 / 进阶效果 3 / 基础奖励 17 / 基础效果 3 | 阶段 3：进阶先决条件 17 / 进阶奖励（基础/进阶成对） |

> 决策：`基础奖励`（17）与 `进阶奖励`（15）归并到 `advanced_reward`（含基础/进阶两档，存结构：`{"base": ..., "advanced": ...}`）。理由：两标签总是成对出现（同一任务链），分开存无检索价值。若人工确认认为应拆开，见 §六 待确认点。

### 2.4 字段状态（field_status 三态白名单）

每字段随值附状态，合法值三态（参考法术 registry `FIELD_STATUS_VALUES`，法术四态中的 `ambiguous` 在专长无对应概念——类型/字段标签归一化不存在歧义面，删除）：

| 状态 | 含义 |
|---|---|
| `parsed` | 字段成功解析，值非空 |
| `missing` | 源文本中未找到该字段 |
| `not_applicable` | 该专长不适用此字段（如普通专长无 task_goal） |

## 三、先决条件结构

勘探形态统计（page_311/野兽血脉/沙之子民 抽样）：

```
先决条件**：智力 13，能够施放异能宣战（Instigate Psychic Duel）
先决条件**：催眠师5级，痛苦注视（Painful Stare）职业能力
先决条件：BAB+6或武僧等级6
先决条件：唬骗3级，潜行3级
先决条件：迅捷狐妖变身者，基础攻击加值+10，狐妖
```

统一结构（保留原文 + 解析项列表）：

```json
"prerequisites": {
  "raw": "智力 13，能够施放异能宣战（Instigate Psychic Duel）",
  "items": [
    {"type": "ability", "ability": "智力", "value": 13},
    {"type": "spell", "value": "能够施放异能宣战"},
    {"type": "class_level", "class": "催眠师", "level": 5},
    {"type": "skill", "skill": "唬骗", "level": 3},
    {"type": "feat", "value": "寓守于攻"},
    {"type": "bab", "value": 6, "or": "武僧等级6"}
  ]
}
```

**解析形态枚举**（item.type 合法值）：`ability` 属性数值 / `skill` 技能等级 / `class_level` 职业等级 / `bab` 基础攻击加值 / `feat` 专长链 / `spell` 施法能力 / `race` 种族限定 / `other` 其他（含 `or` 分支，如 "BAB+6或武僧等级6"）。

> 实现边界：解析器只做形态识别与键提取，不做语义理解；无法归类的保留在 `other`。检索主键是 `raw` 原文与 `feat`/`skill`/`ability` 词条。

## 五、format_cluster 字段

取值 = 六放行形态（`format_clusters_规范与偏差对账.md` §一，人工确认门已过）：

```
standard | whitespace | punct | lb_marker | img_marker | elided | annotation
```

- 判别器 `fc_match.py` 命中簇即写形态；逐字对齐默认 `standard`
- **用途**：检索端按形态降权/折叠（如 `elided` 名称截断条目不参与精确标题匹配），审计端按形态分组回归
- **双份标记**：FC-T 表格行条目 `format_cluster="lb_marker"` + `component_type="feat_index"`（区别于正文 `feat`），表格行与正文条目各自成 chunk（已确认策略）；同书多份主版本选定（3 组）在 dedup 阶段人工定，不在 schema 内解决
- **KN094（2026-08-03）**：新增 `component_type="feat_intro"`——介绍性 chunk（非具体专长条目）标记。判别规则（57 高置信，format 层打 `intro` 标记）：
  1. 空 text 章首标题（23 个，如《核心规则手册》专长，含《远程工具箱》/《阴招工具箱》等无「专长」字样的导航标题）；
  2. title 以「专长」结尾 + text 无字段标签（`_RE_FIELD_IN_TEXT` 不匹配）的类别介绍段（34 个，如团队专长/超魔专长/护盾流派专长，含 `> 来源：` 行前缀形态）。
  守卫：lb_marker 表格行不参与（feat_index 优先，KN085 28 个空 text 不误伤）；title 以「专长」结尾但 text 含 `**先决条件**：` 等字段标签的多条目拼组（4 个，如新流派专长）保持 feat。
  用途：检索端对 feat_intro 降权（介绍段先于具体条目命中时会稀释检索质量）。
