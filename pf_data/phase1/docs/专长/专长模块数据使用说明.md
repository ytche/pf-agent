## 二、检索端注意事项（按优先级）

### 2.1 【必做】feat_index 元数据组装（KN092/KN093 关联）

速查表行 chunk（`component_type=feat_index`）**不是完整条目**：text 通常只有几十字符（中位 27），形态为「中文名 + 英文名 + 页面/来源列」，**不含收益描述**（benefit 覆盖率 0.2%，3/1871 实测口径）。

检索端正确处理方式：

1. **命中 feat_index 时 → 查找同名 `feat` 正文条目组装回答**：
   - 配对键：中文 title 或 aliases 中的英文名（速查表行 100% 含英文名）；
   - 组装后回答应引用 **feat 正文条目的 text**（含先决/收益/特殊等字段标签），feat_index 行仅作定位/交叉引用；
   - 未找到配对正文时（同专长仅在速查表出现的场景，KN093 反向），直接展示速查表行原文并注明「仅有速查表条目」。
2. **去重职责在检索端（KN093）**：同一专长可能同时存在 feat_index 行 + feat 正文条目（双 chunk），top-K 召回时可能同时命中——检索端按「同 title 归并，优先保留 feat 正文条目」去重，避免重复回答。
3. **检索排序建议**：`feat` 正文条目权重高于 `feat_index`（正文信息量更完整），feat_index 可作为 fallback 或补充命中。

> KN092（feat 正文 benefit 覆盖率 84.9%，缺的 15% 为速查表行/无标签收益条目）登记中：速查表效果列组装 + 正文无标签收益提取列为后续迭代，**一期交付不阻塞**——缺失时检索端如实呈现「无收益描述」，不编造。

### 2.2 【必做】feat_intro 降权（KN094）

`feat_intro` 75 个（章首标题 23 个空 text + 类别介绍段 52 个）是「介绍性内容」而非具体专长。检索端：

- 命中 `feat_intro` 时**降权**（如检索分数 ×0.1 或排到具体条目之后）；
- 空 text 的 28 个 feat_index + 23 个 feat_intro（KN085 口径）不得作为回答正文直接输出——**输出空 text 是对用户的严重事故**，必须拦截（可用 title 兜底或跳过该 chunk）。

### 2.3 【通用护栏】超大 chunk 降权（KN095 已闭环，2026-08-03）

KN095（裸标题吞并，源数据修复）已闭环：chunk 总数 5948→**6022**，page_311 71→130 chunks，**全库已无 >5000 字符 chunk**（最大 1467，情感导体）。此前两个异常 chunk（0070 移情感知 16028 / 0081 种族专长 5864）已拆散为独立条目。**后续更新（2026-08-04，KN112）**：公共层守卫参数化修复后 chunk 总数 6026→**6032**（武器大师手册 6 技法恢复，feat 4080→4086），本文档数字已按 6032 终态同步。

检索端可保留**通用护栏**：text > 5000 字符的 feat chunk 降权（防御未来回归——任何形态导致的异常大 chunk 命中时文本泛化）。

> ⚠️ **数据变更规范**：重跑 pipeline 后必须重跑**四个**后处理脚本——`apply_chm_toc_mapping.py` + `apply_feat_creation_source_promote.py`（book 防回归）+ `backfill_chm_toc_path.py`（toc 防回退）+ `backfill_feat_source.py`（source 防回退，KN095 修复时曾因遗漏一度回退 993→337）。

### 2.4 【建议】拼组 chunk 定性（设计保留，勿当 bug 修）

两类「多条目拼组」chunk 是**设计保留**（条目间以字段标签 `**先决条件：**`/`**收益：**` 衔接，无标题分隔线，拆分会破坏字段归属）：

- **种族专长拼组**：KN095 已闭环消解（武器大师手册_专长_0081 5864 字符拆散为独立条目）；
- **习武为艺拼组**（2462 字符 / 53 行）：KN094 守卫确认的带字段标签多条目拼组，**设计保留**。

检索端处理：命中此类 chunk 时，回答应**定位到具体条目**（按 `**标题**` 或字段标签切出对应片段）再组装，不要整段引用。

### 2.5 【建议】来源书字段口径（四级）

| 字段 | 覆盖 | 口径 | 检索端用法 |
|---|---|---|---|
| `book_abbreviation` / `book_name_cn` / `book_name_en` | 100% | 页头《书名》判定链（conf=50，2693 个）→ 映射表（conf=70，1993 个）→ 行内来源提升（conf=65，1000 个）；`?` 100 个 = page_1367 超魔专长一览 92 + 造物专长一览 8，**设计保留**（跨书索引类） | 溯源展示（书籍名 + 缩写） |
| `chm_toc_path` | 100% | 三级链路回填（源 md → md_mapping.json → toc 路径；organized 文件走注释/来源行路径），粒度 chunk 级 → 章节级 → 文件级递减 | **目录引导**（回答后提供「查看 X → Y → Z」），一期 Agent 溯源核心 |
| `metadata.source` | 16.7%（1010/6032） | 仅正文 `**来源：**` 标签（337）或 `> 来源：` 引用块（656）显式来源；无显式线索不编造 | 行内来源展示；缺失时用 book 字段兜底 |
| `source_confidence` | 四级 0/50/65/70/75 | 0=未知（100 个）→ 50=判定链（2693）→ 65=行内来源（1000）→ 70=映射表（1993）→ 75=武术手册 MA 页头《书名》（162） | 溯源展示可透出置信度（如「来源待核」） |

> 检索端组装溯源回答时的优先级：`metadata.source`（精确到书名）> `book_name_cn`（书籍）> `chm_toc_path`（目录路径）。

### 2.6 【建议】字段语义（feat 正文条目）

- `metadata.feat_type`：list 类型，多标签（如 `["战斗","团队"]`），无标签为空列表；标签已归一化到白名单枚举（见 `专长元数据设计.md` §四），无「专长」后缀；KN084 已闭环（英文名泄漏 180→0），检索端可直接信任。
- `metadata.field_status`：三态 `parsed` / `missing` / `not_applicable`（见 §2.4 表格）。**展示策略**：`missing` = 源文本确实没有该字段，如实不展示；`not_applicable` = 该专长类型不适用（如普通专长无 task_goal），不展示。
- `metadata.prerequisites`：结构化对象 `{raw, items:[{type, value}]}`，type 枚举 `ability/skill/class_level/bab/feat/spell/race/other`——检索端可据此做「前置条件解读」增强回答。
- `aliases`：顶层数组，首元素通常为英文名（`"COURAGE IN NUMBERS (TEAMWORK)"`），其余为译者/编者附注别名——英文检索（按英文名查专长）用首元素匹配。
- `format_cluster`：`standard 3269 / lb_marker 1871 / elided 528 / whitespace 228 / punct 22 / img_marker 104`——**内部口径**，检索端不需要区分（lb_marker ≈ feat_index，elided = 一行式简短条目）。

## 三、数据使用速查（后端对接清单）

```
1. 加载 chunks.jsonl（6032 行）→ 建向量索引（建议 text 全文 + aliases 联合）
2. 检索排序：feat（正文）> feat_index（速查行）> feat_intro（介绍）
3. 命中 feat_index → 按 title/英文名配对 feat 正文组装；同 title 去重（KN093）
4. 命中 feat_intro / 空 text → 降权或跳过（KN094/KN085）
5. text > 5000 字符 → 降权（通用护栏，防御回归）
6. 溯源组装：metadata.source > book_name_cn > chm_toc_path（目录引导必出）
7. 字段缺失（field_status=missing）→ 如实不展示，不编造
```
