## 2. 返工问题清单（R1~R9）

### R1 — 输入范围缺陷（P0-1）

- **缺陷**：pipeline 输入仅扫 `pf_rules_md_organized/专长/` 目录；**根目录 66 个已整理专长文件完全未向量化**（专长1~58 系列、其他专长×3、动物伙伴专长、闹鬼专长等，est 合计 610）。
- **连带影响**：formats 的 test_seeds 形态取自 专长11 等根目录文件，**测试与生产输入脱节**；交付声明「已整理 86 文件召回 100%」建立在输入范围不完整之上。
- **实证**：`git log --oneline` 无根目录文件改动；fc_match 快照中 `专长11.md est=92 got=110` 无对应 pipeline 产出。
- **返工**：根目录 66 文件纳入 pipeline 输入（确认 `_feat_file_condition` 与输入枚举逻辑），或明确排除口径并修正交付声明。
- **复算命令**：重跑 pipeline 后逐文件对账 est↔got。
- **验收断言**：根目录 66 文件每个 est>0 的文件均有产出；或文档中列明排除口径及理由。

### R2 — 字段标签独立行被 section header 跳过（P0-2）

- **缺陷**：`formats/feat.py` 的 `_RE_SECTION_HEADER = ^\*\*[^*\n]{1,30}\*\*` 把独立成行的 `**先决条件：**`、`**专长效果：**` 当分节标题跳过 → 该条目不再产字段。
- **实证**：永罪之书 魔族仪典（L136 `**先决条件：**`）、AG 涤净引导 — benefit/prerequisites 全 missing；**全库 benefit missing 1683/2846 = 59.1%**。
- **返工**：section header 判定排除字段标签行（先决条件/专长效果/描述等），或标签行优先匹配路径。
- **复算命令**：`python3 -m pytest vectorizer/tests/ -q` + 魔族仪典/涤净引导专项断言。
- **验收断言**：魔族仪典、涤净引导 prerequisites/benefit = parsed；全库 benefit missing 率显著下降。

### R3 — punct 条目丢失（P0-3）

- **缺陷**：`**可信伪装：**`（内海诡道ISI L6）等 7 个 punct 形态条目产出 0 命中（与 R2 同根因：独立标签行被跳过）。
- **实证**：ISI 专长文件判别器 est>0，产出 0；`fc_full.txt` 中 ISI 无产出记录。
- **返工**：punct 独立标签行应产出条目（format_cluster=punct），随 R2 一并修复。
- **复算命令**：`python3 vectorizer/exploration/专长/fc_match.py --file 专长/内海诡道ISI_专长.md` + 产出断言。
- **验收断言**：ISI 产出 = 判别器 got（7 条），format_cluster=punct。

### R4 — AG 标题形态不支持（P0-4）

- **缺陷**：`_RE_TITLE` 不支持「中文（类型）English」形态（如 `**奥多里战斗技艺（战斗）Aldori Artistry**`）→ AG 判别器 got 9 vs 产出 2，7 条丢失。
- **实证**：`冒险者指南AG_专长.md` L4 起 11 个标题仅 2 个产出，且字段全 missing。
- **返工**：`_RE_TITLE` 增加「（类型）后接英文」形态分支。
- **复算命令**：`python3 vectorizer/exploration/专长/fc_match.py --file 专长/冒险者指南AG_专长.md` + 产出断言。
- **验收断言**：AG 产出 = 判别器 got（9 条）。

### R5 — 正文句误产伪标题（P1-1）

- **缺陷**：`_RE_BARE_CN_EN_PAREN = ^([一-鿿]{2,})[（(]([A-Za-z][^）)]*)[)）]\s*(.*)` 误包裹正文句。
- **实证**：永罪之书 L149/159「当你通过魔族仪典（Fiendish Obedience ）专长获得神恩时…」→ 2 个 elided 伪条目（正文内容冒充条目标题）。
- **返工**：加正文句排除（前缀词黑名单/句长阈值/无闭合语义判定）。
- **复算命令**：永罪之书产出中检索「当你通过魔族仪典」= 0。
- **验收断言**：全库无「正文句首字串」伪标题（probe 脚本断言）。

### R6 — component_type=feat_index 未实现（P1-2）

- **缺陷**：设计 `专长元数据设计.md` §五明文「FC-T 表格行条目 format_cluster="lb_marker" + **component_type="feat_index"**（区别于正文 feat）」；实际 `build_chunk` 不设 component_type，**1354 个 lb_marker chunk 全标 "feat"**。
- **实证**：`processors/feat.py:build_chunk` 无 component_type 赋值；chunks.jsonl 中 lb_marker chunk 的 component_type 全为 "feat"。
- **返工**：`build_chunk` 按 `item["format_cluster"] == "lb_marker"` 设 `component_type="feat_index"`。
- **复算命令**：统计 chunks.jsonl 中 format_cluster=lb_marker 且 component_type=feat_index 的数量。
- **验收断言**：1354 个 lb_marker chunk 全标 feat_index，正文 feat 不变。
