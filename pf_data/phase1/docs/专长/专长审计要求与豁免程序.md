# 专长模块审计要求与豁免程序（流程补丁包 #3~#8 落地）

> 产出日期：2026-08-01 | 依据：`专长模块开工前_流程抽象与预防清单.md` §一（8 个流程补丁）
>
> 目的：把法术模块 5 轮审计返工的 8 类失实模式在专长开工前一次配齐，目标"5 轮不验收"压缩到约 2 轮。

---

## 一、验收口径锁定（补丁 #3）

**执行方 verify = 审计方 audit 同一口径，禁止窄口径冒充。** 具体约定：

1. **判别器回归基准**：`exploration/专长/fc_deviation_matrix.json`（189 条：rel/est/got/per 簇明细）是唯一回归基准。任何判别器/解析器改动后的 got 口径必须与矩阵逐文件可对账。
2. **同口径脚本**：验收脚本统一为 `vectorizer/verify/verify_feats.py`（实现阶段落地），审计方复算时**直接运行同一脚本**，禁止另写窄口径脚本"证明通过"。
3. **不变量清单**（实现阶段按产出定值，当前为红线草案）：
   - 判别器口径 got 与矩阵偏差全可解释（超差归因给表格双份/est 低估/修复项）
   - pytest 全绿（test_feat* 系列）
   - 召回验收：权威清单（职业专长列表页 + 专长汇总表）↔ chunk title+aliases 一对一
   - title 合法性：非"中文+（English）"形态全量列出并归类（KN019 四类全命中口径）
   - 字段值健康度：值长分布 / 含句号数 / 含 `**` 残留数
4. **单方面放宽目标值 = 失实**：验收方禁止自行放宽不变量数值；如需调整走 §三 变更程序。

## 二、豁免程序（补丁 #4）

**先立定性标准，再豁免；禁止 ℹ️ 自行放行。**

1. **豁免前置**：豁免项必须首先满足"逐字核对后判定为源数据缺陷或合法形态"——合法形态判定依据 `format_clusters_规范与偏差对账.md` §一 六种放行形态（whitespace/punct/lb_marker/img_marker/elided/annotation），不在六形态内的逐字不符一律视为缺陷，不得豁免。
2. **逐项书面申请**：豁免清单每项必须包含：
   - `chunk_id`（或 文件:行号）
   - 豁免值（当前 got/est 对比）
   - 理由（归因必须带实测证据——补丁"归因必须验证"）
3. **审批路径**：执行方汇总 → 人工确认（k2.7 护栏）→ 审计方复核。执行方无单方豁免权。
4. **登记落位**：豁免登记落 `docs/state/`（禁 /tmp），格式：`feat_exemptions_<日期>.md`。

## 三、复算命令（补丁 #5）

**每个 ✅ 必须附复算命令，跑不出就停下来查，禁止手填。**

| 断言 | 复算命令 |
|---|---|
| 判别器回归 | `python3 vectorizer/exploration/专长/fc_match.py` 全量快照 diff 基线矩阵 |
| 单文件判别 | `python3 vectorizer/exploration/专长/fc_match.py --file 专长/xxx.md` |
| pytest 全绿 | `python3 -m pytest vectorizer/tests/ -q` |
| 验收通过 | `bash regen_feat_chunks.sh`（单入口，含 Step 4 验收） |
| 旧数字残留 | 裸模式 grep（补丁 #8）：`grep -rn "4214" docs/`（不止 `~4214`） |

## 四、交接清单机检（补丁 #6）

1. **条数 vs 计数一致**：交接文档声明的条数必须与清单实际行数一致（法术教训："19 条写 20 条"传染执行方漏登 4 条）。
2. **登记物禁引 /tmp**：全部登记物（基线/豁免/清单）落 `docs/state/`。
3. **清单自检**：交付前先跑一遍"清单自身核对脚本"（条数/文件名/路径存在性），再交审计。

## 五、宽启发式扫查（补丁 #7，开工即做）

法术三轮共同盲区（44 罗马数字伪标题、~23 D 类续段标题）在专长开工即扫：

1. **罗马数字伪标题**：`^(I|II|III|IV|V|VI|VII|VIII|IX|X)[.、．]` 开头的非条目行全量列出（KN019 教训）。
2. **续段伪标题**：无闭合星 `**` 的加粗段起点，字段标签佐证失败后不得直接放行（判别器 FC-8n 回落链已含此逻辑）。
3. **链接后 N 字 probe**：剥离全部非文字符号后取"链接后 14 字"，在同 doc 全部 chunk 检索，确认截断（KN023 的 33 处确认口径，专长链接 103 处/单文件必须跑）。

## 六、旧数字裸 grep（补丁 #8）

改完文档旧数字残留是第 5 轮 V1/V2 返工根因。约定：

- 数字检索一律裸模式：`grep -rn "69" docs/`（不写 `~69`、`（20`）
- 对账数字变更后，先裸 grep 全库确认无残留，再声明 ✅
