# §14 撤回与修订流程

> 详细规则文档。主文档 `未整理目录整理规则.md` 第 14 节指向本文件。
> 仅在发现已合并内容归属错误、需反向提取时按需加载。

## 14.0 触发场景

- 规则被否定/修订（如 §4.0 修订导致"通用专长合并到他源聚合文件"成为错误做法）。
- 整理时归类错误（如把 HH 专长合入 VC_专长）。
- 目标文件定位错误（如应该归入 page_212 的内容被合入 page_211）。

## 14.1 确认错误范围

1. 扫描目标文件中的 `<!-- XX-source: -->` 隐藏标记，识别非本来源书的条目。
2. 编写诊断脚本统计"错误归属条目数 / 来源书分布"。

## 14.2 编写反向提取脚本

参照 `extract_feats_from_vc.py` 模式：

1. 按标记切分文本块（`<!-- XX-source:... -->` 至下一个标记或文件末尾）。
2. 按 `XX` 来源书标识分类到正确的源书聚合文件：
   - 已存在 → 追加（注意行尾归一化，见主文档 §4.4）。
   - 不存在 → 创建（按主文档 §4.6 命名）。
3. 从原目标文件移除非本来源书的块。
4. 保留原目标文件中"前导内容"与本来源书条目。

## 14.3 验证清单

- [ ] 各源书聚合文件的来源标记是否齐全（每个被撤回条目都有 `<!-- XX-source: -->` 与 `> 来源：...`）。
- [ ] 原目标文件是否仅剩本来源书条目（`grep -c "XX-source"` 应为 0）。
- [ ] 未引入新的重复或丢失内容（行数对比、条目数对比）。
- [ ] 行尾换行符风格一致（避免 CRLF/LF 噪声 diff）。

## 14.4 同步更新规则文档

将新认知固化为新规则（避免重复错误）。

- 例：发现"通用专长不应合并到他源聚合文件"时，更新主文档 §4.0。
- 例：发现"货品服务条目归 page_212"时，新增 §4.2。

## 14.5 报告修订

在 `<来源书>_reorganization_report.md` 顶部加"修订说明"小节，写明：

- 撤销内容（哪 N 条被错合并）；
- 原因（哪条规则被否定/修订）；
- 影响的文件清单。

在 `pf_data/phase1/未整理目录整理问题记录.md` 中追加本次修订的小节。

## 14.6 关键不变量

撤回流程不应丢失任何条目，每个被撤回的条目都应带完整的隐藏标记和 `> 来源：...` 标注进入新位置。
