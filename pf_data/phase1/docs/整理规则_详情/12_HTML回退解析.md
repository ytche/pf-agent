# §12 Markdown 格式混乱时的 HTML 源文件回退解析

> 详细规则文档。主文档 `未整理目录整理规则.md` 第 12 节指向本文件。
> 仅当 `未整理` 目录下的 Markdown 文件因转换问题导致结构严重混乱时使用本规则。

## 12.0 何时选择 HTML 回退

出现以下任一情况时，优先考虑读取 HTML 源文件：

- Markdown 中大量条目标题与首句正文挤在同一行，按行拆分极易切错边界。
- 标题被 `![[图片]]` 标签切断，导致自动标题检测失效。
- 同一文件内元数据标签写法混乱（如 `栏位：无`、`灵光 微弱变化系`、`**类别**：炼金工具**描述**：...` 等）。
- 中英名称混排且无统一分隔符，正则拆分风险高。
- 按 HTML 解析后，条目边界、元数据、子条目关系明显更清晰。

## 12.1 如何定位 HTML 源文件

1. 查看 `pf_data/phase1/md_mapping.json` 中对应条目的 `html_file` 字段。
2. 若 `html_file` 缺失，可按同名规则尝试 `~/.openclaw/workspace/pf_rules/<文件名>.htm`（CHM 解压目录）。
3. 编码通常为 **GB2312**，读取时指定 `encoding='gb2312', errors='ignore'`。

## 12.2 HTML → 文本的转换原则

将 HTML 粗粒度转换为近似 Markdown 的纯文本，便于复用现有基于行的拆分逻辑：

| HTML 标签 | 处理方式 |
|-----------|---------|
| `<BR>` / `<BR/>` | 替换为换行符 `\n` |
| `<STRONG>` / `<B>` | 替换为 `**` |
| `<EM>` | 替换为 `*` |
| `<BLOCKQUOTE>` | 替换为 Markdown 引用块前缀 `> ` |
| `<A>...</A>` | 删除（保留链接文本可能造成噪声） |
| `<P>` / `<DIV>` / `<SPAN>` / `<FONT>` / `<IMG>` / `<HR>` / `<OBJECT>` / `<PARAM>` 等 | 删除标签，保留内部文本 |
| HTML 实体 | 使用 `html.unescape` 还原（如 `&mdash;`） |

转换后仍需做以下清洗：

- 去除译者署名行（如 `译者：xxx`）。
- 合并被 `<BR>` 切断的跨行标题。
- 过滤图片占位符和空行。

## 12.3 条目拆分与去重

HTML 转换后的文本仍按行处理，拆分逻辑与 Markdown 源基本一致：

1. **标题识别**：通常以 `**中文名（English Name）**` 或 `**中文名**` 开头。
2. **元数据识别**：使用 `灵光/灵氲`、`栏位/位置`、`价格`、`类别`、`施法者等级/CL` 等关键词判断条目正文起点。
3. **子条目过滤**：部分物品包含组件子条目（如 `黑羽`、`黄铜叶`），通过长度、无加粗、无标准元数据等特征过滤，避免误判为独立物品。
4. **去重**：仍然使用隐藏标记 `<!-- <来源>-source:<源文件名>:<条目名> -->` 判断是否已写入。

## 12.4 物品分类经验（以 VC 物品10.htm 为例）

从 HTML 解析出物品后，按以下优先级归入 `装备_魔法物品/` 子目录：

1. 若 `类别` 为 `炼金工具` / `冒险装备` / `工具包` / `交通工具` / `炼金物品`，直接归入 `货品服务/`。
2. 若标题或 `栏位` 含"戒指"，归入 `魔法物品/戒指_权杖_法杖/`。
3. 若标题或 `栏位` 含"权杖"，归入 `魔法物品/戒指_权杖_法杖/`。
4. 若标题含典型武器关键词（鞭、拳套、刀、箭、闷棍、灯笼、链枷、长鞭、硬头锤、水兵刀等），归入 `武器/`。
5. 若标题或 `栏位` 含"护甲"/"皮甲"，归入 `特定魔法防具/`。
6. 若正文无魔法灵光/施法者等级等魔法特征，归入 `货品服务/`。
7. 其余归入 `魔法物品/奇物/`。

> **注意**：`栏位` 字段可能附带后续元数据（如 `戒指；**价格** 900 gp；**重量** ―`），分类时应使用子串匹配，不要精确等于 `'戒指'` 或 `'护甲'`。

## 12.5 常见问题与规避

| 问题 | 规避方法 |
|------|---------|
| 跨行标题被拆成多行 | 预合并：从加粗标题行开始，持续合并直到遇到元数据起始行为止 |
| 元数据以纯文本形式出现（无 `**`） | `_is_vc_metadata_start` 同时识别加粗和纯文本元数据关键词 |
| 子条目被误判为独立物品 | 增加长度、加粗、元数据过滤 |
| 同一脚本多次重跑导致重复记录/计划重复 | 计划文件每次覆盖写入；重复记录文档需定期去重，或在追加前检查是否已存在同书章节 |
| HTML 编码错误 | 使用 `errors='ignore'`，避免解码异常中断整理 |

## 12.6 输出要求

使用 HTML 回退解析时，报告文件中应明确说明：

- 哪个 Markdown 源文件因格式混乱未直接使用；
- 对应的 HTML 源文件路径；
- 解析后的条目数、分类统计；
- 是否仍有人工校验点。

示例：

```markdown
## 物品10 分类汇总

- 戒指：3 条
- 权杖：2 条
- 特定魔法防具：1 条
- 特殊武器：8 条
- 奇物：37 条
- 货品服务：11 条
```
