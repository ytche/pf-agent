### 1.1 与 KN012 的交界（实测确认）

两者共享底层边界模型：`parse_fields` 只认 `\n\n` 和 `\n**标签` 两种值边界。

- KN012 修「标签位置」（粘连标签回到行首）；KN013 修「值内容」（值里不该有正文/残留标签）；
- M1 实测：源文件写别名 `**持续**：`，Step 2/3 标签集不含别名未拆行，B2 改名后显示为 `**持续时间：**` 残留——**正是 KN012 机制，KN012 落地后自动消失**（实查 `spell_AG-冒险者指南_0022` 确认）；
- KN012 扫描的 B 类 69 个（SR 值粘正文）是 KN013 在 SR 字段上的表现。

**因此执行顺序：KN012 先落地 → 复测 → 再按本方案处理剩余 M2/M3/M5。**

### 1.2 M2 实样


## 2. 修复设计

### 2.1 M2：方案 A —— `_parse_*` 清洗层（F1 模式泛化）

在 `processors/spell.py` 为字符串字段增加清洗层，`infer_metadata` 中对 raw 值做语义截断。先例：`_truncate_trailing_prose`（spell_level，processors/spell.py:58）、`_parse_saving_throw`（遇 `（见描述）`+CJK 截断，L579）。

#### 通用截断器 `_truncate_value_prose(value)`

适用 target / effect / range / casting_time / duration：

1. **截断信号**（命中即截）：
   - `。`后仍有 >10 字符正文；
   - `\n` 后的行**不**以续行信号开头；
   - 值 token 序列结束后紧跟 CJK 正文起始（仅 duration 用，见下）。
2. **续行信号**（保护合法跨行值）：行首为 `+` / `(` / `（` / `和` / `或` / `，` / `、` / 数字。
3. **duration 专属规则**：保留到 `(D)` / `（可消解）` / `（解消）` / `(见后文)` 等标记为止；其后 CJK 正文一律截断。

#### school 专属 `_parse_school`（顺带覆盖 M3 症状）

白名单前缀截断：从值头匹配 `(防护|咒法|预言|惑控|塑能|幻术|死灵|变化|通用)(系)?`，命中即截断：
- `预言系等级⏎：通灵者 0…` → `预言系`；
- `变化系；等级 ⏎牧师1…` → `变化系`；
- 未命中白名单：保留原文（维持现有「未知学派保留」语义）。

### 2.2 M3：`_merge_bold_field_lines` 扩展

覆盖「标签与冒号跨行断开」形态 `**等级**⏎：`（或 `等级⏎：`），在 normalize 阶段合并为完整标签行。改动集中在 `formats/spell.py:_merge_bold_field_lines`（L495），配正反测试。

### 2.3 M5：`parse_fields` 边界标签集补全

`registry.py` 的 `ALL_FIELD_LABELS` 只含 v0.3 规范字段别名，不含 `EXTRA_FORMAT_LABELS`（描述/诡计描述/伪装对象），导致 `**描述：**` 不构成值边界被吞。

修复：`parse_fields` 的 `next_field` 边界模式改用 `ALL_FIELD_LABELS + EXTRA_FORMAT_LABELS`（注意 `LABEL_TO_KEY` 不含它们，不会误产字段，只是让边界生效）。

## 3. 结构不变量

1. **chunk 边界不变**：清洗发生在 processor 层 raw 值上，不动 normalize/split → chunk_id 集合不变（M3 的 normalize 改动只合并断行，不影响标题识别）；
2. **合法长值不截断**：续行信号保护的跨行值（range 算式、`和/或` 并列）保持完整；
3. **negative test**：`effect` 值本身含 `。` 的合法枚举（如 `属性伤害，目盲，困惑…恶心。` 单句结束型）不误截——截断要求 `。` 后仍有 >10 字符；
4. **status 诚实**：清洗后值仍非空 → `parsed`；清洗导致空 → `missing`（不引入空字符串）；
5. **F1 字段不受影响**：saving_throw/spell_resistance 的现有清洗行为不变。

每条不变量在 `vectorizer/tests/` 中对应断言。
