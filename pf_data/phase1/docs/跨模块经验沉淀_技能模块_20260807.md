## 一、开工前机制（Prepare 阶段）

### 1.1 类目是跨 L1 页面集合——audit 需「L1 子树 ∪ 显式清单」模式（M1.1）
① **内容**：技能类目**不是单一 L1 子树**——CHM「技能」L1（page_161 起）+ 6 处跨类目页（Unchained 技能与选项 / 巨人猎手新技能选项 / 河域子民新技能规则 / 冒险者的军械库工具包 / 异能神秘技能解放 / 科技指南 page_760 / 官方 FAQ page_837）。既有 `audit_chm_scope_gap.py` 的 L1 子树模式直接套用会整批漏扫。
② **落地**：类目注册表扩展为 `cat → {L1 子树列表} ∪ {显式 html 清单}`；职业 page_257（盗贼天赋技能解放）标注「职业模块已覆盖，豁免」而非纳入。**新模块（装备=武器/防具/炼金术跨 L1、怪物=附录+书内散页）大概率同构，先判 L1 覆盖度再决定 audit 模式。**

### 1.2 CHM 归属权威表——逐行定位 + 批次定性
① **内容**：开工前建「CHM 归属权威表」（`CHM_FULL_TOC_WITH_LEVELS.md` 实测行号）：每批输入（A1/A2/B1/B2）对应 CHM 行区间 + organized 路径 + 定性（核心范围/扩展书/职业豁免）。技能 = 26 技能页（技能详述 25 + 根目录孤儿页 page_182）+ UI 8 + 格拉利昂语言汇总 L5 + 7 跨类目页。
② **落地**：批次清单（prepare_batches.json）按权威表四批切分（每批 ≤200KB），孤儿页（page_161/162/182/1038）必须显式纳入——**根目录孤儿页是 L1 子树的盲区**（同 race §七 一次性经验）。

### 1.3 散件 MD5 去重——只证不删 + 双副本 diff（M1.3）
① **内容**：3 对 MD5 完全重复（背景技能/整合技能/分组技能 vs Unchained 同名）**只记录「重复副本豁免」不删除**；另 3 组「疑似双副本」逐 diff 定性（新技能选项 / 新技能规则 / 工具包 vs 工具和技能工具包）——`工具包.md`（9469B）与 `工具和技能工具包.md`（27219B）MD5 不同，diff 后确认是不同内容。
② **落地**：去重结论写 `散件去重结论.md` 进人工门 1；**源数据只读红线：任何情形不移动/不删除源文件**（同种族 §五 元教训）。

### 1.4 目录驱动权威清单——CHM 目录即 26 技能权威（决策 11）
① **内容**：26 技能的关键属性/须受训【训】/防具检定减值【减】三字段 = CHM「技能详述」目录**直接构成**权威清单（`技能名规范表.md` 26 行）；正文标题后缀只作一致性校验，**不一致时以 CHM 为准并记 KN 偏差**（KN158 正是此机制的产物）。
② **落地**：同 trait §1.2「目录即权威词表源」——**技能的关键属性/【减】/【训】、trait 的类型词表、后续装备的材料/重量，都可先问「CHM 目录是否直接给出」**；权威清单落 verify 断言（26 技能三字段全量），防静默漂移。

## 三、产出/修复时机制

### 3.1 来源书归属 = 专属表短路，禁目录/文件名子串推导（P1 系统性失实，本模块最大教训）
① **内容**：M6 独立复测审计发现 **557/557 全标 CRB**——`DirectoryNameProvider` 对 `directory_hints`（含**文件名**的全部路径 parts）做「技能」**子串**匹配 → 文件名/目录含「技能」二字的文件全部误命中 CRB（`.../工具和技能工具包.md` 的「技能」二字、`技能/巨人猎手手册_新技能选项.md` 的目录名）。**目录名推导来源书在全库是系统性失实的**，不是个别噪声。
② **落地**：processor 侧专属表短路——`_B2_SOURCE_OVERRIDES`（7 个 rel 前缀 → (abbr, 中文名, 英文名, conf=75)）+ `_B2_SOURCE_DOC_EXPECT`（12 basename 投影，verify 同源）；**不动公共层 providers.py**（KN136 冻结模块漂移教训——公共层改动会让 spell 重生成漂移）。终态 CRB 214 / PU 226 / FAQ 63 / AA 31 / OCCULT 10 / GIANT 5 / TG 5 / PotR 3。
③ **迁移**：任何新模块的来源书判定，**优先查「源文件所在目录/文件名是否能精确映射」而非子串推导**；映射表放 processor 专属常量，verify import 同一常量（§3.2）。

### 3.2 verify 同源表——import processor 的期望表，单点数据源
① **内容**：`verify_skills.py` 检查 7「来源书一致性」直接 `from vectorizer.processors.skill import _B2_SOURCE_DOC_EXPECT`——**期望表只有一份**，改表不跑 verify 也会自动生效（表改一边的静默漂移不可能发生）。
② **落地**：**verify 的期望数据一律 import 实现的常量，禁复制粘贴**（复制会双份漂移）；本模块后续 KN158 权威清单断言（26 技能三字段）同样单点定义于 verify。

### 3.3 verify 断言「解析错了」而非只查「缺」——无缺口 ≠ 正确
① **内容**：审计前 verify 检查 5 只断言 `book=="?"` 计数——**「未知」为 0 ≠ 「已知且正确」**：557 个 chunk 全部 book=CRB（无 ? 缺口）却是全量错误。这是系统性盲区：缺口闸口防「缺」、不防「错」。
② **落地**：**闸口不能只查缺失，必须有值域/一致性断言**（来源书 ↔ rule_version 匹配、权威清单三字段全量比对）；「无缺口即正确」的思维惯性与 spell 模块 `OK 数合理` 教训（CLAUDE.md 不变量清单）同源——**负数测试与正数测试必须成对**。

### 3.4 源数据形态一致性——同语义标记跨文件分隔符异体（KN158）
① **内容**：KN158 根因 = 游泳标题 `(力量，防具检定减值)` 用**全角逗号**，其余 8 个【减】技能统一**分号** → `_parse_title_suffix` 按 `split(";")` 拆分失败 → key_ability 混入杂质、armor_penalty=False。**9 个文件 8 个同形态 + 1 个异形态 = 强信号**（不是设计差异，是漏网）。
② **落地**：修复 = 源数据规范化脚本 `fix_skill_kn158.py`（内容锚定幂等：dry-run → apply → 幂等复验 0 处；CRLF 字节级保留检查；命中数 != 1 终止防误改）+ TDD 回归 seed_30（test_seed_30_swim_semicolon_suffix，SEEDS[29] 追加）+ verify 权威断言。**「N 个同类文件 1 个异形态」应作为投产前的形态一致性扫描维度**（同 trait §3.1 形态超集归一化）。

## 四、验收/审计时机制

### 4.1 独立复测审计 5 项复核（M6）
① **内容**：审计 5 项 = 判别器 / 召回 / 字段健康 / 形态逐字核对 / 结论遗留复核——比 trait 产出即检多「形态逐字核对」（抽样 chunk 与源数据逐行比对，抓到 P1 系统性失实）与「结论遗留复核」（审计者须复核被审计方遗留清单是否属实）。
② **落地**：**审计必须有「独立复测」环节**（不被交付方结论带节奏）；判别器 est=382↔got=560（+178 全定性，零静默丢失）——**跨来源书汇聚类目的 est 偏差天然大**，对账要全定性说明而非只看百分比。

### 4.2 豁免/筛选用精确 basename，禁 endswith 子串（P2-①）
① **内容**：`'.../工具和技能工具包.md'.endswith('工具包.md') == True`——endswith 子串把「工具和技能工具包.md」误豁免进「工具包.md」的豁免清单 → est 修正 51→31 **从未生效**（先被后写的精确豁免覆盖），审计抓出后改 `rel.rsplit("/", 1)[-1] in _SKILL_EXEMPTIONS` 精确 basename → est=382/got=560 才生效。
② **落地**：**任何「文件名判定」一律精确匹配（basename 集合或完整路径），禁 endswith/contains 子串**——「技能」子串（§3.1）与「工具包」子串（本节）是同一陷阱的两个实例：**子串匹配在文件名判定上永远不可靠**。

### 4.3 交付文档数字必须实测对账（自查失实）
① **内容**：数据使用说明 §一 skill_rule 构成初稿写「FAQ 63 / 巨人猎手 3」，实测 **FAQ 61 rule + 2 intro、巨人猎手 5**——交付文档的构成数字来自记忆而非实测，审计自查时逐条对账修正。
② **落地**：**交付文档所有数字（构成/分布/比例）写完即对账实测**，不得凭过程记忆书写；对账口径 = 产物 chunks.jsonl 实测（同 race 产出对账报告按终态更新的惯例）。

### 4.4 闸口参数变更 = KN 一一对应登记
① **内容**：同 trait §4.2——闸口参数（如 min-main-count、book '?' 阈值）每次变更必须对应一条 KN 登记，防「静默放宽」。
② **落地**：技能模块 book '?' 0（全对账后无需放宽，来源书修复的正面验证）；`docs/技能/技能模块审计要求与豁免程序.md` 固化豁免程序（P2-① basename 精确化 + P2-② 快照表述）。

## 五、元教训——本次新增/强化

1. **无缺口 ≠ 正确**（§3.3）：缺口闸口（book '?' =0）全过仍可 557/557 系统性失实——**断言必须有值域，不能只有存在性**。强化种族/专长「闸口只查缺不查错」盲区共识。
2. **子串匹配永远不可靠**（§3.1/§4.2 双实例）：DirectoryNameProvider「技能」子串（来源书 557 全错）与 endswith「工具包」（est 修正从未生效）——**文件名/目录判定 = 精确路径映射或精确 basename，禁子串**。新模块开工前把子串匹配列为禁止项。
3. **来源书归属必须有显式映射**（§3.1）：目录名推导来源书在汇聚类目（多来源书）上系统性失实；**专属表短路 + verify 同源 import** 是可靠模式——不动公共层（KN136），期望表单点定义。
4. **N 个同类 1 个异形态 = 强信号**（§3.4/KN158）：游泳全角逗号 vs 8 技能分号——**形态一致性扫描应列入投产前清单**；修复走「源数据规范化脚本（内容锚定幂等 + CRLF 保留）+ TDD 回归 seed + verify 权威断言」三件套。
5. **独立复测审计的价值**（§4.1）：M6 审计抓出 P1 系统性失实 + P2×2（endswith 从未生效、快照表述）——**审计者独立跑数据，不依赖交付方结论**；形态逐字核对是抓系统性失实的有效手段。
