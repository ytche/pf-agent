# 法术原始 Markdown 非标准格式登记

建立日期：2026-10-29  
范围：`pf_data/phase1/pf_rules_md_organized/法术/` 及其同源页面中，影响标题识别、条目切分和字段解析的**格式问题**。

## 文档定位

- 本表记录原始 Markdown 的非标准形态，供 pipeline 容错和未来统一源格式清洗使用。
- 编号使用 `SMF（法术源格式）NNN`，与 KN（数据侧已知问题）分开；KN 记录缺陷及处置，本表记录源格式事实。
- 登记不等于授权修改源文件。未来清洗须使用锚定、幂等脚本，保留原行尾约定，并逐文件回源核对。
- 只记录排版和结构问题；译名、数值、条目增删、来源归属等内容类问题仍走单独审批。
- 各格式族可能互相重叠，条数和受影响文件数不得直接相加。

## 状态约定

- **待容错**：已确认问题，等待 pipeline 修复。
- **容错已覆盖**：pipeline 已有或已补规则，源格式仍未清洗。
- **待源清洗**：适合未来统一修源，但尚未排期。
- **源清洗已闭环**：指定范围源文件已规范并全量验证。
- **观察**：需进一步确认是否为合法内容或章节结构。

## SMF（法术源格式）008：紧凑内联标题的罗马后缀与注记粘连

**状态**：容错已覆盖／未来可源清洗  
**关联**：KN（数据侧已知）244、KN（数据侧已知）246、异能选集 PA

### 原始形态

```text
……你可以眨一下眼睛。撕扯肢体 I（Rend body I）学派：塑能系等级：异能者 5
注：再生术（Regenerate）撕扯肢体 II（Rend body II）学派：塑能系等级：异能者 6
```

标题、学派和等级字段全部挤在同一行；中文基名与罗马后缀之间还有空格。旧的紧凑标题规则不允许名称含空格，只截取最后的 I/II；较早的通用规则还可能把“注：再生术（Regenerate）”并入标题。

### 已知来源

- `法术/异能选集PA_法术.md:28-43`
- 撕扯肢体 I–IV、精神蛀虫 I–IV 及同源编译页对应条目。

### 建议规范形态

```text
【塑能】撕扯肢体 I(Rend body I)
**等级**：异能者 5

注：再生术（Regenerate）
【塑能】撕扯肢体 II(Rend body II)
**等级**：异能者 6
```

### 清洗注意

注记独立成行，标题带完整中文基名和罗马后缀；不能为了覆盖该形态而允许任意带空格散文成为标题。

## SMF（法术源格式）009：正文破折号与标题种族后缀混淆

### 已知来源与影响

- 涉及 20 个 chunk：Spell CRB 医疗系列 6、屠龙者手册 8、BotM 3、Spell ARG 1、
  page_1007 合并块 1、典礼 1。修复前 19 条 `spell_level` 恒空。
- 字段解析依赖 `等级：`／`环位：` 带冒号形态，无冒号时整段等级值丢失。
- 连带影响：屠龙者手册 6 条把括注（`一块龟壳`、`一个价值150金币的小玻璃球`）误当
  `subschool`。

### 当前容错（2026-10-30）

`formats/spell.py::_unify_field_labels` 三条规则：空值 bold 标签、`；` 后裸标签、
`环位` + 2 空格以上。值尾紧贴的下一字段标签（`…术士/法师3施法时间`）不在本层拆成
字段——那会让 `casting_time` 吞掉整段表头；改由 `_truncate_trailing_prose` 在
贴数字的 `施法时间/成分` 处切断环位取值。实测 19 条回填、6 条 subschool 归零，
`casting_time` 等字段零新增、零污染。

### 建议规范形态

```text
**等级：** 牧师 1，先知 1，战斗祭司 1
```

### 清洗注意

属标签缺失而非内容错误，优先做 pipeline 容错（允许无冒号、允许值与标签跨行）；
源清洗时统一为带冒号单行形态，且不得改动职业名与环级。放宽规则时注意
「等级」在正文里常作后缀词（施法者等级 / 1分钟/等级 / 全部等级），
裸空格形态只能对「环位」放开。

## 后续源格式清洗原则

1. 先按本表建立文件与格式族清单，再按格式族分批，不逐文件随手修改。
2. 每批只改排版，不改规则含义；出现译名、数值、条目增删或来源归属变化时立即停止并转内容审批。
3. 修复脚本必须内容锚定、幂等、保留行尾，输出逐文件变更清单。
4. 清洗前后重跑对应 pipeline，对 chunks 做全量 diff；标题、边界、正文和来源变化分别对账。
5. pipeline 容错与源清洗不互相替代：源格式已规范后，仍需保留必要守卫，防止历史副本或新增数据回归。
6. 每次容错修复或源清洗后，更新本表状态、关联 KN 和验证证据。
