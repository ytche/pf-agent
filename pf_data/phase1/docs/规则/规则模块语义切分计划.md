## 二、元数据设计

### 2.1 公共字段（沿用既有骨架）
chunk_id / doc_id / category / component_type / title / text / source / book_abbreviation / book_name_cn / book_name_en / chm_toc_path / page_ref / format_cluster + field_status 三态 + rule_version。

### 2.2 本模块特有字段：toc_group（**用户拍板 2026-08-09**）

| 决策项 | 结论 |
|---|---|
| 字段 | `toc_group`：记录该 chunk 对应**原始目录所属的分组** |
| 枚举（4 值，verify 值域断言）| `core_rules`（核心规则）/ `rules`（规则）/ `retrain`（重训）/ `quick_reference`（常用速查）|
| 归属 | **本模块特有字段，不进骨架（公共 schema）** |
| 与 chm_toc_path 关系 | 并存：toc_group 是目录分组的一级索引，chm_toc_path 保留完整溯源路径 |
| 赋值机制 | **manifest 显式注解**（prepare_batches.json 每文件条目带 toc_group 键），M1 人工门固化后不运行时推导——保证「快速分组检索」初衷不依赖路径判断 |

**决策原因（用户拍板，记录原文语义）**：
1. 业务无关——纯分组标记，不参与任何业务解析/判定。
2. 初衷：以后再次处理 chunk 内容时（清洗/迭代/检索）可快速按分组检索，无需根据业务字段（chm_toc_path 前缀匹配、book 判定等）做复杂判断。
3. 不入骨架：本模块特有字段，避免污染公共 schema，遵循公共层零改动原则（KN136 口径）。

## 三、切分策略（章节型新形态，S1~S6 格式簇分派）

**chunk 单元 = 语义节**，按格式簇分派（无单一启发式，formats/rule.py 内分派）：

- S1 CRB 结构化页（`####`/`###` heading）→ 每标题一节，标题即 chunk title
- S2 环境页（加粗标题形态）→ 加粗标题 = 节边界
- S3 BBS 星壳页（重训 page_159）→ 星壳加粗标题 = 节边界；先剥离 URL/译者/编注行（技能 `_RE_URL_LINE`/`_RE_TRANSLATOR_LINE` 先例）
- S4 纯表格页（page_1/page_9）→ 整表 1 chunk（rule_table）
- S5 prose 无结构页（UCa 休整期/GMG/怪物规则）→ 按语义小标（「前言」「表 X」等）划分，无标头段落群合并
- S6 超大型聚合页（永罪之书 296K 等）→ 先按条目级标题预拆为节，节内走小块合并/oversize 规则（规则书向量化规则.md §6 七场景表）

**表格归属**：规则正文中的表跟随所属节（不独立成 chunk）；例外 = 整页纯表格页（S4）。MIN_CHUNK_CHARS 以下小节与相邻节合并；oversize-limit 5000 超限按下一级结构再拆。
