## 一、设计原则（对齐 v2.0 类目无关引擎 + 装备先例）

| 骨架模式 | 落地 | 规则元数据影响 |
|---|---|---|
| **骨架通用字段**：`chm_toc_path` 顶层字段由 FileProcessor 模板方法统一填充 | 规则不重复设计来源路径富化 | 字段表不含来源路径类字段 |
| **类目特有字段进 `metadata` dict** | 规则特有字段放 `Chunk.metadata` | §二 字段表全部是 metadata 键 |
| **三钩子模板方法**：`build_chunk` / `resolve_source` / `infer_metadata` | 元数据推断在 `infer_metadata`；格式解析在 format 层（`formats/rule.py`） | format 只管产出节 dict，字段归一化在 infer_metadata |
| **字段命名风格**：snake_case、默认空串、`field(default_factory=list)` | 沿用 | — |
| **结构不变量前置**：含专项覆写的处理模块改动前不变量清单（CLAUDE.md 规则） | 规则格式簇（§三）+ component_type（§四）即不变量来源 | §四与§三 = 不变量断言清单 |

**本模块形态定位（与词条型模块的本质差异）**：规则模块 chunk 单元 = **语义节**（一节规则 1 chunk），text 是 prose 正文；词条型模块（装备/专长/法术）chunk = **条目**，字段是条目属性故提取为 metadata。规则正文中内嵌的词条块字段行（`先决条件：`/`豁免：`/`效果：`等，勘探聚合 13 种标签 138+130+100 高频）**留在 text 原文中不提取**——它们是节的内容不是节的属性；检索端「X 的豁免 DC 多少」靠字段行原文命中即可。

## 二、metadata 字段表（5 规范字段 + extra 保真，无字段体系）

设计输入：勘探 `field_labels` 全库聚合（13 种标签、286 文件；全为内嵌词条块字段，见 §一）→ **规则模块不设类目字段体系**，仅 5 个标识/来源键。

| key | 类型 | 说明 | 决策依据 |
|---|---|---|---|
| `toc_group` | str | 本模块特有分组标记，**4 枚举**：core_rules / rules / retrain / quick_reference | KN192（用户拍板，本模块特有不入骨架）；manifest 显式注解（prepare_batches.json 每文件条目带 toc_group 键，人工门固化后不再运行时推导）；归属表见 §三 3.1 |
| `source` | str | 来源书引用原文（`> 来源：` 块 / HTML 注释 / 文件级来源行，复用专长/装备模式） | 装备 2.3 先例 |
| `rule_version` | str | 版本标识（值域 = 书缩写全集，`_RULE_SOURCE_OVERRIDES` 同源；重训固定 uca） | 装备 2.3 先例 + KN194 |
| `format_cluster` | str | 格式簇名（**6 值**：s1_heading_tree / s2_bold_title / s3_bbs_star / s4_table_page / s5_prose / s6_large_aggregate） | 人工门 1 第 4 项拍板（S1~S6 画像） |
| `component_type` | str | 见 §四 枚举 | — |

**不保留 `field_status`**（与词条型模块的关键差异）：规则 prose 无字段可标三态，field_status 无对象。verify 以「**标题形态健康度**」替代（title 清洗断言：无星壳残迹/无 CR 残迹/无 BBS URL 译者行——KN159/160 防回退 + R7 异常覆盖）。

**extra 保真**：内嵌词条块字段行（先决条件/豁免/效果/价格等 13 种）**不提取进 extra**（§一 形态定位）；确需保真的低频散信息（如 BBS 帖尾注、编注行）走 text 原文，不建 schema。
