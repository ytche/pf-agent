# KN018 修复方案：显式否定字段被误判 missing（解析层编码，判定层不动）

> 关联 KN：[docs/已知问题记录.md §KN018](../已知问题记录.md)

## 1. 问题复核：影响面远超登记时的 530

KN018 原文：`_is_semantically_empty`（`processors/spell.py:35-55`）的 dict 分支 `not any(v for v in val.values())`，把 `{"applies": false}` 这类**显式否定**误判为空，约 530 个 SR chunk 的 field_status 被错标 `missing`。

2026-07-29 复测（当前 chunks.jsonl，4137 chunks），全 falsy dict 按"源文本是否含字段标签"分解：

| 字段 | 全 falsy dict | 文本无标签（真 missing） | 文本有标签·显式否定 | 文本有标签·解析失败 |
|---|---:|---:|---:|---:|
| saving_throw | 2092 | 1153 | **494**（`豁免：无/否`） | 445 |
| spell_resistance | 2829 | 1517 | **849**（`法术抗力：无/否/不可`） | 463 |
| components | 1159 | 1111 | 0 | 48 |

关键结构事实：**解析器无条件输出默认 dict**（4137/4137 全部为 dict，仅 1 个 null），因此"标签缺席"与"显式否定"在 metadata 层面是同一种全 falsy dict——

- **"有 key 即非空"的全局改法不可行**：`applies`/`type` 等 key 在默认 dict 中恒存在，全局放宽会把 3781 个真 missing 误翻 `parsed`，比现在更失真；
- **判定层按字段特判也不可行**：`_compute_field_status(metadata)` 只拿到最终 dict，无法区分"没看到这个字段"与"看到了但值是否定"。

→ 唯一干净的方向：**在解析层把显式否定编码为 truthy 值**（解析时原始字符串还在手里），`_is_semantically_empty` 与 `_compute_field_status` 完全不动。

## 2. 修复设计（用户已拍板）

**拍板结论**：标记形态 = 复用现有字段（不新增 schema key）；显式否定的 field_status = `parsed`（enum 不变，下游无感）。

### 2.1 `_parse_saving_throw`（`processors/spell.py:590`）

```python
# 修改前
result = {"type": "", "effect": "", "harmless": False}
if not value or value in ("无", "没有", "—"):
    return result

# 修改后：空值与显式否定分流——空值照旧返回全 falsy（→ missing）；
# 显式否定归一化写入 type="无"（truthy → parsed）
result = {"type": "", "effect": "", "harmless": False}
if not value:
    return result
if value.strip() in ("无", "没有", "—", "否"):
    result["type"] = "无"   # 归一化，不保留"没有"/"—"原形
    return result
```

### 2.2 `_parse_spell_resistance`（`processors/spell.py:651-673`）

显式否定分支把原始否定词写入既有 `note` 字段：

```python
# 修改前
elif keyword in ('不可', '否'):
    result["applies"] = False
elif keyword == '无':
    result["applies"] = False

# 修改后
elif keyword in ('不可', '否', '无'):
    result["applies"] = False
    result["note"] = keyword   # truthy → parsed；保留"不可/否/无"原词
```

下方的整段匹配分支（L667-673）同步处理 `clean in ("不可", "否", "无")` 时写 `note`。

### 2.3 不动的部分

- `_is_semantically_empty` / `_compute_field_status`：**不改**；
- `_parse_components`：**不改**。1159 个全 falsy components 中 1111 个源文本无"成分"标签（真 missing），48 个有标签但解析失败（保持 missing 是诚实状态，归 KN013 域）；
- `not_applicable` 保留字段集合（subschool/area/effect）：**不扩**。

### 2.4 TDD 用例（先写测试）

正用例：
- ST：`"无"`/`"没有"`/`"—"`/`"否"` → `{"type": "无", ...}`，status=`parsed`；
- SR：`"不可"` → `{"applies": False, "note": "不可"}`；`"否"` → note=`"否"`；`"无"` → note=`"无"`，status=`parsed`。

回归用例（不得改变）：
- ST：`"强韧，通过则无效"` 原样；`""`（空值）→ 全 falsy dict，status=`missing`；
- SR：`"可"` → `{"applies": True, "note": None}`；`"不可（无害）"` → harmless=True（本来就 truthy，不回归）；`""` → missing；
- components：任意输入行为完全不变。

Negative test：
- 文本无 `豁免`/`法术抗力` 标签的 chunk（如 MA 摘要、怪物志法术）：ST/SR 保持 `missing`（1153 + 1517 个）；
- 文本有标签但值非否定词且解析不出类型（如 `意志 通过则无效` 无逗号变体）：保持 `missing`（445 + 463 个，归 KN013 域，不在本 KN 修）。
