1. **TDD 测试完整性**：每个 KN 先写方案文档中列出的正/反测试用例（当前应失败），再实现；**禁止**因 bug 难修而修改或跳过既有测试——除非能论证断言本身有业务错误，且需在交付文档中说明；
2. **不做文件特判**：禁止 `if file_name == "page_1365"` / `if class_name == "X"` 式硬编码。所有解析器修复必须是信号驱动的通用逻辑（KN012 实查结论：粘连是各来源通用问题，非战役设定特有）；

4. **不改 `_is_semantically_empty` / `_compute_field_status`**（KN018 全部改动在两个 `_parse_*` 的返回值编码上）；
5. **chunk 总数轨迹**：4137 → **4134**（KN015 -3）→ **约 4198**（KN016 +64，含 4 个被静默丢弃法术）。其余 KN 均不得改变 chunk 总数。落地后若不在此轨迹上，停下来查因，不要用改测试蒙混；
6. **每个 KN 独立 git commit**（源数据批可合并为一次），commit message 标注 KN 编号，保证可单独回滚；
7. 方案文档中的代码片段是设计意图示意，行号以当前代码为准（已核实：`formats/spell.py:212` 1c½、`:1189` split、`:1296` parse_spell_level；`processors/spell.py:474` domains、`:579`/`:628` 两个 _parse、`:688` _compute_field_status）。

## 5. 各 KN 实施要点（细节以方案文档为准）

### KN012（解析器）
- registry.py 新增 `INLINE_COMPACT_ALIAS_LABELS`（从 `LABEL_ALIAS_TO_CANONICAL` 派生，长标签优先排序）与 `LEGACY_INLINE_COMPACT_STEP23_LABELS`；
- `_fix_inline_compact` **只切 Step 2/3**，Step 4（无冒号）保持原标签集——散文 `**抗力**`/`**持续**` 强调不得误拆（negative test）；
- 幂等：已在行首的标签不得重复插行。

### KN016（解析器 + 源数据 5 处）
- 8 形态簇归一化规则见方案 §3.1 表格；E/D 簇尾巴（页码/致谢）**转为标题下正文行，不删除信息**；
- 安全约束是全簇共用的：**候选标题后 1~3 非空行内必须出现 `**学派：**`/`**等级：**`**，否则不触发（防把正文法术名引用升级为标题，KN015 M-c 教训）；
- 反向故障 `spell_动物档案AArch_法术_0008` 随簇 I 痊愈，是验收抽样点。

### KN017（解析器 + 源数据 3 处）
- 1c½ 收窄：`^(\*\*.*?)/[一-鿿]{1,12}\s*$` → `^(\*\*[^*]+\([^)]+\)\*\*)/[一-鿿]{1,12}\s*$`（标题结构锚定）；
- **先写测试固定 FoP 真神祇形态**：若实际存在后缀在粗体内（`**X (Y)/神祇**`）的变体，需补一条规则，验收以 FoP 18 个 chunk 标题无 `/神祇` 残留为准；
- 无空格兜底 `^([一-鿿][一-鿿/]*?)(\d+)$` 插在标准模式之后、纯数字分支之前；
- split 丢弃告警：仅当丢弃段含 `**学派：`/`**环位：`/`**等级：` 信号才 warning，含文件名 + 段首 80 字符。

### KN013（解析器，KN012 之后）
- `_truncate_value_prose` 通用截断器 + 续行信号白名单（`+`/`(`/`（`/`和`/`或`/`，`、`、`/数字 开头行不截）；
- duration 专属：保留至 `(D)`/`（可消解）`/`（见后文）` 等标记；
- `_parse_school` 白名单前缀截断（防护/咒法/预言/惑控/塑能/幻术/死灵/变化/通用），未命中保留原文；
- M3（`等级⏎：`跨行断开）改 `_merge_bold_field_lines`；M5 给 parse_fields 边界补 `EXTRA_FORMAT_LABELS`。

### KN014（解析器，最小改动）
- `processors/spell.py:474`：`([^\s,，、]+(?:领域|子域))` → `([^\s,，、]+(?<!子)领域)`；L483 不动。

### KN018（解析器）

### KN011（后处理脚本）
