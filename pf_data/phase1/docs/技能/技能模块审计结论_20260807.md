## 三、审计发现与修复（全闭环）

### P1【严重】来源书标注系统性失实（book 557/557 全标 CRB）

**现象**：557/557 chunks 的 `book_abbreviation` 全部 = CRB。一期 Agent 溯源误导——Unchained 6 文件（226 chunks）、FAQ 837（63）、工具和技能工具包（31）、巨人猎手（5）、河域子民（3）、异能 315（10）、科技 760（5）的内容全部标成核心规则书。

**根因**：`DirectoryNameProvider` 对 `directory_hints`（含文件名的全部路径 parts）做「技能」子串匹配（`for cn_name, abbr in DIRECTORY_ABBR_MAP.items(): if cn_name in hint`）。技能模块文件名/目录含「技能」二字的文件（`工具和技能工具包.md`、Unchained 目录、根目录孤儿页）全部命中 CRB（conf=80）；page_315/760/837 走 `SkillKnownScopeProvider` 兜底（conf=60）同判 CRB。

**为什么 verify 没拦住**：检查 5 只查 `book == "?"`（未解析），不校验「解析错了」——CRB 子串误命中是有值误标，不在原检查面。

**修复**（fcc0bfc，不动公共层）：
- 公共层 `providers.py` 不可改（spell/职业冻结模块共用，KN136 共享层改动漂移教训）
- processor 侧加专属表短路：`_B2_SOURCE_OVERRIDES`（rel 前缀 → SourceResult conf=75，对齐 trait 专属表冲突覆盖模式），12 个非 CRB 文件在进入共享链前直接覆盖
- verify 新增检查 7「来源书一致性」：doc 级 book↔rule_version 匹配（非 CRB 文件 book 必须命中 `_B2_SOURCE_DOC_EXPECT` 同源表；CRB 文件 book=CRB），防回退
- 覆盖表：Unchained 6 文件 → PU 解放者手册｜Pathfinder Unchained；官方FAQ 837 → FAQ；工具和技能工具包 → AA 冒险者的军械库｜Adventurer's Armory；巨人猎手手册_新技能选项 → GIANT；河域子民PotR → PotR 河域之民｜People of the River；异能规则 315 → OCCULT；科技指南 760 → TG

**修复后终态**：CRB 214 / PU 226 / FAQ 63 / AA 31 / OCCULT 10 / GIANT 5 / TG 5 / PotR 3；confidence 75×343（专属表）+ 80×209（共享链 CRB 正确命中）+ 60×5（孤儿页兜底）。

### P2-①【一般】`_SKILL_EXEMPTIONS` endswith 子串误豁免

`rel.endswith(k)` 匹配下 `'…/工具和技能工具包.md'.endswith('工具包.md') == True` → 工具和技能工具包被误豁免，est 修正 51→31 从未生效、31 equipment 不入对账口径。改精确 basename（`rel.rsplit("/", 1)[-1] in _SKILL_EXEMPTIONS`）→ 矩阵口径 **est=382 ↔ got=560**，豁免登记 11 条精确生效。
