## B2. 元数据兜底链泛化（**已定稿 2026-08-05：方案一 + Prepare 实体枚举前置**）

现状（`processors/race.py`）：四级链 = intro 登记（`_RE_RACE_NAME_IMPURE` 纯净性过滤）> 路径归属（`_race_name_from_path`：三级目录/文件名/`_PAGE_RACE_NAME_OVERRIDES` 页号映射）> 「——」拆分 > title 兜底；例外特判（组标题/overview 行）前置不落 title。KN113/131/132 三轮 P1 都栽在实体名归一。

**定稿设计（方案一 interface-first）**：

1. `processors/base.py` 加 `entity_name_resolvers` stage 列表（首个非空生效；默认空 = title 兜底，spell/feat 行为零变化）
2. race 四个 stage 函数留在 race.py（词表/页号映射是类目知识不下沉），构造时注册；只把「有序短路 + 例外前置」执行语义上移
3. 粒度：**只抽链执行语义**，路径归属等具体实现不预置（装备=来源书章节、怪物=数据块标题行，信号形态差异大）
4. 验收：迁移后全库 3654 chunks 的 race_name 逐条 diff 零变化（全量断言，非抽样）

**Prepare 阶段预防设计（用户 2026-08-05 拍板新增）**：

实体名归一不应靠运行期兜底链独扛——**实体枚举是 Prepare 阶段就该收集的勘探资产**，race 模块缺了这一环才导致 KN116/KN132 事后补救：

1. **新 Prepare 产出物**：`entity_enum.json`（官方实体名枚举 + 别名/英文名）——从 CHM 目录（audit_chm_scope_gap 同源）+ 该模块天然权威汇总页 + 来源书清单收集，人工门确认后锁定（同 format_cluster_assign.json 的资产地位）
2. **产出即检新增检查**：归属字段值 ∉（枚举 ∪ 登记豁免白名单）→ 判伪显形——KN116「嗜火者/边栏：」、KN132「书名/条目名/X——Y」这类污染在产出当场就会被拦，而不是等人工抽查
3. **verify 常驻检查**：实体名合法率 100%（枚举 ∪ 豁免）；豁免走登记程序（先例：「年龄」章节自身、「野兽血脉」书名 intro）
4. **模板化**：装备（官方装备清单）/怪物（怪物图鉴清单）开工时在各自 Prepare 阶段建同款资产——写入开工补丁包清单（架构文档 §6.4 扩充）
5. race 模块补建：37 族汇总页基线已有，需扩为全量枚举（含怪物种族/来源书种族，65+ 值），既有 KN116/KN132 白名单并入豁免登记

## C2. audit 弃用收尾（现状核查后修订）

**现状**：`audit.py` 头部 docstring 已有完整弃用标记（「⚠️ 已弃用，仅保留代码不删除」，v2.2 评审问题 E 拍板，4 条理由）——标记存在，但有 3 处残留：

1. **`formats/base.py:28` `get_audit_rules` 仍是 @abstractmethod**——唯一消费方是已弃用的 audit 引擎，却强制每个新 format 实现死方法（feat/race 均有死实现；装备/怪物会被迫再写一次）→ base 改为可选钩子（非抽象，默认返回 {}），feat.py/race.py 死实现删除，**spell.py 冻结不动**
2. `pipeline.py:5` docstring 链仍写「→ audit（审计）」→ 删除该环节描述
3. 架构文档 §8「Tier 2 规则键法术语义」债 → 随 1/2 完成后标记关闭

关于 Python 弃用机制：PEP 702 `warnings.deprecated` 装饰器（3.13+，低版本用 `typing_extensions.deprecated`）用于 API 级弃用提示；对 audit.py 这种「从未接线、无调用方」的死代码，运行时 warning 无受众，docstring 横幅是正确粒度，**不加运行时警告**。
