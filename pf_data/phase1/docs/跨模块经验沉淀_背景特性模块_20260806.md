## 一、开工前机制（Prepare 阶段）

### 1.1 范围对账双向化——organized 整理产物是 E5 的盲区（KN148）
① **内容**：开工前清单已按 E5 硬要求做了 CHM 目录 → organized 单向对账（13 个 L2 基础页全覆盖、零缺口）——**但「背景/」目录 6 个手册文件（DH/DHH/MHH/MSH/护甲大师/巨人猎手，28 条目）不在 CHM 目录覆盖内**，是任务 #147 主动补入的。organize 整理期会新建 CHM 目录没有的整理产物目录（如「背景/」），E5 的「organized 全量并集」口径没有自动化强制。
② **落地**：范围对账双向化——CHM 目录 → organized（E5 已固化）+ **organized 全量 → CHM 目录反查**（organize 新建目录逐文件定性：纳入/索引页豁免/重复副本豁免），反查结果写入开工前清单。

### 1.2 目录驱动词表定稿——CHM L2 目录即权威词表源（R1）
① **内容**：trait_type 13 值词表 = CHM「背景特性」L1 下 13 个 L2 类型目录**一一对应**（战斗/信念/魔法/社会/派系/种族/地区/宗教/宇宙/装备/坐骑/典范/缺陷）——比「全库扫描定性」（KN100 教训）更进一步：**目录即权威词表源**，零遗漏、无需枚举。
② **落地**：新模块开工先查 CHM 目录结构是否直接构成类型维度词表（装备类型/怪物类别大概率同构）；目录驱动词表 + 全库扫描交叉验证。

## 二、实现时机制（解析器设计）

### 2.1 括号语义簇感知映射——同簇同语义，异簇异语义
① **内容**：标题内括号内容语义随格式簇漂移：`（EN）` 英文名 / `（泽弗斯）` 神名（ISG）/ `（地区）` 类型 / `（神祇，EN）` 后置神祇（page_157 宗教页唯一）/ `【地区】` 前置类型标记（秽邪勇士）——**同一条解析逻辑（括号提取）不能跨簇复用语义**。
② **落地**：簇分配表定稿时同步交付「括号语义表」（簇 → 括号内容语义 → 解析动作），作为 formats 实现的输入资产；「括号内容可能是 X/Y/Z」的模块（装备=材料/类型/重量、怪物=亚种/模板）开工前先建表。

### 2.2 字段标签八异体归一——异体→语义字段映射表
① **内容**：字段行标签 8 个异体（类型/分类/类别/背景类型/出处/要求/效果/前置条件）归一为 4 个语义字段（类型/需求/效果/出处）——`**效果：**` 缺陷页同源。
② **落地**：字段词表交付形态 = 「异体 → 语义字段」映射表（而非词表本身）；B4_field_no_colon 簇（`**分类** \n值` 无冒号字段，值下一行）与 KN149 破损字段行家族（§3.2）同属「字段行形态完整性」维度。

### 2.3 高熵文件整簇负样本——「识别不误吞」优于「解析」
① **内容**：B9_high_entropy 簇 6 个高熵文件（标题/字段六形态并存、标签分裂、星壳泄漏）不设解析目标，作为格式簇测试负样本——解析器目标「识别不误吞」而非「解析」。
② **落地**：任何模块勘探中发现「无法归簇的高熵文件」，单列负样本簇进 TDD（负例三件套的整簇升级版），禁止用正则硬啃。

### 2.4 混合页段落级类型标记——优先于整页默认（R3-B，用户拍板选项 B）
① **内容**：背景特性17 是混合页（原内容段=宇宙背景 + HH 补录段 21 条=信念/地区）。R2 整页默认会把 HH 段全部错填「宇宙」；用户拍板选项 B：`<!-- HH-source:` HTML 注释识别段边界 + 段内裸文本分类标记行（「信念背景」「地区背景」）段落级跟踪 → 段落级填充，前 3 条无标记维持空。
② **落地**：「一文件多段落异质类型」通用模式 = 段边界注释标记 + 段落级分类标记行跟踪，整页默认只作最后兜底。

### 2.5 页面级声明传播到条目级（R4）
① **内容**：page_158 页面级声明「PFS中不可使用缺陷系统」→ trait_flaw 66 条 pfs_eligible=False（页面级规则 → 条目级字段值）。
② **落地**：页面级规则发现时登记「声明 → 传播范围 → 条目级字段」三要素，避免逐条手填。

## 三、产出/修复时机制

### 3.1 形态超集 → 源数据归一化——解析器识别面不足时的首选策略（KN147）
① **内容**：条目标题 10 种失配标准形态（`**中文（English）**：`）——①无开星 ②HTML 链接残留 ③缺闭星跨行 ④中文星壳+英文无闭星 ⑤裸标题跨行 ⑥四星残留 ⑦EN 独立行 ⑧介绍段与标题同行 ⑨链接标题变体 ⑩`［地区名］`全角方括号后缀——统一源数据改写为标准形态（9 文件 33 处），**解析器零改动**。
② **落地**：形态失配的处置优先级 = ①源数据归一化（保持解析器小而稳）> ②解析器加规则（必须 TDD 全链模拟 + 全类目回归，KN112/KN136 门禁）；「十形态分类法」可作形态审计模板（全库标题候选扫描的输出格式）。

### 3.2 字段吞正文信号进产出即检——KN149 家族的发现时间压缩
① **内容**：`****需求** `（4星2星无冒号尾随空格）破损字段行 → 字段行被当作需求字段开始，**正文被吞进 requirement 字段**（text 空）；`+1 \n背景加值` 断行 → text 截断 + 断行残句成伪条目。**该家族产出即检未抓到（评估轮才暴露）**——同家族跨模块重演（专长 KN012/013、种族 KN102）。
② **落地**：产出即检「字段值健康度」加信号：字段值长度异常 / 含句号（正文信号）/ 含 `**` 残留 / 字段值 >200 字符 → 告警人工定性。修复 = 源数据规范化到可解析形态（`需求：X` 裸文本形态即可，对齐既有可解析形态，见 KN149）。

### 3.3 标题修复后必须验证正文层——KN149 是 KN147 的同族后续
① **内容**：KN147 修复 3 条缺闭星跨行标题（title 恢复、召回绿），**正文层仍被 `****需求** ` 吞进 requirement**（text 空）——质量评估轮（任务 #148）才暴露。修复链只验证了标题层/召回，未验证正文层。
② **落地**：源数据规范化修复后 checklist 加一步：「抽样断言 text 完整（首句命中源数据 + 尾句无断行残句）+ 空 text 枚举」，不能只信 title/召回绿。

### 3.4 亚产能文件 → P0 丢失优先排查入口（KN147 发现路径）
① **内容**：KN147 的 33 条 P0 丢失靠「判别器回归亚产能文件（est>got）逐文件比对 + 全库标题候选扫描」挖出——est↔got 从数量对账升级为条目级对账。
② **落地**：verify 增加「标题候选扫描」检查项（源文件标题形态全量提取 → 与 chunk title 求差集）；亚产能文件（est>got）不再只当 WARN，逐文件比对是 P0 排查的第一步。

## 四、验收/审计时机制

### 4.1 质量评估第三层质检——产出即检/verify 之外的收口检查（任务 #148）
① **内容**：全量量化 + 深度检查（空 text 枚举 / 长文本 / 重复标题（同名异文 vs 伪条目）/ 伪条目「长无括号标题」扫描）+ 随机抽样正文核对（20 条，首句命中 + 尾句无残句）——抓到 verify/产出即检漏掉的 KN149（P1 正文缺失）。
② **落地**：评估方法沉淀为通用检查清单，每模块收口时跑一遍（尤其「空 text 逐条定性」与「伪条目扫描」——都曾让 P1 溜过产出即检）。

### 4.2 闸口参数变更 = KN 一一对应登记
① **内容**：min-main-count 1000→990（KN139 伪条目剔除后真值收敛，**正当放宽**配 KN 登记）+ book '?' 门参数 201→205（KN137 参数审议，实测 203）——「只收窄不放宽」（流程教训沉淀 E1）的例外面补上登记制。
② **落地**：任何闸口参数变更（收窄或放宽）必须同 commit 登记 KN（参数 ↔ KN 一一对应），放宽时注明「正当性」理由。

### 4.3 est 是勘探时点快照——源数据修复后必须重计
① **内容**：KN146 删重复副本后矮人 est=24 未重计 → got=23 亚产能 WARN 变噪声（任务 #147 收尾重计 24→23，亚产能全库清零）。
② **落地**：源数据修复（删内容/合并条目）后，勘探 est 同步重计；est 变更记 changelog 行。

## 八、一句话总结

**trait 模块证明**：专长/种族两条沉淀链直接复用可行（同构模块零解析器返工），并新增四类可移植资产——**源数据归一化优先于解析器加规则（十形态）**、**字段吞正文信号进产出即检（跨模块三演家族）**、**目录驱动词表 + 括号语义簇感知**、**混合页段落级标记 + 页面级声明传播**；

**最贵的教训**——标题层修复后必须验证正文层（KN149 是 KN147 的同族后续，P1 后置一天），而产出即检的字段健康度检查本可以当场抓到。
