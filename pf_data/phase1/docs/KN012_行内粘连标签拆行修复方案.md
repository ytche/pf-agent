## 1. 问题重新定性

KN012 原文定义："text 明确含 `**法术抗力：** 有/可` 但 `field_status.spell_resistance != "parsed"` 的 chunk 共 395 个"。

2026-07-29 按「text 含抗力标签但 status≠parsed」全量扫描当前 chunks.jsonl（4137 chunks），实际命中 **1249 个**，分三类：

| 类别 | 数量 | 机制 | 归属 |
|---|---:|---|---|
| **D 行内粘连** | 650 | `**豁免：**…无效**法术抗力：** 有` 标签不在行首，被前字段值吞掉 | **KN012（本次修复范围）** |
| **B 行首标签+值粘正文** | 69 | `**法术抗力：** 否该法术…` 值边界不完整 | KN013 家族，不在本次范围 |
| **A 解析成功却被标 missing** | 530 | SR=无/否 → `{applies: false}` 全 falsy dict 被 `_is_semantically_empty` 误判 missing | 独立 status 语义 bug，已另立 KN018 |

**结论**：本次只修 D 类 650 个。之前「KN012≈战役设定紧凑格式」的定性不准确——战役设定 page_1019/1331 只占 11 个命中，主体是各来源通用的 bold 标签行内粘连（page_1365 276、page_1363 88、Spell UI 31、page_1169 18、page_669 16、page_1219 13 等）。修复必须是**信号驱动的通用逻辑，不做文件特判**。

## 2. 根因链（已逐行核实）

```
源文本:  **豁免：** 强韧，通过则无效**抗力**：有
                                  ↑ 别名标签，行内粘连

① _fix_inline_compact (formats/spell.py:817) Step 2/3/4 拆行
   标签集 = LEGACY_INLINE_COMPACT_LABELS (registry.py:176)
        = LEGACY_13 + 诡计描述/伪装对象
   → 不含 抗力/施放时间/持续/SR 别名 → 粘连处不插换行

② _unify_field_labels (formats/spell.py:1064) B2 规则
   **抗力**：有 → **法术抗力：** 有   ← 只原地改名，仍不插换行
   （F2-inline 规则只覆盖 裸 标签，不覆盖 bold 标签）

③ parse_fields (processors/spell.py:105) 值边界
   只认 \n\n 和 \n**标签**
   → **豁免** 的值吞掉粘连的 **法术抗力：** 有
   → finditer 从被吞区域之后继续，SR 标签永远成不了匹配起点
   → spell_resistance 静默丢失
```

## 3. 修复设计（方案一：扩展标签集）

### 3.1 核心改动

在 `vectorizer/registry.py` 新增一组标签，并把 `_fix_inline_compact` 的 Step 2/3 切换到扩展集：

```python
# registry.py
# bold 别名标签（施放时间/持续/抗力/SR），仅用于 _fix_inline_compact Step 2/3。
# 从 LABEL_ALIAS_TO_CANONICAL 派生，不在 formats 层维护字面列表。
INLINE_COMPACT_ALIAS_LABELS: list[str] = sorted(
    LABEL_ALIAS_TO_CANONICAL.keys(),   # 施放时间/持续/抗力/SR
    key=lambda x: (-len(x), x),
)
LEGACY_INLINE_COMPACT_STEP23_LABELS: list[str] = (
    LEGACY_INLINE_COMPACT_LABELS + INLINE_COMPACT_ALIAS_LABELS
)
```

`formats/spell.py::_fix_inline_compact`：
- **Step 2**（`**field**：` 冒号在粗体外）和 **Step 3**（`**field：**` 冒号在粗体内）：`field_pat` 改用扩展集 → `值**抗力**：有` 拆为 `值\n**抗力**：有`；
- **Step 4**（无冒号 `**field**`）：**保持原规范标签集不变** —— 避免散文中 `**抗力**`、`**持续**` 这类术语强调被误拆行（KN012 实样全部带冒号，Step 2/3 已够）；
- Step 0/0b~0f/1 等其他步骤是否用扩展集：实现时统一评估，默认跟随 Step 2/3（标题旁的别名标签同样该拆）。

拆行发生在别名归一化**之前**，后续 `_unify_field_labels` B2 照常把 `**抗力**：` 改名为 `**法术抗力：**`，`parse_fields` 按 `\n**法术抗力：**` 边界正常抽取。链路无新环节。

### 3.2 别名误匹配安全性（已分析）

| 担心 | 结论 |
|---|---|
| `抗力` 子串误中 `**法术抗力：**` | 安全。正则要求 `**` 紧邻标签，`**法术抗力：**` 中 `抗力` 前是 `法术` 不是 `**`，锚定位置不匹配 |
| `持续` 子串误中 `**持续时间：**` | 安全。同理，`持续` 后是 `时间` 不是 `**`/`：`；且扩展集按长标签优先排序 |
| 散文中 `**抗力**` 强调被拆行 | 通过「Step 4 不扩展」规避 |
| 其他步骤（Step 0 系列）引入标题误拆 | 标题模式要求 `**中文 (English)**` 结构，别名只影响字段侧 lookahead，风险低；实现时用测试覆盖 |

### 3.3 为什么不选其他方案

- **方案二**（`_unify_field_labels` 加 bold 版 F2-inline）：把粘连边界逻辑拆到两个归一化阶段，与现有 F2-inline 裸标签规则重复；
- **方案三**（`parse_fields` 边界认行内 `**标签`）：字段值内的合法 bold 会被误截断，风险不可控。

## 4. 结构不变量（改 `spell.py` 归一化前必须明确）

1. **chunk 边界不变**：只在字段值内部插换行，不触碰 `split_into_items` 的标题识别（Step 2/3 模式不匹配标题行）→ chunk_id 集合不变；
2. **既有 parsed 字段不回归**：已正确拆行的文本（标签已在行首）幂等——`(?<!\n)` 类约束或正则锚定保证不重复插行；
3. **negative test**：散文中 `**抗力**`（无冒号）、`**持续**` 强调不得被拆行；
4. **别名归一化顺序**：`_fix_inline_compact` 仍在 `_unify_field_labels` 之前执行，改名行为不变。

每条不变量在 `vectorizer/tests/` 中对应断言。
