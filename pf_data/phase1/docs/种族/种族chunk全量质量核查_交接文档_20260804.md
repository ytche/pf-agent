## 三、抽查判断 case（全量核查方法）

本次抽查对每族检查 4 项：**基本描述 / 种族特性 / 亚种 / 替换特性**，外加元数据与内容污染。全量核查（约 65 个 race_name，先剔除 KN116 点名的 3 个坏 race_name）按以下 case 逐族过：

### case 1 — 基本描述（race_intro / race_overview）

- race_intro 存在且 text 为该种族的描述性文字（不是字段表、不是别的条目粘连）
- race_overview（page_10/11/12 汇总页 chunk）的属性行（属性调整/生物类型/体型/速度/感官/语言）完整，与详情页一致
- 反例：人鱼 intro 粘连属性行、属性调整未独立成 trait；灵猴族 overview 速度「攀爬30尺」与详情页矛盾（KN117）

### case 2 — 种族特性（race_trait）

- 对照该族详情页源文档，标准种族特性逐条核对：**名称齐、数值对、text 完整不截断**
- 数值类断言必须回源文档核对（page_*.md），再与官方口径比对——**chunk 与源文档一致但源文档错**的，归源数据问题（KN117 先例），不算解析 bug
- 反例：娜迦裔催眠凝视正文截断/规则错误；矮人 11/11 全对（正例）

### case 3 — 亚种 / 血统变体

- 官方有亚种/血统变体的族（神裔、魔裔、元素裔等），检查亚种内容是否有 chunk
- 缺失时先走 KN118 流程：核对 CHM 目录与输入范围，区分「输入缺口」vs「解析丢失」vs「源文档本身没有」
- 反例：神裔 Agathion/Angel/Archon 血统变体 0 chunk（KN118）

### case 4 — 替换特性（alt_trait）

- 对照源文档「替换种族特性/种族特性替换」章节，逐条核对：条目齐、replaces 字段正确、**边界不粘**
- 粘连高发位：PFS 禁用说明 follow-on 段落（「精类思维/幽暗居民/暗影猎手/实用/危机感应/形影不离」）粘进前一条目（KN114）；整段未切出（KN115 BotB）
- replaces 错解析反例：半身人「昏暗精准」「精类魔法」replaces 被解析成矮人的特性名

### case 5 — 元数据

- race_name 必须是种族名——「年龄」（KN113 实锤 70 个）、「嗜火者」「兽态人Skinwalker种族特性」「边栏：非人类魔裔」（KN116）均为坏值
- component_type 与内容匹配：物品≠race_feat、ISR 条目≠race_trait、种族描述≠alt_trait（KN116/KN115 实例）
- 别名/title 无 `**` 残留（娜迦裔、半身人反例）

### case 6 — 内容污染

- 译者吐槽/译注（KN119，4 族已点名，【好贵！！】等）
- 字段名伪条目：「频率/效果/治愈/条件/价格调整/通常情况/强韧豁免」——KN100 已修一批，抽查仍见残留（树蛙人/土元素裔/灵猴族/矮人），需确认是词表缺口还是新切出路径
- `[[fc:whitespace]]` 等处理标记泄漏进 text（矮人 4 处）

从有 race_intro 的 65 个 race_name 以 seed 20260804 随机抽 10 个，剔除非种族名后替补。命中：树蛙人、土元素裔、矮人、神裔、灵猴族、娜迦裔、人鱼、大地精、嗜火者、半身人。
