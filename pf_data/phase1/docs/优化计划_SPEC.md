# 术语提取报告优化计划

## 目标
将 `pf_data/phase1/术语提取报告_分类版.md` 从当前粗糙版本升级为高质量、可维护的 PF 1e 中英术语对照表。

---

## 阶段一：数据清洗（Phase 1 - Cleanup）

### 1.1 修复"推荐翻译"字段污染
**问题**：大量"推荐翻译"列混入上下文描述句子，而非纯译名。

**典型污染模式**：
- "该能力改变了..." / "该能力取代了..." / "该能力调整了..."
- "就如同..." / "如同..." / "和..."
- 带括号的引用片段如 "(4)" / "(2)"
- 完整句子而非名词短语

**处理规则**：
1. 提取核心译名（去掉能力描述前缀）
2. 保留纯译名，去掉上下文
3. 如果推荐翻译为空或无效，从"其他翻译"中找最短的纯译名作为候选
4. 人工复核边界案例（如 `Arcane Bond` 到底译"奥术联结"还是"魔宠联结"）

**输出**：`术语提取报告_清洗版.md`（中间产物，不对外）

---

### 1.2 拆分"其他"分类
**问题**："其他"分类包含 780 个术语，占总数 ~75%，失去分类意义。

**新增分类**：

| 新分类 | 识别规则 | 示例 |
|--------|---------|------|
| **技能 (Skills)** | 含 Skill/检定/知识/察觉/潜行等 | Perception, Stealth, Knowledge |
| **装备/物品 (Equipment)** | 含武器/防具/药水/卷轴/工具等 | Longsword, Chain Mail, Potion |
| **怪物/生物 (Creatures)** | 含动物/异界生物/不死生物等 | Goblin, Skeleton, Demon |
| **动作/战技 (Combat)** | 含攻击/防御/移动/擒抱等 | Full Attack, Charge, Grapple |
| **状态/条件 (Conditions)** | 含目眩/眩晕/恐慌/无力等 | Blinded, Stunned, Shaken |
| **位面/环境 (Planes)** | 已有"位面"分类，但需扩充 | 合并现有位面分类 |
| **组织/势力 (Factions)** | 含公会/教团/国家等 | Pathfinder Society, Cheliax |
| **地名 (Locations)** | 已有"地域"分类，需扩充 | 合并现有地域分类 |

**分类优先级**：
- 先处理出现次数 >10 的高频术语
- 低频术语（<5次）可暂留"其他"或单独"杂项"分类

**输出**：`术语提取报告_重分类版.md`

---

### 1.3 修正错位分类
**问题**：部分术语分类明显错误。

**已知错位**：
- `Shield Other` → 从"种族"移到"法术"
- `Detect Evil` / `Smite Evil` → 从"状态"移到"职业/法术"
- `Craft Wondrous Item` → 从"制造"移到"专长"（或保留"制造"但提升为一级分类）
- `Dimension Door` → 从"其他"移到"法术"
- `Spring Attack` / `Whirlwind Attack` → 从"规则概念"移到"专长"
- `Fast Movement` → 从"规则概念"移到"职业"

**处理**：基于英文术语名和上下文自动判断，人工确认边界案例。

---

## 阶段二：格式优化（Phase 2 - Format）

### 2.1 清理"其他翻译"列
**问题**：当前"其他翻译"列包含大量上下文例句，而非不同译名。

**处理规则**：
1. 去掉带数字括号的引用片段（如"(4)"、"(2)"）
2. 去掉完整句子，只保留**不同的译名变体**
3. 如果"其他翻译"和"推荐翻译"相同，清空"其他翻译"
4. 例句可单独生成一个"例句参考"文件，不放在主表中

**输出**：精简版主表 + 独立的 `术语例句参考.md`

---

### 2.2 缩写/标注附录
**问题**：`Sp`, `Su`, `Ex` 等缩写出现次数为 0，但很有用。

**处理**：
- 新建 `PF_缩写表.md` 附录文件
- 包含：法术成分（V/S/M/DF）、能力类型（Sp/Su/Ex）、动作类型（SA/MA/FA）等

---

### 2.3 添加元数据列
**建议新增列**：
- **来源**：CRB/APG/UC/UM 等（如果能从文件名推断）
- **类型**：法术/专长/物品/职业 等（与分类一致）
- **备注**：常见误译、推荐使用场景、特殊说明

---

## 阶段三：质量验证（Phase 3 - Verify）

### 3.1 自动化检查
- 检查"推荐翻译"是否包含句子（以"该"、"就"、"和"开头）
- 检查"推荐翻译"是否包含括号数字
- 检查同一英文术语是否出现在多个分类中
- 统计各分类术语数量，确保"其他" < 20%

### 3.2 人工抽查
- 抽查高频术语（出现次数 >50）的翻译质量
- 抽查新增分类的代表性术语
- 确认边界案例（如 `Arcane Bond` 的准确译名）

## 回滚策略

- 每个阶段完成后 git commit
- 阶段产物用 `_v1`, `_v2` 等后缀标记
- 最终版本用 `术语提取报告_优化版.md`（无版本号）
- 如果某阶段结果不满意，可 `git checkout` 回退到上一阶段
