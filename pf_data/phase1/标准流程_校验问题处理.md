# 标准流程：校验问题处理

> 适用范围：`pf_data/phase1/` 下所有规则书向量化输出（`chunks.jsonl`、`class_archetype_index.json` 等）的校验。
> 目标：把“发现问题 → 记录 → 排查根因 → 横向排查 → 修复 → 验证 → 关闭”固化为可复现流程，避免只修个案、遗漏同类问题。

---

## 1. 流程总览

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  1. 发现问题    │────▶│  2. 记录问题    │────▶│  3. 排查根因    │
│  (验收/抽样)    │     │  (校验问题记录) │     │  (代码+数据)    │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                                                        │
                                                        ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  6. 关闭问题    │◀────│  5. 修复并验证  │◀────│  4. 横向排查    │
│  (归档+复盘)    │     │  (代码/数据)    │     │  (其他职业)     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

## 2. 每一步的标准动作

### 2.1 发现问题

#### 触发来源

1. **自动化验收脚本失败**：`verify_all_classes.py`、`verify_class_attribution.py`、`verify_paladin_archetypes.py` 等报错。
2. **人工抽样检查**：
   - 查看某个职业的 `class_archetype` 列表时，发现明显不是变体的条目。
   - 查看 `class_feature` 时，发现关键能力缺失或归属错误。
3. **数量异常**：
   - 某职业变体数相比基线突然增加/减少超过 5%。
   - 总 chunk 数异常波动。
4. **negative test 失败**：新增断言“某类条目不应以某 component_type 出现”后失败。

#### 即时记录

发现问题后，立即在 `pf_data/phase1/校验问题记录.md` 中新建条目，不要等排查完再写。记录内容至少包括：

- 发现时间
- 问题标题
- 问题归类（规则识别 / 来源标注 / 数据格式 / 归属错误 / 其他）
- 严重程度（阻塞 / 需要人工校验 / 轻微）
- 发现人 / 触发方式
- 初步现象（具体条目、职业、源文件）

### 2.3 排查根因

按以下顺序排查，避免只看表象：

1. **源数据层面**
   - 打开对应源文件，查看原始 Markdown 格式。
   - 确认是格式问题（如 `**标题：**`、缺少 `##`、多余 `**`）还是内容组织问题（如非变体章节混在变体文件里）。

2. **标题提升链路**
   - 在 `vectorization_prep_profession.py` 的 `clean_file()` 中，依次检查：
     - `_merge_unclosed_bold_spans`
     - `merge_line_breaks`
     - `promote_image_prefixed_headings`
     - `promote_bold_headings`
     - `promote_leading_bold_headings`
     - `promote_inline_ability_headings`
     - `promote_inline_archetype_headings`
   - 确认哪一步把正文/能力名错误提升为 heading。

3. **分类逻辑**
   - 检查 `looks_like_archetype_title()`、`classify_component()`、`infer_class_name()`、`extract_archetype_info()`。
   - 确认弱规则是否被误触发。

4. **来源推断**
   - 如果问题涉及来源书错标，检查 `resolve_source()` / `detect_book()` / `SourceProvider` 链路。

5. **Processor 专项覆写**
   - 如果涉及 `WitchProcessor`、`PaladinProcessor` 等子类，检查是否过度特化或遗漏。

排查时，用最小脚本复现问题：

```python
import json

def find_chunk(class_name, title_keyword, component_type='class_archetype'):
    for line in open('vectorization_prep_profession/chunks.jsonl', encoding='utf-8'):
        c = json.loads(line)
        if c.get('class_name') == class_name and c.get('component_type') == component_type and title_keyword in c.get('title', ''):
            return c
    return None

c = find_chunk('女巫', '寒冬')
print(c['title'], c['doc_id'], c['text'][:200])
```

### 2.4 横向排查：其他职业是否有共性问题

根因明确后，必须按模式横向扫描，不能止于个案。

#### 4.1 提取模式特征

把根因抽象为正则或规则，例如：

- 标题以 `中文（English）：` 形式结尾。
- 标题含 `阵营/本职技能/语言/法术` 等通用字段且被标为 `class_archetype`。
- 标题是“季节/自然主题”且出现在女巫变体文件中。

#### 4.2 全量扫描脚本模板

```python
import json
import re
from collections import defaultdict

chunks = [json.loads(l) for l in open('vectorization_prep_profession/chunks.jsonl', encoding='utf-8')]

# 示例：扫描所有 class_archetype 中标题以冒号结尾的条目
pattern = re.compile(r'[（(][A-Za-z][^）)]*[）)]\s*[：:]')

grouped = defaultdict(list)
for c in chunks:
    if c.get('component_type') == 'class_archetype' and pattern.search(c.get('title', '')):
        grouped[c.get('class_name', '?')].append((c['title'], c['doc_id'], c['char_count']))

for cls in sorted(grouped):
    print(f'\n## {cls}（{len(grouped[cls])} 条）')
    for title, doc_id, cc in grouped[cls]:
        print(f'- `{title}` | `{doc_id}` | {cc} 字')
```

#### 4.3 记录横向排查结果

把扫描结果写入 `校验问题记录.md` 的“受影响条目”和“共性问题模式”章节，格式：

```markdown
### 3. 受影响条目

- 女巫：15 条（`page_70.md`、`全变体未整合.md`、`幽暗地域英雄HotD_女巫变体.md`）
- 猎人：14 条（`page_104.md`）
- 武僧：9 条（`page_52.md`、`page_55.md`）
- ...

### 4. 共性问题模式

| 模式 | 示例 | 本质 |
|---|---|---|
| 能力名（English）： | `寒霜炸弹（Frost Bomb，Su）：` | 变体下的 class_feature |
```

#### 4.4 判断是否属于同一根因

如果扫描结果都命中同一模式（如“标题以冒号结尾 + 在变体文件里”），则合并为同一个 issue 处理；
如果命中不同模式，应拆分为多个 issue，分别跟踪。

---

### 2.5 修复并验证

#### 修复原则

1. **优先改脚本，次选改源数据**：
   - 如果问题是通用模式，修复 `vectorization_prep_profession.py` 的规则。
   - 只有在源数据格式确实错误（如多余 `**`、标题行缺少 `##`）时才改源文件。

2. **不改基线文件**：
   - 不得修改 `术语提取报告_分类版.md` 等基线文件。

3. **最小改动**：
   - 不要为了增加一个特例而引入大量硬编码。
   - 优先利用现有扩展点（`Processor` 子类、`EXPAND_STRATEGIES`、注册表等）。

4. **不变量清单**：
   - 修改前列出本次改动涉及的结构不变量（heading 层级、chunk 边界、归属、来源书、变体数等）。
   - 新增或更新 `verify_*.py` 断言。

#### 验证步骤

1. 运行主脚本：
   ```bash
   cd /Users/chezi/code/java/pf_agent/pf_data/phase1
   python3 vectorization_prep_profession.py
   ```
2. 运行所有验收脚本：
   ```bash

   python3 verify_class_attribution.py
   python3 verify_paladin_archetypes.py
   python3 verify_heading_levels.py
   ```
3. 运行针对本问题的 negative test：
   ```python
   # 例如断言不再出现误识别的 64 条标题
   ```
4. 抽样确认真实变体没有受损。
5. 记录修复前后数量对比。

### 2.6 关闭问题

满足以下条件后，把状态改为 **已关闭**：

- [ ] 根因已定位并记录。
- [ ] 横向排查已完成，同类问题已修复或单独建 issue。
- [ ] 修复已提交 Git。
- [ ] 所有验收脚本通过。
- [ ] 新增/更新 negative test 并通过。
- [ ] `校验问题记录.md` 已补充修复实现和验证结果。

关闭时添加复盘：

```markdown
### 10. 复盘
- 为什么之前的验收没发现？
- 以后如何避免同类问题？
- 是否需要更新 CLAUDE.md 或其他规范？
```

## 5. 应用示例：V001 误识别变体

   - 增加通用能力字段黑名单。
   - 为女巫庇护主主题识别 `feature_subtype='patron'`。
6. **待验证**：新增 negative test，确保上述 64 条不再出现。
