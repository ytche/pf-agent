# 法术模块源文件规范化建议

> 基于 149 个文件的逐文件勘探结果整理。
>
> 分类原则：**格式缺陷** = 源文件本身格式需要改动才能被解析器统一处理；
> **非条目陷阱** = 文件中混入的不应被当作法术条目的内容，需解析器识别过滤或预处理剥离。

---

## 第一部分：格式缺陷源文件

## 第三部分：推荐处理策略

### 策略 A：统一源文件格式（推荐）

对所有源文件进行预处理清洗：
1. **标题统一**：所有条目格式化为 `**中文名（English）**`
2. **字段展开**：所有字段改为逐行 `**字段名：**` + `值` 格式
3. **英文名合并**：跨行英文名合并为一行
4. **剥离非条目内容**：前言、边栏、表格等移出或标记
5. **剥离附加标记**：`![[图片]]`、`◎`、`~~删除线~~`、`[种族]` 等
6. **统一字段名**：`环位→等级`、`距离→范围`、`抗力→法术抗力` 等
7. **分段文件**：`page_1365.md` 按书拆分子文件；`Spell CRB.md` 重建为标准格式

### 策略 B：解析器自适应处理

若不动源文件，解析器需处理的复杂性：

1. **多格式检测**：先检测文件属于哪种格式簇（管道表格 / 内联 / 分行 / 混合）
2. **前言剥离**：检测第一个正式法术标题前的所有内容跳过
3. **分组标题识别**：全大写魔法名/种族+法术/章节标头等模式排除
4. **字段名映射**：维护所有变体字段名到标准字段名的映射表
5. **阶梯法术合并**：I/II/III/IV 系列在索引中标注为同一家族

### 源文件修改与解析器处理的权衡

| 方案 | 优点 | 缺点 |
|------|------|------|
| **改源文件** | 一次清理，所有下游受益；格式统一后解析器简单 | 修改 149 个文件工作量大；需维护基线不变 |
| **解析器自适应** | 源文件不变（不可修改的基线）；逐步提升解析能力 | 解析器极复杂；每种变体都要特殊处理；对混合格式文件需顺序切换 |
| **混合方案**（推荐） | 修复 P0 缺陷（跨行/格式混用/内联展开），解析器处理 P1/P2 变体 | 工作量适中；解析器仍保留一定自适应能力 |

**建议以混合方案实施**：先批量修复最高频的格式缺陷（英文名跨行合并、字段换行展开、剥离图片标记和译注符号），再由解析器处理非标准字段名映射和分组标题识别。
