## 一、归因修正（k3 实测复核，补充/纠正 T4 报告）

复核了 4 题的完整 `tool_calls.jsonl`（约 230 次工具调用）+ 锚点 chunk 原文 + `FilterTranslator`/`SearchService` 源码，发现 T4 报告的归因**不完整**——真正的统一根因是**检索层工具能力缺口**，不是单纯的 embedding 语义弱：

### 根因 1：`searchByMetadata` 的 title 过滤只有 spell 模块支持（主根因）

`FilterTranslator.java:28-35`：spell 可用字段含 `title`；class 无 title；**六个标准模块（feat/race/trait/equipment/skill/rule）只暴露 `book` + `componentType`**。

工具调用日志实锤——LLM **已经知道答案的确切名字**并反复尝试按名过滤，全部被工具拒绝（返回字段清单）：

| 题 | LLM 实际调用 | 结果 |
|---|---|---|
| easy-22 | `searchByMetadata(rule, {title:'叠加'})`、`{title:'叠加（Stacking）'}` | ❌ rule 不支持 title |
| medium-4 | `searchByMetadata(equipment, {title:'法力再生珍珠'})` | ❌ equipment 不支持 title |
| medium-21 | `searchByMetadata(spell, {title:'防护邪恶'})` | spell 支持，但当轮未进最终 sources（待验证，见 §四 T3） |
| medium-25 | `searchByMetadata(feat, {title:'精通擒抱'})`、`{title:'高等擒抱'}`、`{title:'战技专攻'}` 等 | ❌ feat 不支持 title |

### 根因 2：title 不参与 embedding，vectorSearch 对「已知确切条目名」的查询反而低效

`StandardChunkMapper` 的 `Document.text` 只含 chunk 正文，**title 只进 metadata 不进向量**。例：medium-4 锚点 `equipment_page_234_0179`（法力再生珍珠，173 字符），正文以「光泽与大小和一般珍珠无异…」开头——**通篇没有「法力再生珍珠」六个字**。LLM 用 `vectorSearch("法力再生珍珠 pearl of power 恢复已准备已施展法术 命令字")` 精确点名，该 chunk 余弦仅 0.5773 且排在 top15 候选之外。

### 根因 3（次要）：topK 截断发生在重排之前

`SearchService.search()` 先 `similaritySearch(topK=15)` 再 `rankedScore` 重排——候选集只有 15 条，锚点若原始余弦排 16 名外，任何排序加权都救不到。easy-22 锚点 `rule_page_127_0028`（142 字符短文本）即此类。

### 对 T4 归因表的修正

- ~~「LLM 引用波动」~~（medium-21 CRB_0421「复刻 top3 但 LLM 未引用」）：复刻用的是原始问题做检索词；实际运行中 LLM 的检索词不同，**0421 根本没进当轮 sources**（实测 sources 列表确认）。属检索词/召回问题，非引用波动。
- ~~「短文本 embedding 弱」~~：是表象不是根因——LLM 多次用确切名称检索仍失败，因为名字不在向量里、title 过滤又不支持。

## 二、修法设计（两个 Java 侧改动，互补）

### 修法 A：`searchByMetadata` title 过滤全模块开放【主力，确定性最强】

**改动**（全部在现有扩展点内，无新流程）：

1. `FilterTranslator.translateStandard()`：`case "title" -> "title"` 补进映射；
2. `FilterTranslator.availableFields()`：六个标准模块可用字段加 `title`；class 模块加 `title`（`ClassChunkMapper:30` 确认 class metadata 有 title 键）；
3. `RetrievalTools.searchByMetadata` 工具描述：「其余模块可用字段」补 `title(条目名，精确匹配)`，并加示例「按名查专长 → {module:"feat", filters:{title:"精通擒抱"}}」。

**匹配语义**：沿用现有 `eq` 精确匹配（`SearchService.java:149-155` 不变）。LLM 已表现出「短名被拒→换全名重试」的行为（easy-22 试过 `叠加` 和 `叠加（Stacking）` 两种写法），精确匹配 + 工具描述示例足够。

**风险**：极低。新增字段映射不影响既有字段行为；`title` 键在八模块 metadata 均已存在（StandardChunkMapper / ClassChunkMapper / SpellChunkMapper 三处确认）。

**测试**（TDD）：
- `FilterTranslatorTest`：六个标准模块 + class 的 `title` 翻译、availableFields 清单；
- `SearchServiceTest` 或 `RetrievalToolsTest`：`searchByMetadata(feat, {title:'精通擒抱'})` 不再返回字段错误提示。

### 修法 B：vectorSearch 候选扩容 + title 命中加权【辅助，覆盖模糊点名】

**B1 候选扩容**（对治根因 3）：`SearchService.search()` 的 `SearchRequest.topK` 从 `topK`（15）扩为 `topK + rerankExtraCandidates`（新增配置 `pf.search.rerank-extra-candidates`，默认 **10**），重排后仍 `.limit(topK)`。与既有 `class-extra-candidates` 模式一致，推广为全模块。

**B2 title 命中加权**（对治根因 2）：`rankedScore()` 增加一项——检索词中的词元命中 chunk 的 `title` 或 `aliases` metadata 时加分（新增配置 `pf.search.title-match-boost`，默认 **+0.05**，置 0 关闭）：

- **词元抽取**：检索 query 按空白/标点切分；CJK 连续串长度 ≥2、ASCII 词长度 ≥2（小写化）入选；
- **匹配**：词元为 title/aliases 的子串即命中（双向只需此一向，实测 4 题全部覆盖：`法力再生珍珠`⊆title、`叠加`/`Stacking`⊆title、`精通擒抱`⊆title、`CMB`⊆title）；
- **一次命中只加一次分**（不按词元数累加，防止长 query 刷分）；
- **停用词表**（配置 `pf.search.title-boost-stopwords`，默认：`法术,规则,专长,效果,职业,装备,物品,魔法,如何,什么,哪些,途径,方法,of,the,and,to,in`）防止泛词大面积误加权。

**风险**：中低。加权只影响排序不影响召回；幅度 0.05 约为相邻 chunk 语义差（实测 medium-7 邻居差 0.042）的量级，能把「被点名的确切条目」抬过「语义相近邻居」，但不足以让不相关 chunk 凭空进 top15。配置置 0 即完全回退。

**测试**（TDD，`SearchServiceTest`）：
- title 命中词元的 chunk 以 0.05 幅度压过略高余弦的邻居；
- 命中 aliases 同样加分；停用词不加分；boost=0 时行为同现状；
- B1：requestTopK = topK + rerankExtraCandidates 传入 `SearchRequest`（captor 断言），最终返回仍 limit(topK)。

### 两修法对 4 题的预期覆盖

| 题 | 修法 A（title 过滤） | 修法 B（扩容+加权） | 预期 |
|---|---|---|---|
| easy-22 叠加 | rule title 过滤放开，LLM 已会重试 `叠加（Stacking）` 全名 | `叠加`/`Stacking` 词元命中 title | ✅ 双保险 |
| medium-4 法力再生珍珠 | equipment title 精确命中（title 干净无括号） | 词元 `法力再生珍珠` 命中 title | ✅ 双保险 |
| medium-21 防护邪恶/心灵屏障/仿生人 | spell title 已支持（需 T3 验证链路）；LLM 多轮 query 点名 `防护邪恶`/`心灵屏障` | 同名词元加权 | ✅ 任一锚点命中即得分（score_citation 任一命中=1） |
| medium-25 精通擒抱/CMB 公式 | feat title 精确命中 `精通擒抱` | `精通擒抱`/`CMB`/`战技加值` 词元命中 | ✅ 大概率恢复（3 锚点任一即可） |
