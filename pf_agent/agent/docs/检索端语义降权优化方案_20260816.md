## 一、背景与目标

8 模块向量检索链：`RetrievalTools.vectorSearch → SearchService.search(question, module)` → 各 `SimpleVectorStore` 召回 → 合并按相似度降序取 topK。当前**纯相似度排序**，唯一例外是 v1.8 的 class 基础职业页加分（`boostedScore`，AKN-003 方案 B）。

目标：对**低信息量 / 无效 chunk** 做检索端语义降权，避免噪声挤占有效结果，提升一期规则问答的溯源正确性与回答质量。约束：

- **不动数据侧、不重建向量库**（spell/class 冻结，KN136 禁令；其他模块重建成本高且数据侧既有口径已登记）。
- **优先复用既有扩展点**（`boostedScore` 先例），不在通用流程硬编码模块特判。
- **降权只影响排序，不影响召回**——被降权 chunk 仍在候选集（LLM 仍可读到），只是不再挤占 topK 靠前位置；幅度保守，可配置可回滚。

## 三、降权项与处理方案

### 项 1：空 text 过滤（P1，效果最直接）

- **问题**：`ChunkImporter` 不过滤空 text，`StandardChunkMapper` 把空 text 映射为 `""` 进库 → 空 embedding，检索时可能误召回、LLM 读到无内容片段。
- **量级**：equipment 113 + feat 51 + skill 7 + trait 1 + rule 1 = **173**。
- **方案**：`SearchService.search()` 排序前**剔除**空 text Document（`doc.getText().isBlank()`）。空 text 无信息量，剔除（而非降权）合理。
- **风险**：极低。不影响任何可支撑回答的 chunk。
- **验证**：SearchServiceTest 断言空 text chunk 不进结果；评测集溯源维度不回归。

### 项 2：intro/reference 类降权（P1，核心项）

- **问题**：`feat_intro`（「战斗专长」）/`rule_intro`/`rule_reference` 等泛化/章节标题 chunk 与具体条目竞争 topK，检索具体问题（如「猛力攻击先决条件」）时噪声占位。
- **方案**：对称实现 class 基础页加分 → `_intro`/`_reference` 结尾的 `component_type` 排序**减分** `pf.search.intro-penalty`（默认 0.03）。仅排序，不改 `Document.score`。参考 `boostedScore` 同一机制，集中到一个 `rankedScore()` 方法。
- **边界决策（待拍板 ⭐）**：`_overview` 是否一并降权？
  - class_overview 715 个最大量，但含「职业变体」「本职技能」等**目录级总览**，部分问题（如「有哪些职业变体」）可能真的需要——误降风险存在。
  - race_overview 111 个是「矮人/精灵/侏儒」等**种族概述**，问「矮人特性」时有一定价值。
  - **建议**：第一批**只降 `_intro`/`_reference`**（明确低信息量），`_overview` 单独观察（第二批评估）。理由：intro/reference 是「引子/目录引导」，overview 是「内容总览」，信息量级不同。
- **风险**：降权只影响排序不影响召回，且幅度 0.03 保守；LLM 仍可读到被降权 chunk。验证阶段若发现典型问法受损（如问章节总览类问题），可调低或关闭（配置为 0 即回退）。
- **验证**：真实 bge-m3 复现「猛力攻击先决条件」「火球术射程」，对比降权前后 top5 构成。

### 项 3：oversize 超长 chunk 降权（P1/P2）

- **问题**：超长 chunk embedding 语义稀释，检索召回易跑偏；工具返回已截断 1500（`vector-result-chars`），但排序阶段整块参与竞争。
- **量级**：equipment 21（max 17532）+ class 15 + rule 7 + spell 2 + feat(skill/race) 各 1 ≈ **48**。
- **方案**：text 长度 > `pf.search.oversize-threshold`（默认 5000）排序减分 `pf.search.oversize-penalty`（默认 0.02）。数据侧拆 chunk 方案放弃（spell/class 冻结，不可重跑）。
- **风险**：spell「法术索引表」43085 字符——若用户问「法术都来自哪些书」这类列举，走 `searchByMetadata` 不走 vectorSearch，无影响；向量检索场景下超长 chunk 反而低效。可接受。
- **验证**：同项 2，评估典型问法 top5 是否还混入 spell_index。

### 项 4：book '?' 口径（P2，登记不处理）

- **问题**：race 2483 / rule 188 / trait 99 / feat 100 / spell 13 来源不可回溯，前端显示「未知来源」。
- **判断**：**不是检索降权问题**，是数据侧口径（KN106/111/137 已登记，设计保留）。检索影响仅两点：
  - `searchByMetadata` 按 book 过滤时 '?' 不等于任何书缩写，**不会误匹配**（安全）；
  - 前端来源展示为「未知来源」。
- **方案**：本批次**不处理**（数据侧修复另立任务，遵循 KN106/111 口径）。仅在工具描述或文档中登记。若联调发现 book 过滤误伤再评估。
- **遗留**：数据侧 race 来源归位 2483 条是独立大任务，不属 Agent 检索层。

### 项 5：表格结构化 KN221（P3，登记不处理）

- **问题**：rule_table 331 个 + 大量纯文本表格 chunk（rule 1299 个以 `|` 开头）。
- **判断**：P3，表格类 chunk 是一期文本问答可接受形态；「表：召唤怪物」等是有效内容，**不应降权**。结构化（metadata 加 `table:true` / 行结构化）是数据侧改造，用户已拍板「回头统一处理」（KN221 处置），不在本批次。
- **方案**：登记观察。

## 四、实现架构（检索层统一降权框架）

参考 class 基础页先例（`boostedScore`），扩展为集中式排序调整，保持单点可控：

```java
// SearchService 新增字段（@Value，均带默认值，置 0 即关闭对应降权）
@Value("${pf.search.intro-penalty:0.03}")      private double introPenalty;
@Value("${pf.search.oversize-threshold:5000}") private int oversizeThreshold;
@Value("${pf.search.oversize-penalty:0.02}")   private double oversizePenalty;
@Value("${pf.search.filter-blank-text:true}")  private boolean filterBlankText;

// 统一排序分：base + classBonus - intro - oversize（替换 boostedsCore）
private double rankedScore(Document doc, String module) { ... }

// search()：先剔除空 text，再按 rankedScore 降序取 topK
```

- `rankedScore()` 取代 `boostedScore()`，原 class 基础页加分测试保留不回归。
- `filterBlankText` 默认 true，置 false 可关（兼容极端情况）。
- `application.yml` 补齐 `pf.search.*` 配置项，同步设计文档 §12（顺带补 class-base-bonus/class-extra-candidates 遗漏项——当前代码靠 @Value 默认值兜底，文档/配置不同步）。

**边界（不动）**：`searchByMetadata` 枚举路径不涉及降权（按字段过滤，无相似度排序）；`FilterTranslator`/`StandardChunkMapper`/`ChunkImporter`/各 DataLoader 不动。

## 五、验证口径

1. **TDD**（SearchServiceTest 新增，先测试后实现）：
   - intro/reference chunk 相似度略高于普通条目时被压到普通条目之后（对称于基础页加分测试）；
   - 空 text chunk 不进结果（filter-blank-text 开/关两个分支）；
   - oversize chunk 降权；非目标模块不误伤；
   - `intro-penalty=0` 时行为与现状一致（可回退验证）。
2. **评测集 baseline**：执行前先跑 `evaluate.py` 记录 56 题基线（溯源/诚实/结构三维度），改后对比，只允许升不允许结构性降。
3. **真实检索复现**：bge-m3 复现「猛力攻击先决条件」「火球术射程」「女巫巫术」「专长有哪些分类」，对比降权前后 top5 构成与命中率。
4. **回归**：AKN-003 两个问法（女巫等级表 / 准备施法者）不得回退（class 基础页加分测试保留）。

### 五.A 真实检索复现结果（2026-08-16，Batch A/B 后）

用真实向量库（`~/.pf_agent/vector_store_*.json`）+ Ollama bge-m3，Python 复刻 `SimpleVectorStore.similaritySearch`（阈值 0.5）+ `rankedScore` 排序逻辑，对比降权前后 top5：

| 问题 | 模块 | 降权效果 |
|---|---|---|
| 专长有哪些分类 | feat | ✅ 生效：`feat_intro 专长` 0.6744→0.6444 被压 0.03，真实条目「奇才」新进 top5 |
| 猛力攻击的先决条件 | feat | 无变化（top5 全为真实条目/索引，无 intro/oversize 竞争） |
| 攻击加值如何计算 / BAB 是多少 | rule | 无变化（top5 全为 `rule_section` 有效内容） |
| 火球术射程 | spell | 无变化（spell 库 `component_type` 全空，冻结模块旧格式，降权不生效——符合约束） |
| 矮人的种族特性 | race | 无变化（top5 为 `alt_trait`；`_overview` 不在首批降权范围，符合拍板） |

结论：降权在真实数据上**如设计工作**——低信息量 `feat_intro` 被压后真实条目浮出；无 intro/oversize 竞争的问题**零误伤**（top5 构成不变）。

### 五.B _overview 第二批评估结果（2026-08-16，AKN-005）

真实检索复现评估 `_overview` 是否纳入降权（方案 §七.1 决策点），结论：**不纳入**（用户拍板）。

- **画像**：`_overview` 仅 class_overview 715（5.1%）/ race_overview 111（3.0%），其余模块无。
- **挤占**：class 2/6 问法「职业特性」总览混入 top5（游侠宿敌第 2、牧师领域第 5），0.02 降权可改善；战士问法 top1 差 0.038 压不动。
- **误伤（决定性反例）**：职业介绍类 4/4 问法 class_overview 是正确 top1（战士/牧师/女巫/游侠），「牧师介绍」top1 与第 2 仅差 0.0068——降权 0.02 会压掉介绍类正确命中。
- **决定**：不纳入。第一批 intro/ref 降权已覆盖主要噪声；后续若观测到具体特性检索仍被挤占，再评估「按问法区分」方案。
