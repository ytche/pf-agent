> **日期**：2026-08-25

## 一、背景

部分 chunk 正文含仓库内部整理路径行：`> 来源：XXX手册（XXX Handbook），页码见原书，未整理 → XX → Y`（全库约 1900 chunks，跨职业/专长/规则/法术/装备 5 模块）。该行对 LLM 和用户都是噪声，但它是数据侧 toc 回填链路的来源信号（`BackfillChmTocPath`），且用户明确要求保留作追溯用——因此只在**展示出口**剥离，落盘数据不动。

## 二、改动设计

### 改动 1：新增剥离工具方法

新建 `pf_agent/agent/src/main/java/com/pfagent/agent/rag/TextSanitizer.java`（普通工具类，非 Spring bean，静态方法）：

```java
/** 剥离仓库内部整理路径行（KN207）：以「> 来源：」开头且含「未整理 →」的整行。
 *  仅用于展示出口；落盘 chunk 与 embedding 不动（用户拍板保留作追溯）。 */
public static String stripInternalSourceLine(String text)
```

- 匹配规则（保守，宁漏勿错）：逐行处理，**仅当一行同时满足**①trim 后以 `> 来源：` 开头、②含 `未整理 →` 或 `未整理→`——删除该行；剥离后把因此产生的连续空行坍缩为一个（文末空行直接去掉）。
- 不匹配任何形式的普通内容行；不含「未整理 →」的 `> 来源：` 行（若有）保留。

### 改动 2：两个展示出口接入

1. **LLM 侧**：`RetrievalTools.formatFragments()`（`:206`）——`truncate(doc.getText(), vectorResultChars)` 改为先 `stripInternalSourceLine` 再 truncate（先剥再截，避免截断后残留半行）。
   - `formatCompact()` 只输出 metadata 不含正文，**不动**。
2. **前端侧**：`ChatService.toSourceRef()`（`:262`）——`SourceRef.content` 由 `doc.getText()` 改为 `TextSanitizer.stripInternalSourceLine(doc.getText())`。

### 不改的地方

`Document.text` 本体、SourceCollector、embedding、chunks.jsonl、evaluate.py 判分（判分走 chunkId/tocPath/book，不依赖正文该行）——全部不动。
