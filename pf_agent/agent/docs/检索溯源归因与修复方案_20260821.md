# 检索溯源归因与修复方案（2026-08-21）

> 定位：baseline 溯源 38/50 后，对剩余 12 题溯源=0 的归因分析与修复规划。
> 状态：**P0-B 批次已执行（2026-08-25）**——溯源 44→46/50（T1/T2 落地 + easy-7/medium-0 恢复），剩余 easy-22/medium-4/medium-21/medium-25 召回精度归因完成（见 §六）；修法由 k3 设计。

## 一、背景与结论

spell 向量库重建闭环后（`eaca0ad`），baseline 溯源 33→38/50、诚实 50/50、结构均值 2.96。剩余 **12 题溯源=0** 经三路调查（锚点来源 / class hash 漂移 / 检索链路）确认：

- **锚点无漂移**：147 个评测锚点（含 class 的 42 个 hash64）100% 命中当前 chunks.jsonl 的 `chunk_id` 字段，0 miss。
- **class hash 无漂移**：6 个 class 锚点在 `vectorization_prep_profession/chunks.jsonl`（13895 行）与 `vector_store_classes.json`（13895 docs）各命中 1 次，无需重建 store。
- **真实根因 = 检索召回精度**：Agent 召回了「语义相关但非精确锚点」的 chunk，`score_citation` 精确匹配判 0。属 P0-B 检索联调对象，与数据/锚点无关。

## 二、归因分析（12 题 → 3 类根因）

### 根因 A1：相邻 chunk 排序压过锚点（约 4 题）

**机制**：同页相邻规则小节语义高度相近，`SimpleVectorStore` 纯余弦降序 + 无 rerank，把「通用邻居」排在「具体锚点」前面；LLM 按序引用第一条就错。

**实测证据**（Agent 2 用持久化向量库复现，与 SearchService 同构）：

| 题 | 邻居（错误命中） | 锚点（正确） | 相似度差 |
|---|---|---|---|
| medium-7 战斗反射 | `rule_rpage_0002_0030` #1（0.7672） | `rule_rpage_0002_0031` #4（0.7256） | 0.042 |
| medium-25 擒抱 CMB | `rule_rpage_0008_0008` | `rule_rpage_0008_0009` | — |
| easy-22 叠加 | `rule_page_127_0005` | `rule_page_127_0028` | — |
| easy-1/14/18（class） | 同职业相邻 chunk（hash 不同） | 锚点 hash | — |

> class 题的特殊性：chunk_id 是 `sha256(doc_id|title|text)` 内容哈希，错位后 hash 完全不同，`score_citation` 四条规则（chunkId 精确/前缀、tocPath 相等/前缀、book、子串）**全部 miss**，无语义兜底 → 必判 0。而 rule/feat 题锚点可读，至少能看出「差 1」。

### 根因 A2：topK=5 太小，锚点出局（约 7 题）

**机制**：`pf.search.top-k` 默认 5，且每模块各自 limit 5 后再全局 limit 5（`SearchService.java:118-124`）。在语义拥挤模块（feat 有 1856 条过 0.5 阈值），正确锚点排到 20+ 名直接出局。

**实测证据**：

| 题 | 锚点 | 实际排名 | 是否进 top-5 |
|---|---|---|---|
| medium-20 法术瞬发 | `feat_page_195_0361` | #23（0.598） | ❌ 出局 |
| medium-1 火焰抗力 | `race_page_245_0008` | 同页 offset 差 | ❌ |
| easy-7/medium-0 兼职 | class 兼职 chunk | 召回 rule 模块 Unchained 规则 | ❌ |
| easy-21 诅咒 | `rule_page_240_0020` + `spell CRB_0444` | 召回 HA 扩展书诅咒 | ❌ |

> class 模块有 `class-extra-candidates=3` 候选扩容，但 feat/rule/race 无；且 medium-20 锚点排 23，+3 也不够。

### 根因 B：聚合题锚点设计不合理（1 题）

- **medium-17**「最高价魔法物品」：需跨 96 个奇物 chunk 综合找最高价，expected 只标了 `equipment_page_222_0000` / `220_0000` 两个 page。聚合题的答案分散在多个 chunk，强制「精确 chunk 溯源」本身不合理。

## 三、修复方案（分层，标注推荐）

### 修复 1：扩大 topK + 单条截断收紧（对治 A2）【推荐】

- `pf.search.top-k` 5 → **15**（token 成本权衡见决策点）
- 配合 `pf.search.vector-result-chars` 1500 → **800**（单条正文截断收紧，抵消 topK 扩大的 token 增量）
- 效果：medium-20 锚点排 23 → 进 top-15 候选。

### 修复 2：相邻 chunk 召回扩展（对治 A1）【推荐】

- `SearchService.search()` 检索后，对命中 chunk 做「同 doc_id 相邻 offset 扩展」——命中 `rule_rpage_0002_0030` 时，把同页 `0031`、`0029` 一并纳入候选（或合并为一条给 LLM）。
- rule/feat/equipment/skill/race 的 chunk_id 可解析 offset（`{category}_{page}_{idx:04d}`，`processors/base.py:144`）；class 用 doc_id 匹配相邻 chunk（hash 不可解析 offset，但 chunks.jsonl 里有 doc_id）。
- 轻量、确定性、可解释，无需额外模型（2核2G 部署友好）。
- 效果：medium-7 锚点 0031 即使排 #4，扩展后必被带上。

### 修复 3：medium-17 聚合题评测口径调整（对治 B）【推荐】

- 聚合题（跨 chunk 综合）的溯源判分从「精确 chunk 匹配」放宽：命中任一相关模块 chunk 即算溯源，或这类题只判诚实/结构不判溯源。
- 实现：`evaluate.py` 增加「聚合题」标记（如 `dimension == "聚合"` 或新增字段），`score_citation` 对聚合题走宽松匹配。

### 修复 4（可选，1+2 不够时）：检索后轻量 rerank

- 对 topK 候选用标题/关键短语重排，或 LLM rerank。较重，二期考虑，本期不排。

## 四、决策（已拍板 2026-08-21）

1. **topK 扩容**：`pf.search.top-k` 5 → **15**，配合 `vector-result-chars` 1500 → **800** 收紧。
2. **相邻 chunk 扩展**：**±1**（命中 chunk 前后各带 1 个同 doc_id 相邻 chunk）。
3. **medium-17 聚合题**：**评测口径放宽**（聚合题溯源从精确匹配改宽松，或只判诚实/结构不判溯源）。

- 诚实 50/50、结构 2.96 不回退

### 修复 2 重新评估（实现障碍 + 有效性重估）

实施前发现两个新信息，动摇了「±1 相邻扩展」的原始假设：

1. **实现障碍**：`SimpleVectorStore` 的 `store` 字段是 `protected Map<String, SimpleVectorStoreContent>`，**无公开遍历 API**（只有 `similaritySearch` 按 embedding 召回）。「chunk_id → Document 反查」只能靠读 chunks.jsonl 另建索引——侵入数据加载层（ChunkImporter 职责）且全量 chunk 文本在内存翻倍（2核2G 部署压力）。

2. **有效性重估**：重看 §二 根因 A1 实测数据，「相邻」假设不成立：
   - medium-7 锚点 `rule_rpage_0002_0031` 排 **#4（在 top-5 内）**，是 LLM 引用 #1 邻居而非召回缺失 → ±1 无效，需排序修正；
   - easy-22 邻居 `0005` vs 锚点 `0028` **差 23 offset**（非相邻）→ ±1 无效；
   - easy-1/14/18（class）锚点是 hash64，**不可解析 offset**，±1 需查 jsonl 顺序（侵入）且「相邻」语义不清。
   真正「±1 相邻且被 topK 挤出」的题约 1-2 题（如 medium-25 `0008`/`0009`），而 topK 5→15（修复 1）已能覆盖「锚点被 limit 截断」的绝大部分情况。

**针对性验证结果（2026-08-21，12 题溯源=0 重跑）**：命中 **5/12**——easy-21、medium-0/7/17/20 恢复（修复 1 救 medium-7/20/easy-21 可读锚点，印证 A2 归因正确；修复 3 救 medium-17；medium-0 为 LLM 召回波动恢复）。仍=0 的 7 题：easy-1/7/14/18（class hash）、easy-22（差 23 offset）、medium-1（race/class）、medium-25（0008/0009 相邻）。

**结论（修复 2）**：±1 边际收益已由数据证实极低——唯一「±1 明确」的 medium-25 在 topK 扩大后仍=0（0009 仍被挤出或 LLM 引用邻居），±1 未必能救；实现又有架构障碍（SimpleVectorStore 无遍历 API）。**修复 2 建议不做**。
