## 1. 背景与定位

开源单体计划第 4 子项目。当前回答只在页尾「来源折叠区」列出引用 chunks，正文与来源**无对应关系**——用户无法逐句追溯「这句话依据的是哪条检索结果」。F-014 要求论文式上标编号：正文句末 `[#N]`，对应来源列表第 N 条，点击定位。

现状链条（全部亲读核实）：

- `SourceCollector`（ThreadLocal 请求级）：工具 `add(docs)` 汇聚 → `drain()` 按 chunk_id 去重（缺 chunk_id 兜底 `doc:doc_id`）→ `ChatResponse.sources`。**编号天然锚点 = drain 后数组下标+1**。
- 编号注入面小：全工程仅 `RetrievalTools` 三处 `collector.add`（`vectorSearch` L104、`searchByMetadata` L137、`getSpellList` L191）。
- `PromptBuilder` 现有约束「回答须引用来源（书 + 页码）」但无编号机制。
- 前端 `renderSources` 渲染折叠区、无编号徽标；正文 `marked.parse(escapeHtml(...))` 渲染（C1 防注入先例：先转义后 parse）。

## 2. 目标 / 非目标

**目标**：
1. 来源编号机制：编号在 `SourceCollector.add` 时按 drain 同款去重键分配（1-based，稳定），工具返回文本携带 `[#N]` 让 LLM 知道编号。
2. prompt 约束 LLM 引用句末标 `[#N]`，编号只能来自工具返回。
3. 后端兜底校验：越界编号剥离（保正文、记日志），不错挂。
4. 前端：正文 `[#N]` 渲染为上标链接，点击展开来源区并定位；来源列表加编号徽标。
5. 评测不回退（基线口径见 §0）；单测覆盖编号分配/注入/剥离。

**非目标**：
- **不改评测维度**（溯源正确性判分已存在；F-014 提到的「编号强化判分」留待后续批次，本批只保证编号机制正确）。
- 不动检索逻辑（topK/排序/路由/截断）、不动 SP3 的 `getSpellList` 清单语义（列表页单来源，标注一次即可，不逐条挂号）。
- 不强制 LLM 必标：LLM 漏标时后端不补插（避免错挂），来源折叠区照常展示（登记观察项即可）。
- 不做流式输出、不动 `ChatResponse`/`SourceRef` 结构（编号=数组下标+1，不落字段）。
- 不改历史会话回答（无编号旧回答正常展示）。

## 3. 设计决策（D1~D7）

- **D1 编号分配（add 时，去重键与 drain 一致）**：`SourceCollector` 内部由 `List` 改为 `LinkedHashMap<dedupKey, Document>`（dedupKey = chunk_id，缺省 `doc:doc_id`，与 drain 现有逻辑逐字一致）。`add(List<Document>)` 返回 `List<Integer>`（与入参等长）：新键分配递增编号（1-based），重复键返回既有编号。`drain()` 返回 `map.values()`（插入序=编号序），编号不再二次计算。未 begin/空入参返回空列表。
- **D2 工具返回注入编号**：三处 add 调用点取回编号，在返回 LLM 的文本中标注：
  - `vectorSearch`：每个命中片段头部加 `[#N]` 前缀；
  - `searchByMetadata`：每条紧凑行末尾加 `[#N]`；
  - `getSpellList`：概览与清单文本末尾统一加一行「本清单来源 [#N]」（单来源不逐条挂号）。
  - 编号文本格式 `[#N]`（半角井号）——工具返回与 LLM 回答用同一标记，模型迁移成本最低，且不与 Markdown 链接语法 `[text](url)` 冲突。
- **D3 回答标注语法**：LLM 在引用检索内容的句/段末写 `[#N]`；多个依据连写 `[#1][#2]`。N 为工具返回中的来源编号。
- **D4 prompt 约束（PromptBuilder 增量，不动既有条目）**：追加规则——「引用检索结果的句末标注来源编号 `[#N]`，N 只能取自工具返回文本中的 `[#N]` 标记；禁止编造编号；无检索依据的推断内容不标注；reportDataGap 路径无编号」。工具描述（@Tool description）不动。
- **D5 后端兜底剥离（ChatService.buildResponse 前）**：正则扫描 answer 中全部 `[#N]`：`1<=N<=sources.size()` 保留；越界/畸形 → 从正文移除该标记（保留句子本身）并记 WARN（含 question 摘要与剥离的编号，供 qa 分析）。**不重排、不补插、不改 sources 顺序**。
- **D6 前端渲染（index.html，延续 C1 先例）**：
  - 正文：`marked.parse(escapeHtml(answer))` 之后对 HTML 串做 `\[#(\d+)\]` → `<sup class="cite" data-n="N">[N]</sup>` 替换（`[#N]` 不含 HTML 特殊字符，转义与 marked 处理均不改变其形态；替换产物是固定模板串，无注入面）。
  - 来源区：`renderSources` 每项加 `id="src-N"` 与编号徽标 `[N]`（summary 计数文案不变）。
  - 点击上标（事件委托）：展开 `<details class="source">`、滚动到 `#src-N`、短暂高亮。
  - 越界编号已被后端剥离，前端遇到的 `[#N]` 必然合法；防御上 N 无对应来源项时按纯文本渲染不报错。
- **D7 编号即索引**：`ChatResponse.sources` 数组顺序 = drain 序 = 编号序，编号不落新字段、不改 API 结构。前端 `sources[N-1]` ↔ `[#N]`。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| LLM 不标/乱标编号 | prompt 约束（D4）+ 越界剥离（D5）；漏标不补插，功能降级为现状，可接受 |
| 编号与 sources 错位 | D1 单一分配点（add 时定号、drain 只取值），单测锁死「重复命中同号」「drain 序=编号序」 |
| 上标替换误伤正文（代码块/表格内的 `[#1]` 字样） | 规则文本几乎不出现 `[#N]` 形态；本地单用户低危，登记已知语义 |
| 工具结果体积增加 | 每条仅多 5~6 字符，远低于 metadata-result-chars 护栏，无影响 |
| 旧回答兼容 | 无编号回答原样渲染（替换正则无匹配），无迁移 |
