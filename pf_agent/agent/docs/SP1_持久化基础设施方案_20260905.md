## 1. 背景与定位

开源单体计划的第一个子项目（SP1~SP6 见决策记录 §三）。引入项目首个数据库 PostgreSQL 16（pgvector 镜像，为将来向量库进 DB 预留），落地会话持久化（F-003）与轮数限制（F-005），并把 VectorStore 消费边界从具体类收窄到接口。

## 2. 目标 / 非目标

**目标**：
1. PG 可选接入：不配 datasource 则行为与现状完全一致（内存模式）。
2. `JdbcChatMemory`：会话跨重启保留，默认保留最近 20 轮（可配）。
3. 持久化故障不打断问答主链路（读/写降级，启动 fail-fast）。
4. VectorStore 消费方全部改注入接口类型，持久化（load/save）隔离到独立内部接口。

**非目标**：
- 不做用户体系/鉴权（微服务版的事，本批匿名会话无 owner 字段）。
- 不做限频配额（SP2）、向量库进 DB（后话，本批只收口边界）。
- 不引入重试/熔断组件；不改检索/评测行为。

## 3. 设计决策（D1~D7，均已拍板）

- **D1 持久层**：Spring Data JPA（不用 MyBatis-Plus）。
- **D2 PG 可选**：默认内存模式；`pf.chat.memory: memory|jdbc`（默认 `memory`）+ `@ConditionalOnProperty` 装配。
- **D3 表结构**（两张表）：

```sql
CREATE TABLE chat_conversation (
  id              VARCHAR(36) PRIMARY KEY,   -- 后端生成的 UUID
  created_at      TIMESTAMPTZ NOT NULL,
  last_active_at  TIMESTAMPTZ NOT NULL,
  message_rounds  INT NOT NULL DEFAULT 0     -- 冗余轮数（F-005 + SP2 配额复用）
);

CREATE TABLE chat_message (
  id              BIGSERIAL PRIMARY KEY,
  conversation_id VARCHAR(36) NOT NULL REFERENCES chat_conversation(id) ON DELETE CASCADE,
  seq             INT NOT NULL,              -- 会话内消息序号
  role            VARCHAR(10) NOT NULL,      -- user / assistant
  content         TEXT NOT NULL,
  created_at      TIMESTAMPTZ NOT NULL
);
CREATE INDEX idx_chat_message_conv_seq ON chat_message(conversation_id, seq);
```

- **D4 ChatMemory 实现**：`JdbcChatMemory implements ChatMemory`（Spring AI 接口）。`get(cid, lastN)` 查最近 N 条；`add()` 单事务完成「写消息 + 更新会话计数 + 超轮裁剪」；`clear()` 删会话。只落 [user, assistant] 对（现状语义不变），`ChatService` 零改动。
- **D5 保留轮数**：默认 20，`pf.chat.history-rounds` 可配。
- **D6 错误处理**：写异常 → warn 日志 + 本轮照常返回；读异常 → warn + 空历史（等价新会话）；配了 PG 但启动连不上 → **启动失败**（fail-fast，不静默降级）。
- **D7 schema 管理**：Flyway（`V1__init.sql`），`ddl-auto=validate`。选 Flyway 而非 `ddl-auto=update`：开源项目的 schema 必须可复现、可演进，且为将来向量库迁移脚本留好机制。

## 4. VectorStore 边界收口（纯重构，零行为变化）

1. 消费方注入类型 `SimpleVectorStore` → `VectorStore` 接口：SearchService（8 处）、各 DataLoader、ChunkImporter。
2. 新增内部接口 `VectorStorePersistence`（`loadIfExists(String path)` / `save(String path)`），默认实现 `SimpleVectorStorePersistence`；仅在 `VectorStoreConfig` 与 DataLoader 构建路径出现。业务代码不可见。
3. 检索 API（similaritySearch / Filter.Expression）本就是接口级，不动。

## 8. 风险与回滚

| 风险 | 缓解 |
|---|---|
| H2 与 PG 方言差异导致「测试绿、真库挂」 | V5 手工冒烟用真实 pgvector 容器兜底；SQL 只用标准语法 |
| 裁剪并发竞态（同会话并发写） | 现有请求按 ThreadLocal 隔离，同会话串行；事务内裁剪 |
| VectorStore 收口误改检索语义 | 纯类型收窄 + V4 评测基线闸口 |
| 回滚 | 单批次 revert 即可；内存模式是默认路径，PG 不启用等于零影响 |
