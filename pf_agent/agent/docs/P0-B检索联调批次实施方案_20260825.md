`rankedScore()`（`SearchService.java:192-205`）现有三项调整：`class-base-bonus +0.03`（class 基础职业页）、`intro-penalty -0.03`（`_intro`/`_reference` 结尾的 component_type）、`oversize-penalty -0.02`（text > 5000 字符）；排序前另有空 text 剔除（`filter-blank-text: true`）。配置集中在 `application.yml` 的 `pf.search.*`（`top-k: 15`、`similarity-threshold: 0.5`、`vector-result-chars: 800` 等）。

### T1 · `isBaseClassPage` 前缀 bug 修复

**位置**：`pf_agent/agent/src/main/java/com/pfagent/agent/rag/SearchService.java:229-236`。

**现状代码**：

```java
/** 基础职业页判定：tocPath 恰为「职业 → 基础职业 → X」，无更细分后缀（变体/巫术/庇护主） */
private boolean isBaseClassPage(Document doc) {
    Object toc = doc.getMetadata().get("tocPath");
    if (!(toc instanceof String tp)) {
        return false;
    }
    String prefix = "职业 → 基础职业 → ";
    return tp.startsWith(prefix) && !tp.substring(prefix.length()).contains(" → ");
}
```

**bug 实证**：对 `pf_data/phase1/vectorization_prep_profession/chunks.jsonl`（只读参考，不改）实测：
- `职业 → 核心职业 → ` 前缀约 3398 条（CRB：战士/牧师/法师/德鲁伊/术士/武僧/游侠/盗贼/吟游诗人/圣骑士/野蛮人）；
- `职业 → 基础职业 → ` 前缀约 2168 条（APG 等扩展书：炼金术师/骑将/女巫/魔战士/铳手/召唤师/先知等）。

两者都是"基础职业页"语义，但代码只匹配后者 → **CRB 核心职业基础页从未吃到 `class-base-bonus +0.03`**，而 CRB 职业恰是问答高频。

**修法**：前缀判定改为两个前缀的集合匹配 `{「职业 → 核心职业 → 」, 「职业 → 基础职业 → 」}`，其余语义不变（恰为该级、之后无更深层 ` → ` 才算基础页；变体/巫术/庇护主等深层页仍不命中）。注意维护方法 Javadoc 使其与新行为一致。

**测试**（`SearchServiceTest.java`，现有用例组「方案 B（AKN-003）」在 `:203` 起，测试装配辅助 `service(...)` 重载在 `:374` 起）补三组用例：
1. `职业 → 核心职业 → 牧师` 命中加分（排序压过非基础页同分邻居）；
2. `职业 → 核心职业 → 牧师 → 神祇/领域`（深层页）**不命中**；
3. 原 `职业 → 基础职业 → 女巫` 用例保留不回归。

**验收关联**：V1、V2。

### T2 · LLM 模块路由提示修复（治 easy-7、medium-0）

**实锤**：F-006 工具调用记录（`~/.pf_agent/tool_calls.jsonl`）证实 easy-7、medium-0 两题「兼职 Multiclassing」，LLM 调 `vectorSearch` 时传 `module: "rule"`；兼职规则实际在 class 模块（tocPath「职业 → 角色升级」），class 兼职 chunk 根本未被检索。根因：工具描述与 system prompt 均无模块语义引导，LLM 靠模块名单猜。

**改动 1**——`RetrievalTools.java` `vectorSearch`（`:103-124`）：`@Tool` description 与 module `@ToolParam` 描述补模块语义边界。必须明确写入的口径：
- **class**：职业特性/职业变体，**以及角色升级、兼职（Multiclassing）、升级时生命值/法术位/BAB 成长**（这类规则在「职业 → 角色升级」，**不在 rule**）；
- **rule**：战斗动作/状态效果/环境/移动等通用游戏规则；
- 拿不准模块时先 `vectorSearch` 用 `module: "all"`，据命中结果的 tocPath 再定向。

**改动 2**——`RetrievalTools.java` `searchByMetadata`（`:47-97`）：module 描述同口径对齐（措辞一致，不新增字段）。

**改动 3**——`PromptBuilder.java`（`:17-33`）system prompt 补一段模块路由速查（3~5 行）。参考措辞（执行时可微调，验收时 k3 审定）：

```
- 模块路由速查：升级/兼职(Multiclassing)/职业成长 → class；战斗动作/状态/环境 → rule；
  具体法术/专长/种族/装备/技能细节 → 对应模块；拿不准先 vectorSearch module:"all"
```

**注意**：`PromptBuilderTest.java:83-84` 现有断言 `assertThat(prompt).contains("基础职业")`，改动 prompt 时不得破坏既有断言；补新断言：prompt 含「兼职」与「角色升级」路由提示。`RetrievalToolsTest.java` 如有对工具描述的断言，同步更新。
