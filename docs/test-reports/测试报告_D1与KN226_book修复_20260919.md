## 白盒审计结果

**coder 测试质量：总体扎实，无假测试。**

- `test_feat_book_abbreviation.py`：18 条映射为 `@pytest.mark.parametrize` 逐一硬断言 + `len==18` 计数断言，无循环跳过/软断言；negative 样例 10 个 chunk_id 经复核确为修复前中文 book 样例且现已归一；`test_miss_keeps_raw`（查表未命中不编造）覆盖了关键异常路径。
- `test_rule_monster_source.py`：`test_scan_rels_completeness` 对全部 286 扫描文件断言专属表完备，9 文件归属为逐文件硬编码期望值，非集合成员弱断言。
- verify_feats `check_book_abbreviation`：实为「23 值黑名单 + `_has_chinese` 全量兜底」双保险，黑名单外新中文值同样 FAIL—— coder 自报口径（"黑名单枚举"）偏保守，实际覆盖已等价于"含中文即失败"。**非 CJK 非 ASCII 值（如全角符号）不在拦截范围**，为残留缺口 → 补测 T-01 全 ASCII 总断言（产物实测 0 违规）。
- verify_rule `check_kn226`：产物级只断言怪物规则文件 book ∈ {B1,CRB,MC,?} 集合 + 无「怪物」残留，未逐文件断言期望值；但逐文件期望已由单测 `test_each_file_resolves`（表级）+ `check_source_book`（产物↔表对账）传递覆盖。**结论：覆盖充分，非缺口**。
- 映射表 AST 检查：`_RULE_SOURCE_OVERRIDES`(87 键)、`MAPPING`(84)、`SRC_KEY_TO_BOOK`(17)、`abbr_candidates`(18) 均无重复键；abbr_candidates 无撞键、无死键（key 无 ASCII 尾部）。

**发现的边界行为（记录，非缺陷）**：
- 空箭头段 / 仅空白箭头段 → 返回 `('' , cn, en)` 空串 abbr 而非 None（产物中无空 abbr，feat_intro/feat_index 不走此通道，风险低）→ 补测锁定契约。
- 箭头段内嵌空格（`秽邪 勇士`）查表未命中保留原文（含中文）→ 由 verify `_has_chinese` 兜底，可接受。
- 有 ASCII 尾部即信任尾部（`武器大师手册WMH`→WMH，不回写规范 WEAPON）——既有契约，补测锁定。
