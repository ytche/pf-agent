## 三、审计结论（coder 23 个新用例复核）

- 断言有效性：通过。工具测试走 Mockito 隔离（SearchService/SourceCollector mock），断言输出文案关键片段（候选计数、"仅展示前 20 条"、固定提示原文），与实现字符串一致；EntryResolverTest 用 @TempDir 真实 jsonl 驱动 buildIndex，非纯 mock，可信度高。
- 正常 + 错误路径：正常路径覆盖充分；错误路径覆盖空名、查无此名、未知模块、开关关闭、文件缺失。
- 审计发现的 coder 测试缺口（已由补测闭合）：
  1. `missingFileAndBrokenLineTolerated`（EntryResolverTest）**测试名承诺坏行容错但用例只测了文件缺失**——坏行路径实际无覆盖。
  2. 反查截断只测了"超上限"，未测"恰等于上限不截断"的边界。
  3. 向量库点查 miss（resolveEntry/getEntryLinks 命中索引但向量库无原文）分支无覆盖。
  4. metadata 重放"store 有额外键"的新幂等语义无覆盖。

## 五、缺陷分级

**Blocker / Major：无。**

Minor（留用户拍板）：

1. **metadata 重放会清除 store 中 mapper 产物之外的 metadata 键**（SpellMetadataReplayTool.java:96-102，逐条比对 fresh.equals(oldMeta)，不一致即整体替换）。补测已固化该行为：未来 Layer 1 若把 `entry_links` 写进向量库 metadata，任何一次 metadata-replay 都会将其静默抹掉。建议 Layer 1 立项时改为"merge 而非 replace"或把抽取产物放 chunks.jsonl 顶层经 mapper 白名单入 metadata。登记 KN 待拍板。
2. **EntryResolver 类 Javadoc 条目数过期**（EntryResolver.java:26 写"约 42,790 条"，实测 42,639）。纯注释，下次顺手改。
3. coder 偏差声明已核对，均合理：索引源用 chunks.jsonl（方案原文"从八个向量库构建"，实为 chunks.jsonl——成本更低且结构化字段只在原始行模型，可接受）；prerequisites 结构化 items（方案写"自由文本"，数据侧已结构化，按 type 优先模块解析正确）。
