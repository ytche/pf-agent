## 四、cicd CATEGORIES 与 skill via=direct 口径评估

- **事实复核（读 cicd/verify.py 装配表确认）**：CATEGORIES 实际 7 个类目（feat/race/trait/equipment/rule/spell/profession，verify.py:26-185），**无 skill**。coder 自报属实，非借口。方案文档"统一验收入口"一节写"8 类目"（docs/design/方案_数据产物可复现构建链_20260918.md:36），与装配表 7 类目不符，属方案侧的陈旧表述。
- 方案验收标准 1 写"≥9 个：8 类目 chunks + spell_lists"。在装配表只有 7 类目的现实下，凑满 9 的两个选项：skill 以 via=direct 登记（coder 选择），或只登记 8 个 artifact（7+1）。
- **评估：via=direct 口径可接受**，理由：
  1. build.py 装载期强制校验（via=cicd 的类目必须在装配表），coder 无法凭空登记 skill 为 cicd——走 direct 是唯一不破坏不变量的路径；
  2. manifest 带 `note` 明示原因与收敛条件（接入 cicd 后改 via=cicd），变更可追溯；
  3. 指纹链对 direct 步同样生效（config_deps 含 pipeline/processors/formats，实测 a2 证明 skill 随 pipeline.py 变 stale）；
  4. 产物路径与 inputs 经装载期存在性校验。
- **附带条件（遗留项）**：skill 直跑命令 `python3 -m vectorizer.pipeline --category skill` 不经过 cicd 四步链（无 pytest/invariants 闸口），其产物质量闸口弱于其余 7 类目。建议主 Agent 验收时跑一次该命令确认产物与现有 output/技能 一致（或将其接入 CATEGORIES 作为批 2 项）。
