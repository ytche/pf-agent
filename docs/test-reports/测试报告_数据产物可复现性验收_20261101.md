# 测试报告：数据侧全量产物可复现性验收

日期：2026-11-01  
范围：`pf_data/phase1` 的 14 个 build artifact（8 类 chunks + 6 类清单导出），共 28 个产物文件（78.6 MB）

## 验收目标

按 2026-10-29 用户补充的验收要求：快照当前全部数据产物 → 执行全量重建 → 逐产物对比，
确认当前 pipeline 能**正确还原**产物；任何差异须逐项定性。

## 方法

1. 从 `vectorizer/state/build_state.json` 取全部 artifact 的 `outputs`（28 个文件），
   `cp` 快照到 `/tmp/pf_repro/files/`，并记录每个文件的 sha256（`hashes.json`）。
2. `python3 -m vectorizer.build all --force`（第一次，全量重建）。
3. `build check` + 全量 pytest。
4. 第二次 `build all --force`，与第一次结果互比，验证连续两次是否一致。
5. 对不一致文件做结构级 diff（递归定位到字段），确认差异性质。

## 结果

| 对比 | 一致 | 不一致 | 差异性质 |
|---|---|---|---|
| 快照 vs 重建后 | 27 / 28 | 1 | `职业/class_tables.json` 仅 `generated_at` 不同（`2026-10-28T21:34:35Z` → `2026-11-01T10:10:55Z`） |
| 第一轮 vs 第二轮重建 | 27 / 28 | 1 | 同上，仅 `generated_at` |

- 其余 27 个产物（8 份 `chunks.jsonl`、8 份 `index.json`、5 份清单 JSON、6 份导出报告等）
  **字节级完全一致**。
- `python3 -m vectorizer.build check`：✅ 14 个 artifact 指纹一致、schema 版本匹配。
- 全量 pytest：**1784 通过**（0 失败）。
- `build all --force` 内部已逐类目跑完 pytest → pipeline → 集成验收 → 不变量闸口，14/14 全绿。

## 差异定性

`class_tables.json` 的 `generated_at` 是导出时刻的时间戳，与内容无关；
该文件是 14 个产物里唯一带此字段的（其余清单/报告均无时间戳或使用固定值）。
因此差异属**导出元数据**，不影响「pipeline 能否还原产物」的结论。

## 结论

1. **数据侧全量产物可复现**：内容级 28/28 一致（27 个字节一致 + 1 个仅时间戳不同）；
   连续两次全量重建结果也一致（同样 27/28）。
2. 建议把可复现性口径写死为「**内容一致，排除 `generated_at`**」，并在 `build check`
   中把该字段排除或改为可复现值（例如取源数据版本号/构建输入指纹，而非墙钟时间），
   以便未来做到严格字节级一致。
3. 构建耗时：第一次 **152 s**，第二次 **1053 s**（同一命令、同一产物），差异疑似机器负载/IO，
   待后续观察；首次 2.5 分钟可接受，若长期在 15 分钟级需排查。

## 附：复现方法

```bash
cd pf_data/phase1
python3 - <<'EOF'
import json, hashlib
from pathlib import Path
st = json.load(open('vectorizer/state/build_state.json', encoding='utf-8'))
files = sorted({r for v in st['artifacts'].values() for r in v.get('outputs', {})})
print({f: hashlib.sha256(Path(f).read_bytes()).hexdigest() for f in files})
EOF
python3 -m vectorizer.build all --force
python3 -m vectorizer.build check
```

比较时对 `职业/class_tables.json` 排除 `generated_at` 字段后应为字节/内容一致。
