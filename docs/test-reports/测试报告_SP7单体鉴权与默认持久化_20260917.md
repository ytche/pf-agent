## 缺陷清单

| 编号 | 严重级别 | 批次 | 描述 | 复现步骤 | 状态 |
|---|---|---|---|---|---|
| D1 | Minor | T3 | `AuthController` 注释声称 memory 模式 auth 接口返回"503 auth_unavailable"，实际 `requireAuthService()` 抛 IllegalStateException 走默认错误处理 → HTTP 500 + 通用错误体；AuthControllerTest 亦把该行为锁定为 500，注释与实现/测试互相矛盾。影响面小（memory 模式仅 auth 关态误调 auth 接口时触发，enabled=true+memory 已被 AuthProperties fail-fast 拦截） | memory 模式启动，`POST /api/auth/register` → 500 `{"status":500,"error":"Internal Server Error"}` | 挂起（交付文档已披露，最终验收由用户拍板：改注释为 500 语义，或加 @ExceptionHandler 转 503 {error:"auth_unavailable"}） |
| D2 | Minor | T5 | 根 `.gitignore` 第 47 行 `.env` 忽略规则带行内注释（`.env  # compose 环境变量…`），gitignore 不支持行内注释，实际 pattern 变为含注释文本的串，`.env` **未被有效忽略**；当前仓库无 .env 文件故未泄露（compose 渲染的密钥来自 shell 环境），但用户一旦 `cp .env.example .env` 并填真实密钥后误 `git add .` 即入库 | `git check-ignore .env` 返回 exit 1（未忽略）；行 47 文本含行内注释 | 新增发现，建议修复为独立行 `.env`（纯测试过程发现，未改任何文件） |

历史观察项（非缺陷，随档备查）：
- `Authorization: Bearer␣␣<token>` 双空格被 trim 容忍放行（行为宽松但一致）；小写 `bearer` 被拒 401
- `token-ttl-hours=0/负数` 无输入校验，语义为 token 立即过期，不崩不炸
- `AuthProperties.DEFAULT_JWT_SECRET` 与 `JwtService.DEFAULT_JWT_SECRET` 两处定义靠注释约定同步（当前一致）
- `me` 的 401 体无 message 字段，拦截器 401 体有 message（前端消费无碍）

## 需求澄清项

1. **密码 trim 语义**（T2 遗留）：D4 只说"≥8 位"，未明示 `" 12345678 "`（首尾空白）是否合法。当前实现 trim 后按 8 位接受，已按实现契约锁定测试。如需"原样校验"需调整实现。
2. **status 探测失败降级语义**（T4 遗留）：D6 未约定 `/api/auth/status` 探测失败（网络错误/5xx）时前端行为。当前实现隐藏登录入口（保守降级，有注释）。若产品期望"探测失败仍显示入口"需提需求变更。
3.（与 D1 关联）memory 模式 auth 接口期望 HTTP 语义：D4 未约定。当前 500。是否改为 503 + auth_unavailable 请设计方拍板。
