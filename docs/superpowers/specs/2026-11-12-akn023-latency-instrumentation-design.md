# AKN-023 列举式问答端到端耗时 — 埋点测量阶段设计 Spec

- 日期：2026-11-12
- 状态：埋点已实施并合并（M36）；2026-11-12 完成武僧清规 3 次复测与耗时拆分（总耗时 33.03/25.02/27.91 秒，LLM 端到端含网络占 73%~87%）。本阶段仍只测量、不优化，后续优化待另立任务；报告见 `docs/test-reports/测试报告_AKN-023武僧清规耗时拆分_20261112.md`
- 来源：`docs/已知问题记录_agent.md` AKN-023

## 1. 问题

「武僧清规有哪些内容」单次端到端实测约 **41.87 秒**。耗时构成未知，
网络延迟只是未证实的可能因素之一，不能据此直接优化。

## 2. 已确认决策

| 决策点 | 结论 |
|---|---|
| 路线 | **先埋点测量，再定优化方案**；本阶段不改问答行为 |
| 埋点落点 | **复用 `tool_calls.jsonl`** 增加分段耗时字段，并打应用日志；不新建 PG 表 |
| 验收 | 武僧清规复测 **3 次**，产出各段耗时拆分报告与优化建议；不跑全量评测 |

## 3. 实施要点

- 单次问答至少拆出：总耗时、LLM 调用次数与累计耗时、每次工具调用的名称与耗时、
  检索（向量/清单）耗时、工具轮次。
- 网络耗时若无法与 LLM 服务端耗时区分，需在报告中明确标注为“LLM 调用端到端耗时（含网络）”，
  不得把未拆分的数据解释成网络问题。
- `tool_calls.jsonl` 新增字段需向后兼容：旧记录无这些字段时，
  `qa/tool_calls_report.py` 等分析脚本不得报错。
- 日志输出与 JSONL 记录口径一致，便于交叉核对。

## 4. 不做

- 不做流式输出、并发检索、减少工具轮次等任何优化。
- 不新建 PG 表，不改评测集与评测脚本。
- 不在本阶段承诺目标耗时；优化目标待拆分数据出来后另定。

## 5. 验收

1. 单测/兼容：旧格式 `tool_calls.jsonl` 记录仍可被分析脚本读取。
2. 武僧清规连测 3 次，得到总耗时与分段耗时拆分，标注最大耗时段。
3. 产出优化建议清单（按预期收益排序），作为下一阶段立项依据。
