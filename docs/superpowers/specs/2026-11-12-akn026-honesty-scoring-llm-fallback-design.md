- 来源：`docs/已知问题记录_agent.md` AKN-026；`pf_agent/agent/qa/evaluate.py`

## 1. 问题

`score_honesty` 在 `gapReported=true` 时仅按 `HONEST_PHRASES` 固定词表做子串匹配。

两次实测反例：
- medium-27（历史）：回答写“已提交数据缺口报告”“没有检索到专门条款”，旧词表不含，误判 0。
- medium-17 run3：回答写“这是数据能力和工具能力的缺口”“不能当作全库最贵”，并给出 4 个收窄问法，
  实质诚实，但因不含连续子串“数据缺口”判 0。该轮 `gapReported=true` 为判分逻辑反推，
  `qa_report.json` 不保存该字段。

M29 只扩充词表，未解决根因。

## 2. 已确认决策

| 决策点 | 结论 |
|---|---|
| 判分方式 | **规则 + LLM 兜底**：词表命中直接判 1；`gap=true` 且未命中词表时调 LLM 判断是否实质诚实 |
| 启用方式 | **默认启用、按需调用**：仅 `gap=true` 且词表未命中时调用，正常题零额外调用 |
| LLM 失败 | 该题记 **待复核**，不记 0；报告中显式标注并单独计数 |
| 负例保护 | 无来源却给出确定结论/具体数值的回答必须判 0，无论措辞是否“谦虚” |

## 3. 实施要点

- `qa_report.json` 新增保存 `gapReported` 原始值与诚实性判定依据
  （词表命中词 / LLM 理由 / 待复核原因），消除“只能反推”的证据边界问题。
- LLM 判分提示词需明确二分标准：
  - 判 1：承认数据不足或范围受限，且未在无来源情况下给出确定结论；
  - 判 0：在无来源情况下编造具体数值、条目、价格、规则裁决，或声明“已核实”但无来源。
- 待复核不计入 0，也不计入通过；汇总需单独列出待复核题数，避免基线被静默抬高或拉低。
- 词表保留为快速路径，不删除。
- 复用现有 DeepSeek 调用配置与 `judge_llm` 的错误处理风格。

## 4. 不做

- 不把诚实性维度完全交给 LLM。
- 不改动其他维度（溯源/结构/事实准确性/完整性）的判分逻辑。
- 不改 Agent 运行时行为；本项只影响评测工具。

## 5. 验收

1. 单测：词表命中判 1；gap=true 未命中词表时走 LLM；LLM 判 1/判 0/失败待复核三条路径；
   无来源编造结论的负例必须判 0。
2. 用 medium-17 run3 的实际回答文本做回归用例，修复后应判 1（或按 LLM 实判记录理由）。
3. 报告中可直接读到 `gapReported` 与判定依据，不再需要反推。
