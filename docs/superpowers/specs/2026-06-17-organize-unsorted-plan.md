# "未整理"部分文档处理计划

## 目标

把 CHM 目录结构中 L1 = "未整理" 下的 Markdown 文件，按**内容类型**重新整理到标准分类目录中，同时完整保留原始出处信息，确保后续 Agent 回答时可以向用户展示可核验的来源。

## 当前状态

- "未整理"下约有 **1194 个 Markdown 文件**，分散在 147 个 L2 来源书/章节下；
- 这些文件当前全部平铺在 `pf_data/phase1/pf_rules_md/` 下；
- 已通过 `pf_data/md_mapping.json` 建立了：
  - MD 文件 → HTML 文件名
  - MD 文件 → 原始目录路径（如 `未整理 → 惧怖冒险 HA → 替换种族特性`）
- 已把原始 HTML 文件复制到 `pf_data/source_chm/`（gitignored）。

## 整理原则

1. **按 CHM 目录的 L1 级别标题归类**，不按来源书归类；
2. **保留原出处**：每个文件必须记录原始目录路径、原 MD 文件名、原 HTML 文件名；
3. **文件名清晰**：新文件名包含来源书 + 内容标题，如 `惧怖冒险HA_替换种族特性.md`；
4. **可回滚**：先输出整理清单，确认后再执行移动；原文件不删除，采用复制方式；
5. **并发执行**：每个 L2 来源书作为一个独立任务，由 subagent 并行处理。

## 处理流程

### 阶段 A：生成分类清单（先验证，再移动）

1. **读取映射**：从 `pf_data/md_mapping.json` 筛选 `toc_path` 以 `未整理 → ` 开头的条目；
2. **按 L2 分组**：每个 L2 来源书生成一个待处理列表；
3. **L3 标题匹配**：用分类体系规则为每个条目确定 `target_category`；
4. **生成新路径**：`pf_data/phase1/pf_rules_md/<target_category>/<L2书名>_<L3标题>.md`；
5. **输出清单**：`pf_data/reorganization_plan.json`。

清单结构示例：
```json
[
  {
    "original_md_name": "page_524.md",
    "original_html_name": "page_524.html",
    "original_toc_path": "未整理 → 惧怖冒险 HA → 替换种族特性",
    "l2_source": "惧怖冒险 HA",
    "l3_title": "替换种族特性",
    "target_l1": "种族",
    "new_path": "pf_data/phase1/pf_rules_md/种族/惧怖冒险HA_替换种族特性.md"
  }
]
```

### 阶段 B：人工确认示例

以 **惧怖冒险 HA** 为例，先处理这一个 L2：
- 生成该 L2 的整理清单；
- 以表格形式展示给用户确认；
- 用户确认分类无误后，再批量执行。

### 阶段 C：并发处理所有 L2

用户确认 HA 示例后，启动多个 subagent，每个 subagent 处理一个 L2 来源书：
- **输入**：`md_mapping.json` 中该 L2 的条目；
- **任务**：
  1. 分析该 L2 下所有 L3 标题；
  2. 按分类体系为每个条目确定 target_category；
  3. 输出该 L2 的整理清单 JSON 片段；
- **输出**：保存到 `pf_data/reorganization_plans/<L2_safe_name>.json`。

主流程汇总所有片段为 `pf_data/reorganization_plan.json`。

### 阶段 D：执行移动

1. 根据 `reorganization_plan.json` 创建目标分类目录；
2. 复制（不是移动）原 MD 文件到目标目录；
3. 生成 `pf_data/reorganization_report.md`，统计每个分类的文件数量、每个 L2 来源书的分布；
4. 生成 `pf_data/document_manifest.json`：所有文件（包括原本就有分类的）的最终路径、原目录路径、HTML 文件名。

### 阶段 E：验证

1. 检查每个目标分类目录的文件数量是否合理；
2. 抽样 20 个文件核对分类是否正确；
3. 检查 `reorganization_plan.json` 中是否有未分类条目（目标 < 5%）；
4. 检查原文件是否未被删除。

## 技术实现

### 新建脚本

`pf_data/organize_unsorted.py`：主控脚本，负责：
- 读取 `md_mapping.json`；
- 筛选"未整理"条目；
- 按 L2 分组；
- 调用分类规则；
- 输出清单；
- 执行复制。

### 分类规则实现

用关键词匹配函数，按优先级从高到低：
1. 精确匹配 L3 标题到分类；
2. 关键词包含匹配；
3. 无法匹配时标记为 `规则/`（待人工复核）。

### Subagent 调用方式

每个 subagent 接收：
- L2 来源书名称；
- 该 L2 下所有条目的 JSON；
- 分类规则说明。

每个 subagent 输出：
- 该 L2 的整理清单 JSON 片段。

## 输出产物

| 文件 | 说明 |
|------|------|
| `pf_data/reorganization_plan.json` | 完整整理清单 |
| `pf_data/reorganization_report.md` | 人工可读报告 |
| `pf_data/document_manifest.json` | 全量文档元数据（最终路径 + 原出处） |
| `pf_data/reorganization_plans/*.json` | 各 L2 的清单片段（subagent 输出） |

## 回滚策略

1. 文件复制而非移动，原文件保留；
2. 所有操作前创建 Git 提交；
3. `reorganization_plan.json` 可用于一键清理已复制文件；
4. 若分类错误，修改分类规则后重新生成分类目录。
