## 1. 背景与目标

现有问答页是单文件、单会话、单条结果覆盖式页面，已经具备问答、Markdown、引用上标、来源、标错、登录注册、限频和配额处理。M（塔任务）14 原型验证了单栏消息流、文章式回答、紧凑来源卡片和底部输入区，但只做静态演示，未接后端。

本设计将问答页升级为多会话 SPA，保留原型“正文是视觉主角”的方向，同时补齐真实产品所需的历史恢复、账号归属、后台请求、引用快照和异常处理。

### 1.1 方案与原始需求对照

| 原始需求 | 最终设计 | 状态 |
|---|---|---|
| 单栏，不要固定左侧会话列表 | 默认 780px 单栏；历史使用临时抽屉 | 已确认 |
| 消息历史 | 多会话切换；每会话保留最近 20 轮 | 已确认 |
| 用户问题与 AI 回答分开展示 | 用户右侧浅色气泡，AI 全宽文章式回答 | 已确认 |
| 底部固定圆角输入框 | 自动增高多行输入，Enter 发送 | 已确认 |
| 引用紧凑且可核对 | 每轮默认 3 张来源卡片，支持展开与上标定位 | 已确认 |
| 保留标错、登录注册 | 每轮内联标错；居中登录/注册弹层 | 已确认 |
| 多设备与匿名使用 | 匿名本机可见，登录后按账号恢复并自动认领 | 已确认 |
| 来源可长期验证 | 每条助手消息保存当时完整引用快照 | 已确认 |

### 1.2 范围

本设计包含问答页、会话管理、账号入口及其所需后端接口和持久化改造。管理后台是独立页面，本设计只规定管理员入口，不设计后台内部功能。

## 2. 最终页面形态

### 2.1 视觉与布局

- 只做浅色主题，不做暗色主题和主题切换。
- 桌面主栏约 780px，居中，使用大量留白和柔和圆角。
- 顶栏左侧为简洁品牌标记、“PathFinder 1e 规则问答”和“历史”；右侧为“新会话”和登录/用户名菜单。
- 用户提问使用右侧浅色气泡，最长约占主栏 80%。
- AI 回答使用全宽文章式排版，不加回答卡片边框，不折叠超长回答。
- 宽表格保留表格结构，超出时在表格区域内部横向滚动，不撑宽整页。
- 来源原文始终完整展开，不做固定高度或内部滚动。

### 2.2 空会话

新会话展示一句简短欢迎和 4 个可点击示例问题：

1. 借机攻击在什么情况下触发？
2. 女巫 1 环法术有哪些？
3. 法师 20 级成长表是什么？
4. 肩部奇物有哪些？

示例覆盖规则、清单、成长表和装备查询。不展示原型中的伪造历史问答。

### 2.3 历史入口

- 桌面：左侧 320～360px 覆盖式抽屉，带轻遮罩，选择会话后关闭。
- 手机：全屏历史页层，提供明确返回入口。
- 历史列表包含新建、重命名、删除、置顶，不做搜索和手动排序。
- 会话分批加载，每批约 30～50 个，通过“加载更多”继续获取。
- 排序为置顶优先，其余按最近活跃倒序。
- 当前为空白会话时，再次点击“新会话”只留在当前空白页，不创建重复记录。

### 2.4 输入区

- 输入框固定底部，使用圆角容器和发送按钮。
- 使用自动增高多行编辑，约 6～8 行后内部滚动。
- Enter 发送，Shift+Enter 换行。
- 等待回答时允许继续编辑，但禁止该会话继续发送，不并发同会话请求。
- 不提供停止生成。
- 未发送草稿不持久化，切换会话或刷新即清空。

### 2.5 回答输出与操作

- 保留一次性完整响应，不引入正文流式输出。
- 等待时只显示真实状态“正在检索并生成回答…”，不按时间伪装检索/生成阶段。
- 每轮回答底部使用弱化操作行，显示一次短绝对时间、复制、重新生成、标错。
- 今天的时间显示时分，更早显示日期和时分。
- 复制内容为该回答的 Markdown 原文，保留引用编号。
- 重新生成只允许最后一轮，直接替换旧回答与引用，不保留版本。
- 标错入口为回答底部弱化文字链，点击后原位展开 5 类错误、正确说法和备注表单。

## 3. 引用展示

- 来源跟随每轮回答，不做全局汇总或固定侧栏。
- 默认展示前 3 张紧凑卡片，其余通过“查看全部 N 条”展开。
- 卡片展示编号、中文书名与缩写、完整目录路径和当时原文快照，不展示 chunkId 等技术字段。
- 点击正文上标时，自动展开来源列表和目标卡片，滚动到对应位置并短暂高亮。
- 数据缺口提示保留为当前回答下方的温和提示，不进入全局通知中心。
- 旧回答没有来源快照时显示“历史来源未保存”，不伪造来源。

## 4. 会话与账号规则

### 4.1 会话留存

- 界面与模型均只保留最近 20 轮，沿用现有裁剪上限。
- 每条助手消息完整保存当时的引用编号、书名、目录、正文快照和数据缺口标记。
- 首条提问成功后，会话才进入历史列表。
- 旧会话继续保留并降级展示；没有标题时取首条问题，没有来源时使用降级提示。

### 4.2 匿名与账号

- 匿名会话仍由服务端按会话 ID 限存 20 轮，供模型上下文使用。
- 匿名历史入口只在当前浏览器可见；本机保存会话 ID，不支持跨设备恢复。
- 登录后，当前浏览器提交的匿名会话自动认领至当前账号，并明确提示迁移结果。
- 登录用户按账号跨设备恢复会话，只在打开或刷新时同步，不做实时推送。
- 退出登录后，账号历史在本机隐藏并清除缓存；云端数据保留，下次登录可恢复。
- `pf.chat.memory=jdbc` 时提供完整的账号与跨设备能力。
- `pf.chat.memory=memory` 时仍提供同一套多会话和引用快照接口，但数据只在本轮运行有效，重启后清空；登录、匿名认领和跨设备同步不可用，页面明确显示“临时模式，重启后历史清空”，不回退维护旧单会话页面。

### 4.3 标题、置顶与删除

- 默认标题取首条问题的前 20～30 字，允许手动重命名。
- 置顶会话位于列表最前，其余按最近活跃排序。
- 删除需二次确认，确认后永久删除，不提供回收站。
- 删除当前会话后进入空白新会话。
- 进行中的会话也允许删除；晚到结果必须丢弃，不得重建已删除会话。

### 4.4 后台请求与阅读位置

- 等待回答时允许切换或新建会话，原请求继续后台完成。
- 历史列表为请求中的会话显示等待状态，为后台完成的会话显示未读点，打开后清除未读。
- 打开历史默认定位最新一轮。
- 用户回看旧消息时，新回答完成不强制跳转，只显示“有新回答”按钮。
- 多设备采用打开/刷新时同步，不处理实时协同编辑。

## 5. 登录、注册与后台入口

- 登录/注册使用居中弹层，不离开当前问答现场。
- 注册字段只有用户名、密码、确认密码，不增加昵称或邮箱。
- 忘记密码时提示联系管理员，不提供自助找回。
- 登录后使用用户名菜单；管理员看到“管理后台”和“退出登录”，普通用户只看到“退出登录”。
- 管理后台为独立页面，不嵌入问答抽屉。
- 问答因 401 中断时保留当前会话和问题；重新登录后回到原位置，由用户手动重试。
- 429 按原因区分：普通限频提示稍后重试；会话配额用完提供“新建会话”按钮。

## 6. 前端架构

### 6.1 技术栈

- Vue 3
- TypeScript
- Vite
- Pinia
- 自定义轻量 UI 组件
- marked＋DOMPurify
- Vitest＋Playwright

不引入 Vue/React 之外的整套 UI 组件库，不继续使用手写 Markdown 渲染器。

### 6.2 组件边界

| 组件 | 职责 |
|---|---|
| AppShell | 顶栏、账号入口、页面容器 |
| HistoryDrawer | 分批列表、置顶、重命名、删除、状态标记 |
| ConversationView | 当前会话、空态、历史定位、新回答提醒 |
| MessageList / MessageItem | 消息流、时间、回答操作、内联错误 |
| SourceCards | 来源卡片、展开、上标定位与高亮 |
| Composer | 多行输入、发送与等待状态 |
| FeedbackForm | 标错表单与提交状态 |
| AuthDialog | 登录、注册、确认密码与错误展示 |

Pinia 按会话保存消息、分页、请求状态和未读状态，并集中管理账号、匿名 ID 和认领流程。后台请求状态不依赖当前组件停留。

### 6.3 Markdown 与安全

- 模型回答先经 marked 渲染，再由 DOMPurify 按白名单消毒。
- 引用上标映射为当前消息内的组件交互，不通过未经约束的 HTML 字符串事件绑定。
- 来源原文始终按纯文本渲染。
- 表格、代码块和链接均使用明确白名单；外部链接使用 `rel="noopener"`。

## 7. 后端接口与数据流

### 7.1 会话接口

| 接口 | 用途 |
|---|---|
| `POST /api/conversations` | 创建空白会话并返回 ID；空会话不进入历史列表 |
| `GET /api/conversations?cursor=&limit=` | 登录用户分批读取账号会话，置顶优先 |
| `POST /api/conversations/lookup` | 匿名用户凭本机提交的一组 ID 分批读取会话 |
| `GET /api/conversations/{id}` | 读取会话及最近 20 轮消息与引用快照 |
| `PATCH /api/conversations/{id}` | 重命名或修改置顶状态 |
| `DELETE /api/conversations/{id}` | 永久删除会话及消息 |
| `POST /api/conversations/claim` | 登录后认领本机提交的匿名会话 ID |
| `POST /api/conversations/{id}/regenerate` | 重新生成最后一轮并替换助手消息 |

现有 `POST /api/chat` 与 `POST /api/chat/feedback` 保持复用。`POST /api/chat` 在调用模型前确保父会话存在；只有成功写入首轮问答后，会话才在历史查询中可见。

### 7.2 持久化扩展

`chat_conversation` 增加：

- `title`：可空，首轮后由首条问题生成；
- `pinned`：是否置顶；
- `owner_user_id`：可空，匿名会话为空，认领后写入账号 ID；
- 账号归属、置顶和最近活跃的查询索引。

`chat_message` 增加：

- `sources`：可空 JSONB，保存助手回答的完整引用快照；
- `gap_reported`：是否报告数据缺口，默认 false。

旧记录允许新增字段为空。现有 20 轮裁剪规则保持不变，裁剪消息时同时删除其引用快照。

### 7.3 写入与竞态

- 新会话先创建父行，再执行问答；失败且没有完整首轮的会话不出现在历史列表。
- 删除使用硬删除。历史写入不再对缺失父行执行自动重建；父会话不存在时，晚到结果直接放弃并记录告警。
- 同会话禁止并发展开新的问答或重新生成，不同会话可以并行。
- 重新生成只读取最后一轮用户问题，替换最后一条助手消息的正文、引用、缺口标记和完成时间，不增加累计轮数。
- 多设备读取以服务端最新提交结果为准，不提供实时锁。

## 8. 异常处理

- 问答失败在当前轮内联显示具体原因和“重试”，不写成普通 AI 消息，不污染模型上下文。
- 重试沿用原问题；只有成功后才写入完整问答和引用。
- 401 打开登录弹层并保留现场，登录后手动重试。
- 429 根据后端错误原因展示限频或配额分支。
- 历史读取失败显示可重试错误，不把“读取失败”伪装成“暂无历史”。
- 匿名认领失败保留本机 ID，允许重试，不静默丢弃匿名历史。
- 删除与晚到写入竞争时，以删除成功为终态。

## 9. 验收与测试

### 9.1 前端自动化

Vitest 覆盖：

- Pinia 会话切换、后台完成、未读状态与分页；
- 来源默认 3 张、展开全部、上标定位；
- 最后一轮重新生成与版本替换；
- 匿名 ID、认领、退出清缓存；
- 401/429、失败重试与表单状态；
- Markdown XSS 与来源纯文本渲染。

Playwright 覆盖桌面和手机：

- 空白欢迎与示例提问；
- 多会话切换、置顶、重命名和永久删除；
- 后台请求跨会话完成与未读提醒；
- 手机全屏历史页层和底部多行输入；
- 宽表格局部滚动、长回答和长来源完整展示。

### 9.2 后端自动化

JUnit 覆盖：

- 会话列表分页、排序、归属校验与匿名 lookup；
- 匿名认领、退出后的云端保留语义；
- 最近 20 轮消息与引用快照恢复；
- 旧消息空来源降级；
- 最后一轮重新生成不增加轮数；
- 永久删除与晚到写入不复活；
- 数据库迁移和 PostgreSQL JSONB 读写。

### 9.3 必过端到端场景

1. 匿名提问、刷新恢复、登录自动认领、另一设备读取、退出清本机缓存。
2. 多会话同时等待回答，切换后收到未读，返回查看完整消息与引用。
3. 超过 20 轮后，界面和模型均只剩最近 20 轮。
4. 旧会话无来源时明确降级，新会话来源快照完整。
5. 最后一轮重新生成只替换当前回答；历史轮不可重新生成。
6. 删除进行中的会话后，晚到结果不会使其复活。
7. 401 后手动重试，429 普通限频与配额分支正确。
8. 恶意 Markdown 和来源正文不能执行脚本。
9. 手机端历史、输入、来源展开和表格滚动可用。

完成标准是前端全量测试、Java 全量测试和真实浏览器验收全部通过，不以构建成功或单页截图代替功能验收。

## 10. 明确不做

- 不做暗色主题。
- 不做固定左侧会话栏。
- 不做会话搜索、手动排序、回收站和跨设备实时同步。
- 不做正文流式输出、虚假阶段进度和停止生成。
- 不做未发送草稿持久化。
- 不做任意历史轮重新生成、回答版本管理和单轮删除。
- 不做长回答折叠、来源原文限高。
- 不在本批次实现管理后台内部页面。
- 不扩展邮箱、昵称、自助找回密码。
