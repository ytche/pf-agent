# AKN-025 装备极值/排序类提问检索能力缺口 — 设计 Spec

- 日期：2026-11-11
- 状态：已实施并合并（M33 数据侧清单补全 + M35 Java price 排序/过滤）；2026-11-12 统一验收通过：medium-17 连续 3 次溯源/答案全对（力量法杖 235,000 gp），新增 medium-34/35/36 价格题全对，全量评测见 `docs/test-reports/测试报告_一期第二批五项问题验收_20261112.md`
- 来源：`docs/已知问题记录_agent.md` AKN-025；复跑证据 `/tmp/qa-medium-17-run1..3`（仓库外）

## 1. 问题与证据

medium-17「在 PF 装备数据中，可购买（有明确标价）的魔法物品里，价格最高的是哪一件？」
正确答案：力量法杖（Staff of Power）235,000 gp（CRB 法杖价格表）。

单题定向复跑 3 次，溯源 **3/3 全 0**，答案分别为 170,000 / 160,000 / 160,000 gp。
数据侧已核验完整：`equipment_page_222_0000` 存在（5769 字符，含 `力量法杖 | 235,000 gp | CRB`），
`equipment_page_220_0000` 存在。属检索/工具问题，非数据缺失。

### 三层根因（实施前复核确认）

1. **清单类别不全**：`equipment_lists.json` 2681 条，`component_type` 仅 gear(2428)/weapon(143)/armor(110)，
   **法杖/权杖/戒指/奇物等价格表类别条目数为 0**。清单路径不可能答出力量法杖。
2. **有 price 但不能排序**：`ListEntry` 已有 `price` 字段（1576 条有价），
   但排序仅支持 `name`/`book`，过滤字段仅 `componentType`/`slot`/`book`，模型传 `price` 被拒。
3. **表 chunk 截断**：`pf.search.entry-result-chars` 默认 8000，长价格表后半段取不到。

## 2. 已确认决策

| 决策点 | 结论 |
|---|---|
| 修复路线 | **清单补全 + price 排序**（不做纯表读取工具路线） |
| 覆盖范围 | **全部以价格表形式存在的装备类别**：法杖/权杖/戒指/奇物/药水/卷轴/魔杖等；书范围与现有清单一致 |
| price 口径 | 保留 `price` 原文；新增**可空数值字段 `price_gp`**；排序/过滤只用数值；解析失败不参与排序但条目保留，数量写入导出报告 |
| 接口形态 | **扩展现有清单查询接口**：`sortBy=price` + 升降序 + `price_min`/`price_max` 范围过滤；不新增专用工具 |
| 8000 截断 | **不同批**，另记独立项；排序后极值/区间问题不再依赖读整表 |
| F-026 门禁 | **不加豁免**，由模型自行判断是否先给收窄建议；验收需观察该交互是否合理 |
| 验收 | medium-17 连跑 3 次须 3/3 溯源命中且答 235,000 gp；新增 2-3 道同类题进评测集；53 题全量无回退 |

## 3. 实施要点

### 数据侧（pf_data）

- 解析各书装备价格表，生成清单条目，`component_type` 新增类别值（命名沿用现有英文小写风格）。
- 每条目 `price` 保留原文，`price_gp` 为解析后的整数 gp；无法解析（`-`、空、非数值）时 `price_gp=null`。
- **条目的 `chunk_id` 必须指向其来源价格表 chunk**（如 `equipment_page_222_0000`），否则溯源口径仍不命中。
- 无标价条目（神器等）保留条目但不参与排序；答案口径为“有明确标价条目的最高价”。
- 导出报告新增：新增类别条目数、`price_gp` 解析成功/失败计数与失败样本。

### Java 侧（pf_agent/agent）

- `ListExportService` / `FilterTranslator`：装备模块排序字段开放 `price`（映射 `price_gp`），支持升/降序；
  过滤新增 `price_min`/`price_max`（数值，单位 gp）。
- 排序时 `price_gp=null` 的条目排在最后且不计入“最高价”结论。
- 旧版清单文件无 `price_gp` 时的降级行为需明确（拒绝排序并提示，或回退现有排序），不得静默给出错误排序。
- 工具描述需写清：价格字段可用、单位 gp、仅统计有标价条目。

## 4. 不做

- 不改 8000 截断配置，不做表格 chunk 按行拆分。
- 不改 F-026 门禁规则，不加排序查询豁免。
- 不新增“最贵 N 件”专用工具。
- 不处理其他模块（法术/专长等）的数值排序，除非实施中发现同一机制可零成本复用。

3. medium-17 连跑 3 次：溯源 3/3，答案 235,000 gp。
4. 新增 2-3 道同类题（最贵戒指、指定书最贵法杖、价格区间）入 `pf_qa_items.json` 并通过。
