# Java ↔ 数据侧 数据偏离与技术债务登记

建立：2026-09-18（用户指令，SP8 收尾）

## 治理原则

1. **数据侧输出 = Java 侧输入**。Java 侧（含启动器、工具、脚本）不得对数据做再加工后使用；
   任何"Java 侧实际消费的数据"与"数据侧 pipeline 产物"之间的偏离都是技术债务。
2. 偏离事件**必须登记**：产生时间 / 原因 / 处理方式 / 临时处理的产物位置 / 清偿计划。
3. 修补类处理（重放、补丁、手工修库）只是临时止血，**必须挂清偿计划**；正道是数据侧
   修产物 + Java 侧重灌（从 chunks.jsonl 重新导入，embedding 重算也在所不惜时走重灌）。
4. 禁止 Java 侧的加工逻辑倒排影响数据侧（如"反正 Java 会补"而放松数据侧产物质量）。
5. 每个 SP 收尾时回顾本表，能清偿的当场清偿。

## DVG-001：元数据重放工具成为 Java 侧常驻第二写路径

- **产生时间**：2026-08-01（commit `f41cb58`「SpellChunkMapper 扁平化 + 方案 B 元数据重放工具」，
  `f185a3a` 接入 CommandLineRunner）。
- **原因**：SpellChunkMapper 把 school 等键扁平化后，已部署的 `~/.pf_agent/vector_store_spells.json`
  还是旧 metadata 结构；重算 embedding 成本高（当时数小时级），于是造了
  `SpellMetadataReplayTool`——Java 启动时用当前 mapper 重新生成 metadata 直接改写本机向量库。
- **处理方式**：Java 侧工具事后修补本机向量库（非数据侧产物重生）。
- **临时产物位置**：`~/.pf_agent/vector_store_spells.json`（本机，git 外）。
- **债务本质**：向量库从此有**两条写路径**（数据侧重灌 / Java 侧重放），且重放是
  "Java 用代码逻辑再加工数据"的直接体现。2026-09-18 重放幂等逻辑改为逐条比对后，
  又暴露 AKN-011（整表替换会抹掉 mapper 之外的键，如未来 Layer 1 的 entry_links）。
- **清偿计划**：向量库重灌全量化——Java 启动导入一律以数据侧 chunks.jsonl 为唯一事实源；
  重放工具退化为一次性迁移手段，每次使用后在本表登记；Layer 1（F-017）立项时
  先解决 AKN-011 再允许 entry_links 入库。

## DVG-002：base_spell_* 三字段 Java 库缺键（SP8c 修复 + 重放 257 条）

- **产生时间**：字段缺失自 2026-08（SpellChunk record 白名单漏带）即存在，2026-09-18 SP8c 查明并修复。
- **原因**：数据侧 chunks.jsonl 的法术行顶层自 8 月起就带 `base_spell_chunk_id/title/book`，
  但 Java 侧 SpellChunk record 白名单未含这三字段，mapper 不透传 → Java 向量库 257 条
  变体法术缺引用链数据（"pipeline 产物有、Java 消费端没有"的典型偏离）。
- **处理方式**：修 record + mapper（正道）；存量库走 `pf.stores.metadata-replay=true`
  启动重放一次（修补路径），257 条写入、漂移 0、embedding 逐条比对零变化。
- **临时产物位置**：`~/.pf_agent/vector_store_spells.json`；重放前备份
  `/tmp/vector_store_spells_backup_20260918.json`。
- **清偿状态**：✅ 已对齐（2026-09-18）。后续 spell 库任何重灌应以数据侧产物为准重导，
  不再依赖重放维持一致性。
