## 背景与目标

当前法术链路为：

```text
原始 Markdown
  → formats/spell.py 标题与字段归一
  → split_into_items 按 **中文 (English)** 单行标题切分
  → processors/spell.py 提取 spell_level 等 metadata
  → spell_lists_union.json 派生清单
  → Java 向量库与检索工具
```

KN（数据侧已知）244 是标题碎片化的表层结果；KN（数据侧已知）246 是标题未识别后多个法术进入同一 chunk 的结构结果。二者会共同造成：

- 标题只剩 I/II/III/IV，检索、展示和 rescue 锚定失效；
- 多条目字段交错，spell_level 读到同 chunk 内其他法术的值；
- 真实法术没有独立 chunk，形成条目级丢失；
- 派生清单错值、缺项或被迫闸除。

目标是在**不修改原始 Markdown、不改 Java 检索逻辑、不改其他类目**的前提下，从 formats 标题归一层恢复正确条目边界，并让下游产物按既有规则自然恢复。

## 现状与实锤

### 1. 跨行名称被截成罗马数字

例：`page_1363.md` 的 `【变化】(变形)虫类型态` 与下一行 `I(Vermin Shape I)` 被归一为独立的 `**I (Vermin Shape I)**`，中文基名留在前一条目。

KN（数据侧已知）244 历史登记为 52 条；2026-10-29 当前产物实测为 46 个纯罗马数字标题。实施时必须合并“历史 52 条清单”和“当前 46 条实测”建账，不得只修当前抽样。

### 2. 中文子学派括号被误当英文名

`page_1166.md:180`：

```text
【咒法】藏密箱(召唤) (Secret Coffer)
```

当前生成 `**藏密箱 (召唤)** (Secret Coffer)`，不符合 split 的单行标题约束，藏密箱并入和平联系并造成环级串值。

### 3. 译者注清理误删真实标题

`page_805.md:186` 的“隐藏武器”标题与 `◎[隐藏武器]译文来自笨哈` 同行。`_strip_translator_notes` 的整行删除规则将该标题一并删除；实现与“无 `【` 才整行剥离”的注释不一致。

### 4. 章节和下一法术标题粘连

`page_1008.md:95-97` 的“半影法术”章节介绍与“起舞于黯”标题粘连，导致起舞于黯未独立切分。

**基线勘误**：半影法术在该源文件中是章节名，不应恢复为法术条目；KN（数据侧已知）246 丢失清单中的正确对象是起舞于黯等真实法术。

### 5. 当前保守护栏的代价

- QA-K1 的 12 条拒填 = 6 条旧错值净除 + 6 条正确值被保守误伤；标题修复后须逐条恢复并回源核对。
- union 中 38 条污染标题 derived 当前被闸除；标题修复后应以完整名称重新进入派生清单。
- KN（数据侧已知）245 另有不回流的 12 条垃圾串，不能与上述 QA-K1 的 12 条混为一谈。

## 结构不变量

修改前固定以下不变量，并在测试和 verify 中分别断言：

1. **标题**：一个真实法术 chunk 必须有完整中文标题和对应英文名；不得为 I/II 等无语义碎片。
2. **边界**：一个 chunk 只承载一个法术条目；章节介绍不得伪造为法术。
3. **归属**：每个字段和正文段只能归属其源标题下的法术，不得跨条目串值。
4. **正文**：除既有译者注/链接清洗规则外，修复前后不得丢失规则正文。
5. **来源**：非目标 chunk 的 book、toc、source 等 metadata 不变。
6. **范围**：只改 spell formats、对应测试/verify 和下游产物；原始 Markdown、其他类目和 Java 检索逻辑不动。
7. **可复现**：同一输入连续两次构建，全部 spell 产物字节一致。

## 方案设计

### R1 基线与全量影响账单

先快照：

- `vectorizer/output/法术/chunks.jsonl` 和 `index.json`；
- `spell_lists.json`、`spell_lists_union.json` 及两份报告；
- 当前 pytest、spell 四步链和 53 题评测基线。

建立机器可复核的受影响清单，至少包含：源文件、源标题片段、旧 chunk_id、旧标题、应有标题、旧 spell_level、源行应有 spell_level、问题族、预期处置。

账单来源取并集：

- KN（数据侧已知）244 历史 52 条和当前纯罗马数字标题实测；
- KN（数据侧已知）246 多等级标签 chunk 扫描及 tester 已实锤错值；
- `split_drop` 告警和当前无独立 chunk 的源标题；
- QA-K1 的 12 条拒填和 union 的 38 条标题污染闸除项。

多等级标签只是审计信号，不直接等同于错误；合法残留须逐条定性。

### R2 formats 标题归一修复

所有影响标题完整性的规则放在 `_pre_unify_text` 快照和 `split_into_items` 之前完成；字段正文仍走现有归一链。保持 `split_into_items` 的单一标准标题匹配逻辑，不增加第二套切分器。

按格式族实现小而有守卫的规则：

1. **跨行完整标题**：合并中文基名、罗马数字/后缀和英文名的跨行组合；要求后续存在法术字段块，且英文与中文标题结构同时成立。
2. **中文子学派 + 英文名**：识别中文名后的中文括号与后续英文括号，不再把中文子学派当作英文名；学派/子学派语义沿用现有解析口径，不新增 schema。
3. **译者注同行标题**：支持“译文引自/译文来自”等已观察前缀；只剥译者注，保留 `【学派】` 标题。含 `【` 的行禁止被纯注释整行删除规则吞掉。
4. **章节与标题粘连**：章节名转为章节边界或保留为前文，真实法术标题另起一行；不得把“半影法术”等章节名产出为法术 chunk。
5. **跨行英文与标题后缀组合**：覆盖英文名折行后同时带描述符、译者链接等已登记形态；不能为修一个样本放宽成任意行内括号匹配。

通用规则优先，禁止 `if title == "藏密箱"` 之类条目名特判。若个别残留无法安全泛化，停止扩正则并回源审查；只有确认属于无法复用的源格式异常时，才另提格式类源文件修复清单。

### R3 TDD 与负向护栏

每个格式族先写真实源样本测试，再实现：

- 正例：虫类型态 I–IV、撕扯肢体、精神蛀虫、藏密箱、隐藏武器、起舞于黯、弧焰击及 tester 三例错值。
- 负例：正文中的罗马数字、普通括号字段、纯译者注、章节名、合法跨行字段、正常含 I/II 的完整标题。
- 边界：首个和最后一个条目、连续多个同族标题、标题后缺字段、同源重复文件。
- 既有 QA-K1 两级守卫保留，不因标题修复而删除；union 的污染标题闸也保留，正常标题修复后自然通过。

### R4 全库 diff 与源行核对

修复后按 chunk 对齐并输出白名单化 diff：

- 标题、文本、chunk 数、component_type、book/toc/source、spell_level 分开统计；
- 新增、删除、标题变化、边界变化、仅 metadata 变化分别列账；
- 所有非预期变化均为阻断项；
- 被吞条目必须能从源 Markdown 定位并恢复，章节名不得进入恢复清单；
- 为旧新 chunk_id 建立映射，供评测锚点、来源引用和人工复核使用，不强行保留错误旧编号。

### R5 两笔独立回流账

**QA-K1 12 条**：标题完整后，按现有 rescue 规则重算；6 条旧错值应变成源行正确值，6 条被误伤的正确值应恢复。逐条与 KN（数据侧已知）245 文档中的源行表核对。

**union 38 条**：重导派生清单，纯罗马数字标题不再出现；原闸除条目以完整标题和正确 chunk_id 回流，`diff_unclassified=0`。

**KN（数据侧已知）245 垃圾串 12 条**：继续执行排除和不自动回填。单独输出“标题修复后证据是否变化”的裁定清单，需改变排除状态时按既有内容审批纪律另行拍板。

### R6 原始 Markdown 格式登记

新增 `pf_data/phase1/docs/法术/原始Markdown非标准格式登记.md`，记录本批发现的格式族、真实源例、影响、pipeline 容错状态和未来源清洗建议，并登记到 `docs/项目文档总索引.md`。

该文档只承担长期记录，不代表本批开始清洗源文件。未来清洗必须遵守格式类/内容类源数据审批红线、锚定幂等和行尾保留规则。

## 备选方案与取舍

- **路线 A：formats 归一修复（采用）**。修根因，同源重复文件和未来同形态数据共同受益；代价是必须做全库回归。
- **路线 B：只修原始 Markdown**。代码回归小，但重复文件维护成本高，新数据会复发；仅作为无法泛化残留的后续备选，本批不执行。
- **路线 C：split 后二次拆 chunk**。标题和正文边界不可可靠恢复，容易形成第二套切分语义；不采用。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 跨行合并误吞正文 | 中文/英文双结构 + 后续字段块守卫；负例和全库 diff |
| 章节名被恢复成法术 | 章节负例；半影法术基线勘误；tester 回源复核 |
| 修一批错值又引入新错值 | spell_level 独立对账，rescue/union 原护栏不撤 |
| chunk_id 顺移破坏引用和评测 | 输出旧新 ID 映射；评测锚点逐项核对；向量库全量重灌 |
| 只修当前 46 条而漏历史样本 | 历史 52、当前实测、split_drop、KN（数据侧已知）246 扫描取并集 |
| 把 KN（数据侧已知）245 未批内容自动带回 | 两笔回流账分离，排除集不变，裁定清单单独审批 |
| 同源文件只修一处 | 使用形态规则而非路径/条目特判；对 page_1166/page_1365 等同源文件共同验收 |
