## 方案设计

### D1 新产物：`spell_lists_union.json`

- **路径**：`vectorizer/output/法术/spell_lists_union.json`（与 spell_lists.json 同目录平级）。
- **schema**（version 1.0）：
  ```json
  {
    "version": "1.0",
    "generated_from": "职业列表页 27 路径 ∪ chunks.jsonl spell_level（A 阶段清洗后）",
    "scope_note": "五书线 20 职业（清单页仅收 CRB/APG/UM/UC/ACG）；OA 五职业仅官方清单，不派生",
    "classes": {
      "<职业>": {
        "source_page": "...", "aliases": [],
        "levels": {
          "<N>": [
            {"cn","en","book","chunk_id","source":"official_list"}   // 清单页条目原样
            {"cn","en","book","chunk_id","source":"derived",
             "level_evidence":"spell_level: 女巫 1","matched_by":"cn|en|alias_whitelist"}
          ]
        }
      }
    },
    "excluded_classes": {"唤魂师":"OA 清单页跨 20+ 书，派生无收益","秘学士":"…","通灵者":"…","异能者":"…","催眠师":"…"}
  }
  ```
- 对 excluded 五职业：产物内仅含 `official_list` 条目（即官方清单原样透传），并显式标注 `derived: false` 原因——保证 Java 合并读取逻辑对 26 职业统一，不产生特例分支。

### D2 派生与并集规则

1. **聚合**：遍历 chunks.jsonl，对 `metadata.spell_level` 非空条目按 (class token, level) 展开（先 CLASS_NAME_NORM 归一、F3 已拆分）；class token 命中职业词表且该职业 ∈ 五书线 20 职业 → 生成派生条目候选。
2. **匹配键归一化**：cn 名归一（去空白、全半角统一）+ en 名 lower；译名变体过 **D4 白名单**（KN017 先例扩展：`植物凋零术↔植物凋零`、`共振↔共振术` 类；实施时从导出对账差异自动导出候选清单，**映射表待用户审批后入常量**）。
3. **并集**：清单页已有（归一化名命中）→ 不重复，保留 `official_list` 条目；清单页没有 → 加 `derived` 条目。
4. **冲突规则（D7）**：清单页与库侧同书但环级不一致 → **清单页权威**（保留 official_list 值），冲突写入对账报告 `conflicts` 节并登记 KN；同书同级但 chunk_id 不同（重复条目）→ 以清单页 chunk_id 为准，重复登记观察。
5. **边界**：spell_level 空条目不参与派生（10.1% 空率残留的直接体现）；KN246 3 例错值条目参与派生但对账报告中显式标注。

### D3 对账报告与"未归类差异=0"自动化

- 导出同时产出 `spell_list_union_report.json`：
  - `per_class_level`: 职业×环级 三列对账（清单页数 / 派生新增数 / 并集数）；
  - `diff_unclassified`: 归一化+白名单后仍无法并集的差异条目，**每条必须带 classify 标签**，合法标签枚举：`书范围外`（清单页五书外之书，如 COMP/CAMPAIGN/ARG——预期主类）、`译名变体`（入白名单审批流）、`标题污染`（KN244）、`条目合并`（KN246）、`环级证据缺失`（spell_level 空）——标签外差异数必须为 0，**cicd/导出脚本内硬断言**（diff_unclassified == 0 否则 FAIL），这是"未归类差异=0"验收口径的自动化落点；
  - `conflicts`: D7 冲突清单。
- 译名变体白名单未获批前，对应差异条目计入 `译名变体` 类不阻断；白名单获批后重跑归零。

### D4 译名变体白名单

- 常量入导出脚本（同 KN228/KN137 白名单纪律）：仅含获批映射；实施时从首轮对账差异自动导出候选清单提交审批，获批前不入常量。

### D5 build_manifest 登记

- 新增 `lists.spell_union` 步：kind=export_script、via=direct、`python3 spell_list_union_export.py`、inputs=[spell_lists.json, chunks.jsonl]、outputs=[spell_lists_union.json, spell_list_union_report.json]、schema 校验 version 1.0；与 `lists.spell` 相互独立（不合并步，保证 spell_lists.json 步零变化）。

### D6 Java 侧合并读取

- `getSpellList` 改为：读 spell_lists.json（官方清单）+ spell_lists_union.json（取 derived 条目）合并返回；返回结构对每条标注 `source`（official_list/derived）；excluded 五职业自然只有 official_list。
- **F-007 行为核对**：先读现有 getSpellList 实现与 F-007 用例，确认合并后返回条数增加不破坏现有断言（68→并集数的用例需同步更新为"≥实测并集值"，并在用例注释中固定口径）。
- **工具说明补充（D9）**：getSpellList 描述明确"五书线职业返回 清单页五书 ∪ 库侧派生（全库书范围）；OA 五职业仅官方清单（跨 20+ 书不派生）"——根治"Agent 把 68 条当全量"的诚实性问题。
- mvn test 回归；Java 侧读不到 union 产物时的行为：按现状（只返回官方清单）降级并 WARN，不 FAIL——保证产物缺失时工具可用（与数据侧产物解耦）。

### D7-D8 已知残留口径声明（写入产物 scope_note + Java 工具说明 + KN）

- 派生清单基于清洗后 spell_level，残留：10.1% 空率（约 420 条法术不在任何职业派生清单中）、KN246 3 例错值、KN244 52 条标题污染可能致派生条目标题失真——三者均在 union_report 的合法分类标签内可见，本批不修。

## 备选方案与取舍

- **甲：合并进 spell_lists.json**：单产物简单，但污染"官方清单"纯语义（拍板已否）。
- **丙：Java 侧实时 join chunks.jsonl**：免新产物，但 Java 侧承担归一/白名单逻辑，与数据侧单一权威原则相悖，且 KN017 归一逻辑重复实现会漂移。不选。
- **派生范围扩到 26 职业**：OA 五职业清单页跨 20+ 书，派生无收益且引入误并风险（KN233 先例）。不选（D6）。

## 风险与缓解

| 风险 | 缓解 |

| OA 五职业误并 | excluded_classes 显式排除 + 派生聚合前置职业词表∩五书线白名单双重过滤 + 单测 |
| 清单页与库同书环级冲突 | D7 清单页权威 + conflicts 登记 KN |
| KN246 错值/KN244 污染污染派生清单 | scope_note 声明 + 对账报告标注，不修（红线） |

| union 产物缺失致 Java FAIL | 降级 WARN 只返回官方清单 |
