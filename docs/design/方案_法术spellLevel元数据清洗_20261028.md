## 现状分析（实锤出处）

- **解析主路径**：`processors/spell.py` `infer_metadata`（:327-405）——`parse_fields(text)`（processors/parse_fields_common.py）提取原始值 → `_extract_spell_level(raw)`（:629-652，截尾部散文 + F3 复合职业 `/` 拆分）→ `SpellFormat.parse_spell_level`（formats/spell.py:1657-1709，`职业 N` 逐段解析）；失败 fallback `_infer_level`（:530-553，`**环位/等级：**` 两种格式正则）。
- **C 桶根因**：标签黏连使 parse_fields 值边界失效（M11 finding 1），环位原始值拿不到或截断 → 需 formats 层 fix_* 归一（先例：trait `****` 噪声容错，KN137 方案 R6）。
- **A 桶根因**：COMP/CAMPAIGN"未整理"书的法术列表条目，表头/上下文携带职业+环级但条目内无 `**环位：**` 字段行 → parse_fields 与 _infer_level 均无输入。机械回填的可复现落点 = processor `_extract_spell_level` 无值时新增**表头上下文 fallback**（仅当条目归属表的表头结构可机械判定职业+环级，判定规则不写条目名特判）。
- **脏职业名实测**（产物全库统计，本次实跑）：规范名高频值 = 术士/法师/女巫/牧师/吟游诗人/德鲁伊/先知/审判者/魔战士/奥能师/异能者/召唤师/游侠/圣武士/炼金术师/萨满/反圣武士/战斗祭司/催眠师/秘学士/歌者/通灵者/猎人/唤魂师/血脉狂怒者/调查员；脏名清单见 §审批表（含条数）。
- **门参数现状**：spell 段 `cicd/verify.py:165-186`（`--max-book-unknown 3` 等）；**无 spell_level 空率门**，本次评估新增（见 R8）。
- **冻结纪律**：spell 模块已解除冻结，但必须走 cicd 四步链（`--category spell`），禁止绕过（KN136 相关纪律）。
- **QA 基线**：`pf_agent/agent/qa/evaluate.py` 53 题，基线溯源 53/53、诚实 53/53，修复后不回退。

## 方案设计

### R1 标签黏连归一（优先实施，改动面最底层）
- 落点：`formats/spell.py`（fix_* 序列）+ `processors/parse_fields_common.py` 值边界归一，目标形态对齐既有 `**环位：**` 字段行。
- 纪律：幂等 fix_*、无条目名特判、正则锚定标签形态；seed 回归覆盖 C 桶 35 条代表形态。
- 验证：C 桶 35 条 spell_level 从空/残缺 → 解析出职业+环级，且全库已正确条目的 spell_level **零变化**（before/after 逐 chunk diff 白名单制）。

### R2 A 桶 560 条机械回填
- 落点：`processors/spell.py` `_extract_spell_level` 返回空时，新增表头上下文 fallback：由 formats 层在 split 阶段把条目归属表的表头（职业列/环级列结构）写入 item（如 `_table_context = {"class": …, "level": …}`），processor 消费之。
- 判定规则：仅接受**表头结构机械可证**的列表（列名命中职业词表/环级模式）；不满足则维持空（归入 D 桶口径），不写逐条例外。
- 范围护栏：仅 COMP/CAMPAIGN 未整理书 + 已批 560 条清单（实施时从 M11 桶清单导出，同 KN228 白名单模式）；清单外新发现可回填条目 → 停下报告。
- 验证：560 条逐条对账（职业+环级=表头值）；非 A 桶条目零变化。

### R3 职业名归一
- 落点：`_extract_spell_level` 输出后过归一表（模块级常量 `CLASS_NAME_NORM`）；归一只改 class 字符串，不动 level。
- Java 对齐点（必须同步列出）：
  1. `searchByMetadata` 的 `spell_level_<职业>` 过滤键：归一后旧脏键（如 `spell_level_炼金术士`）下若无残留数据则键自然消失；需 Java 侧确认无硬编码脏键引用。
  2. 向量库 metadata 重灌后，Java 侧按 spell_level 聚合的缓存/索引（如有）需重建——列入 DVG 登记。
  3. 建议 Java 侧对未知职业键的容错行为保持现状（透传不匹配），不因归一表新增特殊分支。
- 映射表见下节（逐条待审批）。

## 备选方案与取舍

- **B1'：裸环级全部按页上下文回填（B 桶 91 一起做）**：覆盖面大但违反"机械可证"原则，M11 高风险点，错标职业污染检索过滤。不选（R5）。
- **B2'：表头 fallback 做成独立一次性脚本**：产物不可复现，违反 build 重跑一致纪律。不选，落 processor/formats 层。
- **B3'：归一表放 config JSON 而非代码常量**：便于修订但引入新配置文件与审批面；180 条规模小，代码常量 + KN 登记足够。不选。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| next_field 放宽破坏现有正确条目（M11 标"风险最高"） | 不改全局边界语义；以"标签黏连 fix_* 归一到标准形态"替代放宽（R1）；before/after 全库 spell_level 逐 chunk diff，非白名单变化即 FAIL |
| 裸数字错标职业（B 桶，若强行做） | 本方案建议不做（R5），留 B1 带裁决 |
| MA 神话条目误抄 | A 桶白名单不含 MA 文档；回归对账确认 MA 条目 spell_level 零变化；若表头 fallback 误触发 MA 列表 → 该文档列入排除清单并在 KN 登记 |
| 归一误并（如 导师→通灵者 未经证实） | 不确定项（导师/红螳螂杀手）列"待确认"不动；映射逐条审批 |

| 53 题评测回退 | 评测纳入验收标准，溯源/诚实任一 <53 即阻断闭环 |
| 标签黏连 fix_* 误伤正文 | fix_* 锚定标签/星壳形态（KN137 R6 同纪律），seed 回归 |

### M1 C 桶窄路补救通道（精确落点）

- **根因**：`_unify_school_bracket_titles`（formats/spell.py:833）把 `【学派】(子学派)中文(EN)` 标题行归一，其正则尾部 `\s*(?:\*\*.*)?$`（:846-853）将同行紧跟的 `**等级：**职业 N` 标签部分一并吞掉 → parse_fields 拿不到等级行 → spell_level 空。
- **"空"判定落点**：processor `infer_metadata`（processors/spell.py:349-352）——`_extract_spell_level(raw)` 与 `_infer_level(item)` **均返回空**时触发补救；非空条目一律不进入补救通道（物理零变化的实现保证：通道入口即 `if spell_level: return`）。
- **原始文本来源**：formats 层 split 入口（formats/spell.py:223 调用 `_unify_school_bracket_titles` 之前）新增快照 `item["_pre_unify_text"] = text`。只加 item 内部键，不改任何既有输出字段；processor 补救通道消费该快照，键缺失则跳过（向后兼容）。
- **补救逻辑**：对 `_pre_unify_text` 用**修正后的单行正则**（标题行内 `【学派】…(EN)**等级：**…` 与 `【学派】…(EN) 等级：…` 两种黏连形态；不得改动 `_unify_school_bracket_titles` 本体）抽出行内等级段 → 走既有管线：`_truncate_trailing_prose` → `parse_spell_level` → F3 拆分 → `CLASS_NAME_NORM` 归一。产物形态与首轮一致（spell_level 数组）。
- **不回填约束**：解析结果全部 `class=None`（裸数字）→ 丢弃维持空（B 桶 91 条拍板不变）；含 `class!=None` 才回填。MA 文档（doc_id/文件名含神话/MA 前缀，以扫描清单为准）排除。
- **幂等性**：通道只在空值时写值，重跑产物不变；与首轮已修 52 条无交（52 条已非空，不进入通道）。
- **C 桶 35 条对账**：修复后 C 桶条目应有值且 == 源 md 行内等级证据；未找回的残余登记 KN242 更新小节。
