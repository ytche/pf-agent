## 背景与目标

SP8 批次（J1–J4/J6/J7）方案已拍板，唯独 J5（成长表查表工具）在 2026-09-17 方案中漏覆盖，仅登记需求。本方案补齐 J5 的 Java 侧设计。

数据侧 D3（`pf_data/phase1/class_table_export.py` → `vectorizer/output/职业/class_tables.json`）由另一 coder 并行开发中，产物形态见数据侧方案 §D3：职业 → 等级 → `{bab, fort, ref, will, special[], spells{环→次数|null}}`，顶层含 `version`/`coverage.parsed`/`coverage.missing`（缺失职业如实清单）。**本方案所有字段消费细节以 D3 实际产物为准**，Java 侧用 Jackson `@JsonIgnoreProperties(ignoreUnknown = true)` 容错（先例：SpellListService.java L230/L235/L251）。

目标：给 Agent 一个 `getClassTable` 工具，输入职业名+等级，直接返回 BAB/三项豁免/特殊能力/每日法术位；职业名支持别名；D3 未覆盖职业诚实返回并引导回退；LLM 侧 prompt 引导"数值成长类问题必须查表、不要自己算"。

## 现状分析

### 消费先例：SpellListService（`pf_agent/agent/src/main/java/com/pfagent/agent/rag/SpellListService.java`）

J5 的镜像先例，模式可直接复用：

- **加载时机**：`@PostConstruct load()`（L158–175）启动时同步加载 JSON；文件不存在 → warn + `available=false` 降级不炸启动；解析失败 → error + 降级。**J5 沿用，不引入懒加载**（数据文件 <1MB，启动加载成本可忽略；懒加载会给首次工具调用引入 IO 延迟与并发初始化问题）。
- **别名索引**：`buildAliasIndex`（L177–187）规范名自身 + 每职业 `aliases` → 规范名，`resolve()`（L67–76）返回 null 表未知。
- **溯源**：`listPageDocument()`（L136–155）由数据侧内嵌的 `source_excerpt` 构造合成 Document 交 SourceCollector。**J5 改用更优方案**（见下"溯源设计"），因为 D3 schema 只有 `source_chunk_id`/`source_doc_id`、没有 excerpt 字段。
- **工具包装**：`getSpellList`（RetrievalTools.java L454–480）——`isAvailable()` 检查 → 空参提示 → `resolve` 未知职业返回可用清单 → 命中后挂溯源。J5 工具方法完全对齐这个骨架。

### 工具面与注册（RetrievalTools.java）

- `@Component` + `@Tool` 方法，`ChatService` L141–145 `ToolCallbacks.from(retrievalTools)` 反射注册，**新增 @Tool 方法零注册成本**（SP8 方案已确认）。
- 工具方法返回字符串、命中走 `collector.add` 挂 [#N] 溯源、错误返回可读提示（类 Javadoc L22–24）。
- `EntryResolver`（L56）已对八模块 title/aliases 建索引，但**不适合做职业名归一**：它索引的是 chunk 条目名（职业特性/变体页），不是 D3 的 27 职业规范键空间，且职业 chunk 名噪音大（变体/进阶职业混在一起）。J5 职业名归一应走 D3/法术清单同款"职业规范键 + aliases"通道。

### Prompt 现状（PromptBuilder.java L17–39）

固定 system prompt，含工具引导、模块路由速查、[#N] 引用规则。SP8 方案已规划 J1/J2/J3/J6 引导追加点；J5 引导在此追加（属于"回答链路 prompt 变更"，触发评测重跑，见风险节）。

### 已知问题避让（docs/已知问题记录_agent.md）

- AKN-001：列举式提问须走直查工具而非 LLM 拼结果——J5 同型（数值类走查表工具）。
- AKN-003：LLM 编造施法方式——J5 的 `spells` 字段只给次数不给机制，prompt 引导中须声明"机制/规则细节仍走 vectorSearch"。
- 无与成长表直接冲突的既有 KN。

## 方案设计

### 工具定义

```
@Tool getClassTable(
  @ToolParam String className,   // 职业名：中文/英文/俗称/大小写混用，支持别名
  @ToolParam(required=false) Integer level)  // 等级 1~20；省略=返回全表（≤20 行紧凑表）
```

- **level 省略语义**：返回该职业 1–max_level 全表（D3 每职业约 20 行、每行 <80 字符，总量 <2K 字符，远低于 metadata-result-chars 4000 护栏；对齐 getSpellList 的"省略参数给概览"惯例，但成长表全表比"各环条目数概览"更有用，故省略=全表）。
- **level 越界**（<1 或 >max_level）：返回可读提示并附该职业等级范围（对齐 getSpellList L476–478 的越界处理）。
- **返回结构**（单行示例）：
  ```
  「法师」等级 5：BAB +2 | 强韧 +1 | 反射 +1 | 意志 +4 | 特殊：无
  每日法术：0环4、1环3、2环2、3环1（3环及以下取自表；字段以 D3 产物为准）
  ```
  - `bab` 保留 D3 原文（如 `+6/+1` 多攻形态原样返回，不展开——展开成几次攻击属规则解释，交 LLM 按 BAB 规则推导，J5 只做查表不做派生计算）；
  - `spells` 中 null（D3 以 `-`→null 表无该环位）显示为 `—` 或省略该环；
  - `has_spell_table=false` 的职业（如战士）返回"该职业无每日法术表"。
- **溯源**：见下节。

### 职业名归一

新建 `ClassTableService`（@Component，与 SpellListService 同包并列），别名解析两级：

1. **一级：D3 产物自身别名**。D3 承诺职业键归一复用 spell_list_export 的 `CANONICAL_CLASS`/`CLASS_ALIASES`（数据侧方案 §D3 第 3 点），即 `class_tables.json` 的 classes 键与 `spell_lists.json` 的 classes 键同一规范键空间。**若 D3 产物含 per-class aliases 字段则建自身别名索引**（同 SpellListService L177–187）；字段细节以 D3 实际产物为准。
2. **二级：复用 SpellListService.resolve() 兜底**。两个 JSON 同源同规范键，法术清单的别名覆盖（诗人/游吟诗人→吟游诗人、圣武士→圣骑士等，RetrievalTools L450 工具描述已声明）可直接借给成长表。实现：`ClassTableService` @Autowired SpellListService，`resolve` 先查自身索引、miss 后调 `spellListService.resolve()` 把规范名翻成 D3 键再查 classes。

- **大小写/空白**：resolve 前 `trim()`（对齐 SpellListService L71）；D3 键为中文，大小写问题主要影响英文别名——别名索引构建时对英文别名做 `toLowerCase` 双向登记（查询侧同样 lower 后查），中文不受影响。
- **兼职/变体职业**：**J5 一期不做兼职合成**（"我战士3级/法师2级 BAB 多少"需要按兼职规则合成，属规则计算非查表）。处理：用户问兼职时 LLM 应分别查各职业成长表后按兼职规则（vectorSearch 查兼职规则）自行合成——prompt 引导中写明这个分工。变体职业：D3 把变体职业的表归宿主职业键，别名索引若含变体名直接命中；不含时返回"该变体成长表未单独整理，其基础职业「X」的成长表为……"（用二级 resolve 的宿主名兜底查一次）。

### 数据源加载与容错

- **加载**：`@PostConstruct` 启动加载（同 SpellListService），配置 `@Value("${pf.class-tables.file-path:../../pf_data/phase1/vectorizer/output/职业/class_tables.json}")`——路径与 D3 方案产物路径对齐；若构建链任务（`方案_数据产物可复现构建链_20260918.md`）改变产物落点，集成时以 build manifest 为准修正默认值。
- **找不到文件/解析失败**：`available=false` 降级，工具返回"职业成长表暂不可用（class_tables.json 未加载），请改用 vectorSearch 检索职业成长规则"（对齐 SpellListService 降级语义，不炸启动）。
- **找不到职业**：
  - 名字能 resolve 但 D3 未收录（在 `coverage.missing` 里）：返回"「X」的成长表数据侧尚未整理（已登记缺失清单），可改用 vectorSearch 检索该职业成长规则原文，或确认后 reportDataGap"——**诚实返回，不编造**；
  - 名字无法 resolve：返回可用职业清单（`coverage.parsed` 排序后列举，对齐 getSpellList L465–467）。
- **找不到等级**：level 越界提示（见上）。
- **JSON 容错**：全部 record 加 `@JsonIgnoreProperties(ignoreUnknown = true)`；`spells` 缺失视为无法术表；单行字段缺失按 null 处理并在格式化时省略该段。

### 溯源设计

D3 每职业带 `source_chunk_id`（成长表所在 chunk）。**优先用真实 chunk 溯源**：`ClassTableService` @Autowired SearchService，命中职业后用 `searchService.getByChunkId("class", sourceChunkId)`（J1 已建此通路）取真实 Document 交 `collector.add`，前端溯源区直接展示成长表原文页——优于 SpellListService 的合成 excerpt 方案。chunk 点查未命中（向量库版本错位等）：降级为合成 Document（title=「X」职业成长表，metadata 带 chunk_id/doc_id，正文一句说明），保证 [#N] 不缺席；同时 warn 日志（提示数据侧产物与向量库版本错位，登记数据一致性技术债务清单的候选）。

### 与既有工具的分工边界

| 问题类型 | 走哪个工具 | 边界声明 |
|---|---|---|
| "法师 5 级 BAB/豁免/法术位多少" | **getClassTable** | 派生数值的唯一权威入口，prompt 禁止 LLM 自行按公式计算 |
| "法师 5 级有哪些法术可学" | getSpellList + vectorSearch | 清单枚举 vs 数值查表，不重叠 |
| "兼职 BAB 怎么算""高 BAB 职业有哪些" | vectorSearch（规则）+ getClassTable（取各职业原始值） | J5 不做合成计算 |
| 职业特性/变体规则细节 | vectorSearch/searchByMetadata/getEntryById | J5 只返回成长表行，不返回特性正文 |

### PromptBuilder 改动

追加一条引导（对齐 SP8 方案"PromptBuilder 改动点汇总"格式）：

> J5：涉及**职业按等级的派生数值**（BAB、强韧/反射/意志豁免、每日法术位、职业成长表任意一行）时**必须用 getClassTable 查表，禁止按公式自行计算**；机制解释（如"为什么法师 BAB 低""兼职怎么合成"）仍走 vectorSearch。变体职业成长与基础职业相同时可直接给基础职业表并注明。

新增工具 + 引导属于回答链路 prompt 变更 → **触发评测重跑**（口径：溯源 ≥52/53、诚实 ≥50/53、结构 ≥2.89）。

## 备选方案与取舍

1. **职业名归一复用 EntryResolver（J6）而非 SpellListService 通道**：不选。EntryResolver 索引的是 chunk 条目名（含变体/进阶/特性页，13922 条职业 chunk），不是 27 职业规范键空间；"法师"在 EntryResolver 里会命中多个 chunk（职业页/变体页/规则页），无法唯一映射到 D3 的 classes 键；而 SpellListService/D3 共享同一 CANONICAL_CLASS 规范键（数据侧方案 §D3 第 2 点承诺），归一正确性有数据侧常量背书。
2. **level 省略时返回"各段概览"（对齐 getSpellList）而非全表**：不选。成长表全表仅 ~20 行，直接给全表比概览更有用且字符安全；getSpellList 返回概览是因为单环清单可能数百条，成长表无此问题。
3. **把 BAB 多攻形态（+6/+1）展开成攻击次数数组**：不选。展开是规则解释（BAB≥6 才多攻等），属 LLM 按规则推导的活；J5 定位是"忠实查表"，原文返回最不易错。
4. **懒加载替代 @PostConstruct**：不选。文件 <1MB，启动加载毫秒级；懒加载引入并发初始化与首次调用延迟，违背 SpellListService 已验证的模式。
5. **兼职/变体合成内置进工具**（如 className 传多个）：不选。兼职合成是规则计算不是查表，且"法师5级/术士5级"这类提问等级结构多样（逐职业等级、总等级），参数对象会膨胀；一期由 LLM 查表+查规则自行合成，若 tool_calls 数据显示高频再立项。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| D3 并行开发中，schema 细节可能微调 | Jackson ignoreUnknown 全容错；字段缺失降级省略不报错；集成前以 D3 实际产物对齐 record 定义；产物路径以构建链 manifest 为准 |
| D3 覆盖率缺口（一期约 20 标准职业）导致用户问到未覆盖职业 | coverage.missing 驱动诚实返回文案；不编造；引导 vectorSearch 回退；缺口随数据侧迭代收窄后自动生效（重启加载） |
| 新增工具 + prompt 引导 → 回答链路变化 | 触发评测重跑（溯源 ≥52/53、诚实 ≥50/53、结构 ≥2.89），随 SP8 评测批同跑 |
| `source_chunk_id` 与向量库版本错位（先例：F-002 ② spell store 旧版错位 2015 条） | 点查未命中降级合成 Document + warn 日志；观察错位率，高则登记数据一致性技术债务 |
| LLM 把机制问题也丢给 getClassTable（如"先攻怎么算"） | @Tool description + PromptBuilder 双向声明边界（只查 BAB/豁免/法术位/特殊能力行） |
| 职业名二级兜底（SpellListService.resolve）引入跨产物键不一致 | 两产物同源于 CANONICAL_CLASS 常量；兜底 miss 时按未知职业处理返回清单，不硬匹配 |
| 神话阶层（Mythic）成长不在 D3 一期 | 诚实返回未覆盖；神话 BAB/豁免加成走 vectorSearch；二期评估 |
| 测试基线 287 | 新增单测只增不减；不改既有断言 |

## 待拍板问题

1. **工具名**：`getClassTable`（对齐 D3 产物名 class_tables）vs `getClassProgression`（语义更直白）。推荐 getClassTable。
