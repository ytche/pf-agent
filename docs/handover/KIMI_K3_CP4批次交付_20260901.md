## 三、CP4-1 Java 侧迁移

### 3.1 ProfessionChunkMapper（组合复用，非复制）

```java
@Component
public class ProfessionChunkMapper implements ChunkMapper<StandardChunk> {
    @Autowired
    private StandardChunkMapper baseMapper;   // @Autowired 字段注入（约定，禁构造器注入）

    @Override
    public Document toDocument(StandardChunk c) {
        Document doc = baseMapper.toDocument(c);          // 统一映射（来源书/tocPath/title）
        Map<String, Object> meta = doc.getMetadata();
        Map<String, Object> nested = c.metadata() == null ? Map.of() : c.metadata();
        putNonNull(meta, "class_name", nested.get("class_name"));
        putNonNull(meta, "archetype_name", nested.get("archetype_name"));
        putNonNull(meta, "feature_subtype", nested.get("feature_subtype"));
        return doc;
    }
    // private putNonNull 与 StandardChunkMapper 同口径
}
```

- 扁平键 `class_name`/`archetype_name`/`feature_subtype` 即 `FilterTranslator.translateClass`（:95-110）
  结构化过滤的目标键——扁平后职业库 Document 直接可过滤，**FilterTranslator 零改动**。
- 缺省键经 putNonNull 跳过（Spring AI Document 不接受 null value），与各模块 null 兜底一致。

### 3.2 单测（3 用例，含 k3 要求的 null 变体）

| 用例 | 覆盖 |
|---|---|
| `toDocumentFlattensProfessionFieldsKeepingBaseMapping` | 三字段全有：扁平键 = nested 值；基础映射（book/tocPath/title/aliases）保留 |
| `toDocumentNullMetadataSkipsProfessionKeys` | metadata 为 null：三扁平键全部不出现（null 变体①） |
| `toDocumentPartialMetadataSkipsMissingKeys` | 仅 class_name（overview/基础 feature）：缺失键安全跳过（null 变体②） |

测试注入经 `ReflectionTestUtils.setField(mapper, "baseMapper", new StandardChunkMapper())`
（项目既有模式，SearchServiceTest 同款）。
