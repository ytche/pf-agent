## 2. 实现要点（对照方案 D1~D7）

### D1 · 单一组合 Bean `queryEmbeddingModel`（`config/EmbeddingConfig.java`）

- 新增 `@Configuration EmbeddingConfig` 产出 `@Bean EmbeddingModel queryEmbeddingModel`；VectorStoreConfig 8 store 全部改指它。
- 消费方（TruncatingEmbeddingModel / SimpleVectorStore）对通道细节完全透明；3 个 EmbeddingModel 候选的注入歧义靠这一处消解。

### D2 / D6 · 通道链矩阵（在 Bean 方法内按字段决策）

| primary | fallback-enabled | cloud api-key | 行为 |
|---|---|---|---|
| ollama（默认） | false（默认） | 不需要 | **裸主通道返回**（同实例，零包装、无 cloud 装配、无自检、无网络新增） |
| ollama | true | 必需 | `FallbackEmbeddingModel(ollama, cloud)`，本地挂降云端 |
| cloud | **未显式 → 默认 true** | 必需 | `FallbackEmbeddingModel(cloud, ollama)`，云端挂降本地 |
| cloud | false | 必需 | 裸 cloud（托管极简部署） |

- `fallbackEnabledRaw` 存 **raw String 三态**（`@Value("${pf.embedding.fallback-enabled:}")`）——显式 true/false 直用；空串（未显式）按 D6：primary=cloud 默认 true、ollama 默认 false。规避「yml 样例写 false / D6 却要 cloud 默认 true」的歧义（设计 §3 风险已注明）。

### D3 · 云通道装配 + 校验

- 手工 `new OpenAiEmbeddingModel(new OpenAiApi(baseUrl, apiKey), MetadataMode.EMBED, OpenAiEmbeddingOptions.builder().model(model).build(), retryTemplate)`——**独立于 `spring.ai.openai.*`**（那是 DeepSeek chat 的 base-url）。
- retryTemplate 经 `ObjectProvider<RetryTemplate>`（`@Bean` 工厂方法参数注入，允许边界）；无 bean 时走 3 参构造器。
- cloud 参与（主或备）而 base-url / api-key 为空 → Bean 装配期 `IllegalStateException` fail-fast，错误提示点名 `PF_EMBEDDING_CLOUD_API_KEY`（env 注入、严禁入库）。**不静默回退**。
- 真机实测注记：Spring OpenAI 客户端对本通道 POST 走 **chunked 传输（无 Content-Length）**——V5 stub 初版按 Content-Length 读体返回 400（`Expecting value at char 0`），改支持 chunked 后即通。属验证基建适配，非应用缺陷。

### D4 · FallbackEmbeddingModel（`config/FallbackEmbeddingModel.java`）

- 覆写面与 `TruncatingEmbeddingModel` 一致：`call / embed(Document) / embed(String) / embedForResponse / dimensions`，任意入口都被兜底包裹。
- 逐次调用降级、无状态无熔断：`withFallback(() -> primary.X(), () -> fallback.X(), op)` 主成功直传（零开销）；主挂记一条 WARN（含主/备通道名 + 异常摘要，**不含任何 key/token**）后走备；双挂备通道异常原样上抛。
- `dimensions()` 委托主通道（不触发备探测）；维度一致性由 D5 启动自检保证。

### D5 · 启动维度自检（Bean 方法内、cloud 参与时）

- 建好 cloud 后执行一次 `cloud.embed(DIMENSION_PROBE_TEXT="维度探测")`，断言返回长度 == `BGE_M3_DIMENSIONS=1024`（常量注明出处：8 个 `vector_store_*.json` 均由本地 bge-m3 构建）。
- 不符 → `IllegalStateException` fail-fast，错误提示「模型一致性约束：换模型=重建向量库，请确认 model=BAAI/bge-m3」，防「向量库 1024 维 / 云通道异维，检索全废但服务照起」。

### D7 · 观测

- 启动日志打印生效通道链：`embedding 通道链: primary=ollama（默认单通道，fallback 未启用）` / `primary=cloud[BAAI/bge-m3], fallback=ollama` 等。
- 每次降级一条 WARN（D4 `withFallback`）。不进 metrics（本批无设施先例）。

## 7. 遗留与披露

1. **真实云通道一致性抽查未跑**：V5 加跑项（真实硅基流动 key：主通道问答 + 同问题两通道结果一致性抽查）需用户提供 key。已由 stub 覆盖装配/校验/维度自检/兜底全部机制；真实云端数值一致性（同 bge-m3 权重，浮点级差异）属方案已声明风险。
2. **首次建库走同一通道链**：SimpleVectorStore 逐条 embed，云端首建慢（方案非目标已登记）——建议建库仍在本地 Ollama。
3. **Spring OpenAI 客户端 chunked 传输**：真机发现其 POST embeddings 无 Content-Length（chunked）。真实服务端天然兼容；仅影响自建 HTTP 观测/桩需支持 chunked。非缺陷。
4. **运行产物不入库**：`qa/out_sp5*`（评测输出）受 `.gitignore` 覆盖，未提交；可删除再生。
5. **降级不告警**：fallback 每次降级仅 WARN 日志留痕，未接告警设施（本批无观测设施先例，方案 §5 已声明）。
6. **未自行合并**：`feat/sp5-embedding-dual` 停在 T1~T3 + 本文件，交 k3 验收、用户拍板后合并。
