## 3. ⚠️ 重大发现：AKN-008（你设计之外，修法 A 生效的隐蔽阻塞）

T4 中测溯源不升反降（46→44）时定位到：**修法 A 本身已工作**（`{title:"法力再生珍珠"}`、`{title:"防护邪恶"}` 调用成功返回命中），但**锚点仍进不了 `sources[]`**。根因在 `SourceCollector.drain()`：

### 机理

- 各模块 mapper 写入的 `doc_id` 是**页面级**：equipment `page_234`、rule `page_127`、spell **`Spell CRB`（全书共享）**、class `核心职业/盗贼/page_49.md`（一页最多共享 **327** chunks）。
- `drain()` 原按 `doc_id` 去重（`LinkedHashMap` + `putIfAbsent`）→ **同一页面多个 chunk 只保留先到者**。
- `vectorSearch` 先返回同页邻居（如 page_234 的 `_0268`），`searchByMetadata` title 过滤后精确命中锚点（`_0179`）再 add → 被 `putIfAbsent` 丢弃。
- 前端溯源判分按 **`chunk_id`（chunk 级，唯一）** 匹配 → 锚点落空。

### 为什么 P0-B 时代不显性

P0-B 时锚点多由 `vectorSearch` top1 返回、作为**首个 add** 被保留；修法 A 开放 title 过滤后，「精确命中锚点但晚于同页邻居 add」成为常态（medium-4/20/21 皆此），bug 全面暴露。**对 class 模块影响最深**（doc_id 一页共享最多 327 chunks，折叠区此前每页只留 1 个）。

### 修复（最小改动）

`SourceCollector.drain()` 去重键 `doc_id` → **`chunk_id`**（缺失回退 `doc:` + doc_id 防 null 合并），去重粒度与 `toSourceRef` 的溯源口径（`chunk_id`）对齐。测试：`beginAddDrainDeduplicatesByDocId` → `ByChunkId`（同 doc_id 不同 chunk 全保留）+ 缺 chunk_id 回退用例；全量 157 测试全绿。
