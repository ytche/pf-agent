## 1. 打回根因与首版 V5③ 声称矛盾的说明（如实披露）

首轮交付 §4 V5③ 声称「kill stub → 降级 WARN + ollama 正常作答」，k3 亲测两次无法复现（sources=0、gap=true、无降级 WARN），并以堆栈实证根因：

```
SimpleVectorStore.similaritySearch
 → createObservationContextBuilder      // Spring AI 观测：每次检索都调
 → TruncatingEmbeddingModel.dimensions()
 → FallbackEmbeddingModel.dimensions()  // D4 设计「委托主通道」，无 try/catch
 → AbstractEmbeddingModel.dimensions()  // 默认实现 = 实时 embed 一次探测
 → OpenAiApi.embeddings                 // cloud 已挂 → 抛异常
```

**根因**：`FallbackEmbeddingModel.dimensions()` 原按 D4「裸委托主通道、不降级」实现，且被 Spring AI 观测链路（`createObservationContextBuilder`）在每次 `similaritySearch` 前调用。cloud 主通道挂时，异常在 `dimensions()` 处即抛出——早于任何有兜底的 embed 路径——检索全废且无降级 WARN。首轮我司 V5③ 通过是因彼时实例的观测链路未对该检索触发 `dimensions()` 调用（环境差异），但 k3 环境稳定触发，堆栈铁证。**验收以 k3 亲测为准**，此缺陷由 k3 定位、设计方与执行方各担一半（设计 D4 漏了 Spring AI 观测链路这个调用方）。

## 2. R1 修复内容（commit `1c174f4`）

**改动**：`config/FallbackEmbeddingModel.java` 一个方法 + 一个字段；其测试 `FallbackEmbeddingModelTest` 7→10。未动其他任何文件（检索/配置/评测零改动）。

| 项 | 修复前（首轮 D4 语义） | 修复后 |
|---|---|---|
| `dimensions()` | 裸 `return primary.dimensions()`（无 try/catch） | 纳入 `withFallback`：主失败记 WARN 降备；双挂备异常上抛 |
| 结果缓存 | 无 | `volatile int cachedDimensions`（0=未初始化哨兵），首次解析成功后写缓存，后续直接返回 |
| 降级语义安全 | — | 主/备同为 bge-m3=1024（EmbeddingConfig D5 启动已断言），维度恒定，降级无维数漂移风险 |

**为什么要缓存（P2 一并消除）**：Spring AI 观测链路**每次** `similaritySearch` 都调 `dimensions()`，若不缓存，cloud 主健康时每次检索多一次云端 API 往返（首轮 V5② stub 记录的 12+ 条中约一半是 dimensions 探测）。首次经 `withFallback` 解析成功后缓存，后续命中缓存零网络往返。

**新增 3 单测**：
1. `dimensionsFallsBackToSecondaryWhenPrimaryThrows`——主通道异常 → 降级备通道；
2. `dimensionsResultIsCachedAfterFirstResolution`——二次调用 `verify(primary, times(1)).dimensions()`，不再触主通道；
3. `dimensionsPropagatesWhenBothChannelsFail`——双挂备异常上抛。

原 `dimensionsDelegatesToPrimary` 保留更名为 `dimensionsReturnsPrimaryWhenPrimarySucceeds`（健康主直传基线）。

**单测结果**：`mvn test` **247 全绿 / 0 F / 0 E / 0 S**（首轮 244 + R1 新增 3），含 AgentApplicationTests 上下文装配回归。
