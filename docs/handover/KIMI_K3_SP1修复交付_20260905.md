## 3. 冒烟自跑新发现的 FK 缺陷（验收范围外，真 PG 兜底暴露）

**现象**：首次自跑冒烟（jdbc 模式）提问成功返回，但 PG 查 `chat_message` 空。日志：
`SQLState: 23503 — insert or update on table "chat_message" violates foreign key constraint "chat_message_conversation_id_fkey"`，随后 `JdbcChatMemory` warn「历史写入失败…不落库」按 D6 降级（主链路未断）。

**根因**：`JdbcChatMemory.doAdd` 中消息 `saveAll(rows)` 时 FK 指向的会话父行尚未持久化——父行要到最后 `conversationRepository.save` 才落库。生产 V1 schema 有 `chat_message.conversation_id → chat_conversation.id` 外键，故违反。

**为何单测没拦住**：与 P0 同源——`@DataJpaTest` 关 Flyway 后由 Hibernate 按实体 create-drop 建表，实体间是普通列关联（无对象 @ManyToOne），Hibernate 不生成外键 → H2 无 FK，先插消息不报错。这**正是上一轮交付文档 §6 预留的「H2 与 PG 方言差异、测试库与生产 schema 不一致」风险面**，本批冒烟按要求自跑才将其兜出。

**修复**：`doAdd` 的新会话分支改为 `orElseGet(() -> conversationRepository.save(new ChatConversationEntity(...)))`——新会话先落父行，消息再插入时 FK 即有引用。已存在会话走 findById 不受影响。语义不变（仍同一事务、仍窗口制裁剪），行为零变化。

**验证**：修复后重跑，提问正常落库 [user, assistant] 两条 + 会话行 message_rounds=1（§4.2），真 PG 上 FK 通过。
