## 三、发现的问题

### P0（阻塞，必须修复）：`dimensions()` 无兜底，真实检索链路 fallback 失效

**现象**：cloud 主通道挂掉后，`vectorSearch`/`searchByMetadata` 全部抛 `ResourceAccessException: I/O error on POST .../v1/embeddings`，Ollama 兜底未触发，无降级 WARN。

**根因**（堆栈实证）：

```
SimpleVectorStore.similaritySearch
 → createObservationContextBuilder          // Spring AI 观测：每次检索都调
 → TruncatingEmbeddingModel.dimensions()
 → FallbackEmbeddingModel.dimensions()      // D4 设计「委托主通道」，无 try/catch
 → AbstractEmbeddingModel.dimensions()      // 默认实现 = 实时 embed 一次探测
 → OpenAiApi.embeddings                     // cloud 已挂 → 抛异常
```

`dimensions()` 在 `embed()` 之前被调用且不走 `withFallback`，异常在这里就炸了，根本到不了有兜底的 embed 路径。**设计 D4「dimensions 委托主通道不降级」在真实调用链下不成立**——这是设计层面漏了 Spring AI 观测链路这个调用方，设计方（k3）与执行方各担一半。

**修复要求（R1，k3 设计）**：
1. `FallbackEmbeddingModel.dimensions()` 纳入 `withFallback`（主失败 → 备）。两通道同为 bge-m3=1024（D5 启动已断言），语义安全。
2. **结果缓存**：`dimensions()` 结果被 Spring AI 观测链路**每次检索都调用**（V5② stub 记录 12 条中约一半是 dimensions 探测）——primary=cloud 健康时这意味着每次检索多一次云端 API 往返（流量与延迟翻倍，P2 级隐形开销）。首次调用时经 withFallback 计算并缓存（`volatile int`，0=未初始化），后续直接返回缓存值。
3. 新增单测：dimensions 主失败降级备、缓存后不再重复触发主通道、双挂抛错。
4. 修复后重跑 V5 全四项 + `mvn test` + V2 默认零变化。

### P2（不阻塞，随 R1 一并解决）

dimensions 每次检索的重复网络调用（见上，缓存即消）。

### 观察项（不阻塞）

1. **yml 显式 `fallback-enabled: false` 使 D6 默认失效**：k3 首轮 V5 实例只传 `--pf.embedding.primary=cloud`，通道链打出 `fallback=无`——因为 yml 里显式写了 false，raw 三态拿到的是 "false" 而非空串。D6「primary=cloud 默认 true」只在 yml 删掉该行或用参数/env 覆盖时生效。部署文档（SP6）需写明这一点；功能正确，属配置呈现方式风险。
2. **交付 §4 V5③ 声称与实测矛盾**：交付方称 kill stub 后降级 WARN + 正常作答，k3 两次复现均失败。可能其测试路径未走 similaritySearch（如仅验证 embed 直调）或实例状态差异——**验收以 k3 亲测为准**，交付方修复时需自己真机复现 V5③ 通过后再交付。
3. Spring OpenAI 客户端 chunked 传输（交付披露）：k3 自建 stub 同样适配后通过，属实，非缺陷。
