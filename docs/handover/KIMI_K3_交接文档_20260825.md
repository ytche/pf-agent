## 0. 项目是什么

**PathFinder 1e（PF 1e）跑团规则问答 Agent**：用户就 PF 规则提问，Agent 基于规则书内容回答，并给出**目录引导**（tocPath / 来源书）让用户可追溯验证。

一期目标 = 规则问答 Agent；二期（车卡辅助 + Build 建议）未开始。

分两个技术域：
1. **数据准备域** `pf_data/`（Python）：从 CHM 规则书提取的 Markdown 中清洗、向量化，产出可检索的 chunk 库。
2. **Agent 应用域** `pf_agent/agent/`（Java / Spring Boot + Spring AI）：把 chunk 库加载进向量库，由 LLM 工具调用驱动检索 + 生成回答。

## 2. Agent 检索链路（接手前必懂）

```
用户提问 → ChatService
  → LLM 工具决策（自主判断走哪个检索工具，无硬编码意图分类器）
      ├─ vectorSearch(question, module)  → 语义检索（事实点查类）
      ├─ searchByMetadata(...)           → 元数据枚举过滤（列举/聚合类，上限 500）
      └─ reportDataGap(...)              → 记录数据缺口
  → SearchService.search(question, module)
      ├─ SimpleVectorStore.similaritySearch（纯余弦）
      ├─ rankedScore 加权重排（见下）
      └─ limit(topK=15)
  → 组装 sources（含 chunkId/tocPath/book）→ LLM 生成回答 + 目录引导
```

- **module**：`spell / class / feat / race / trait / equipment / skill / rule / all`
- **加权项**（仅影响排序，不改原始 score）：
  - `class-base-bonus +0.03`（class 基础职业页加分）
  - `intro-penalty -0.03`（feat_intro/rule_intro 等低信息量 chunk 降权）
  - `oversize-penalty -0.02`（>5000 字符超长 chunk 降权）
- **关键配置**（`src/main/resources/application.yml`，`pf.search.*`）：`top-k: 15`、`similarity-threshold: 0.5`、`vector-result-chars: 800`、`max-tool-rounds: 10`、`max-history-chars: 50000`。

**⚠️ 已知 bug**：~~`SearchService.isBaseClassPage` 前缀错配~~ **已修复**（P0-B T1，`34e8d8d`：补「核心职业」前缀，CRB 职业基础页起吃 class-base-bonus）。P0-B2 新增 AKN-008 教训：`SourceCollector.drain()` 原按 doc_id（页面级）去重吞掉同页锚点 chunk，已改 chunk_id 去重（`9833088`）——评估历史检索问题时需注意该 bug 此前的掩盖效应。

## 5. 红线（不可违反）

1. **联调前严禁重跑 spell / 职业 pipeline**（KN136 禁令）：spell、职业两模块为冻结模块，产物即交付基线。共享层改动会让 spell 重生成结果漂移（4172→4173 伪标题，已有实证），红线测试读落盘产物无法拦截。**Java 侧从冻结 chunks.jsonl 重建向量库是合法的**（不碰 Python pipeline）。
2. **`术语提取报告_分类版.md` 不可修改**（基线文件，只读）。
3. **讨论阶段不动手**：问题/方案讨论期只读不改，方案经用户明确拍板后再动工。
4. **Java 方法名 camelCase 禁中文**；方法中文说明写 Javadoc。（仅约束 Java，Python 不限）
5. **Spring 依赖注入用 `@Autowired` 字段注入**，配置值用 `@Value` 字段注入，**禁止构造器注入**。（仅约束 Java/Spring）
6. **先理解后向量化 / 先理解代码设计再修 bug**：优先利用已有扩展点（`FileProcessor` 模板方法、`EXPAND_STRATEGIES` 注册表等），禁止在通用流程硬编码 `if class_name == "X"` 业务特判。
7. **回退前暂存**：`git checkout/reset/clean` 前若有未提交改动，先 `git stash`。
8. **每次阶段完成提交 Git + 同步文档**（README/设计文档/进度文档随代码同一次提交）。
9. **规划/审计/总结类工作发现 bug 只记录**（登记 KN/问题清单），不中断主线去修 bug，修复另立任务。
