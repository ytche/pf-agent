## 五、关键决策

1. **POSTPROCESSORS 不装配**：职业 `chm_toc_path`/source 已由老逻辑全覆盖，finalize 后
   处理链会引入非预期行为变化，违反 CP1「逐字段等价」出口标准。
2. **ABC 三抽象方法显式拒用**：`process()` 覆写走老块层逻辑，框架模板链永不触发，
   `build_chunk`/`resolve_source`/`infer_metadata` 三钩子 `raise NotImplementedError`。
3. **canonical 去重固定在 `INPUT_DIR`（职业目录）**：老脚本 `process_profession_corpus`
   的 input_dir 即职业目录；pipeline `--input` 传根目录（判别器矩阵 66 根级 rel 需
   要），若 rglob 根目录会把职业外文件混入去重污染 canonical 集。
4. **路径统一 `resolve()` 归一**：`--input` 相对/绝对两种传法下，canonical 集与
   `process()` 分派均用绝对路径比较，兼容二者。
5. **`source_confidence` 捕获链**：`detect_book` 加 `confidence_out` 参数 →
   `FileProcessor.resolve_source` 记录 `_last_source_confidence` → `build_chunk` 落
   Chunk 字段 → `_to_standard` 映射顶层。老脚本 Chunk 无此字段（§3 新增，无老基准）。

## 七、遗留与说明

1. **terms/aliases 差异为数据演进，非迁移 bug**（k3 口径 B 复核：38 metadata.terms +
   19 aliases，涉及 39 条 chunk）：07-24 老产物用**旧 terms.json** 生成；新 pipeline
   用**当前 terms.json**（08-09 P2 清理，1068 术语），alias→英文映射更新，故同一
   chunk_id 下 metadata.terms / aliases 出现差异。示例：`精魂伙伴` chunk terms
   `["Martial Arts Handbook"]` → `["Pathfinder Player Companion"]`（text 含「玩家伴侣」）。
   **口径 A（patch 后当前老脚本 vs 新 pipeline）terms/aliases 0 差异**，证明差异来源
   是 terms.json 数据演进而非迁移逻辑。

   （不同文件相同 title+text），新旧各 13895 行均含，**行为一致保留**。若需收敛是
   独立决策，不在 CP1 范围。
3. **产出文件 523 < canonical 540**：17 个 canonical 文件产出 0 chunk（被 keep 过滤，
   如纯表格/导航页），老脚本同样如此，非回归。
4. **KN223**：老脚本缩写表路径失效致默认重跑失真（14341），老脚本冻结 + 待退役，
