## 2. 实现要点（对照方案 D1~D7）

### D1 持久化默认化（T1）
- `pf.chat.memory` 默认翻转为 `jdbc`（`${PF_CHAT_MEMORY:jdbc}`）；datasource 默认
  `jdbc:postgresql://localhost:5432/pf_agent`（`pf_agent/pf_agent`，env 可覆盖）；
  `jpa.ddl-auto=validate` + `flyway.enabled=true` 并入主 yml。
- 测试豁免：context 测试 `@SpringBootTest(properties="pf.chat.memory=memory")`；
  `JdbcChatMemoryTest` 追加 `ddl-auto=create-drop`（主 yml 的 validate 会泄漏进 H2 slice 测试）。
  注意：曾尝试 test resources 整文件覆盖 application.yml，会因丢失主配置（api-key 等）失败，已废弃。
- fail-fast：`AuthProperties.validateAuthMode()` —— `pf.auth.enabled=true` 且非 jdbc 启动即失败，
  错误信息明确指引。
- 无 PG 启动报 Flyway 连接拒绝错误（明确），非诡异堆栈（实测）。

### D2 用户表（T2）
`V3__user_account.sql` 严格按方案 schema（BIGSERIAL PK / username VARCHAR(64) UNIQUE NOT NULL /
password_hash VARCHAR(72) / nickname 可空 / created_at / last_login_at），不预留角色/邮箱。
大小写不敏感由应用层归一（trim + 小写）。实测在已有 V1/V2 + 数据的库上平滑 apply。

### D3 依赖与算法（T2）
新增且仅新增两个依赖：`spring-security-crypto`（只用 BCryptPasswordEncoder）+
`io.jsonwebtoken:jjwt-api/impl/jackson 0.12.6`。JWT HS256：sub=username + uid，
`pf.auth.token-ttl-hours` 默认 72h；密钥 `pf.auth.jwt-secret`（env `PF_AUTH_JWT_SECRET`），
yml 开发默认值带警告注释；`enabled=true` 且密钥仍为默认值启动 WARN（不阻断）。

### D4 鉴权接口（T3）
`AuthController`：`POST /api/auth/register|login`（200 返 token+uid+username+nickname）、
`GET /me`（Bearer token → 用户信息，无效 401 unauthorized）、`GET /status`（`{enabled}`）。
错误码语义化：username_taken→409 / invalid_credentials→401 / invalid_request→400，
错误体 `{error, message}`。`/api/auth/**` 全豁免鉴权拦截（WebConfig 路径注册保证）。

### D5 AuthInterceptor 落地（T3）
`enabled=false`（默认）全放行零行为变化；`true` 时只拦 `/api/chat`、`/api/chat/feedback`
（`/api/auth/**`、`/api/health`、静态资源与 `/` 天然不在拦截范围），失败 401
`{error:"unauthorized"}`（与配额 429 `quota_exceeded` 结构区分）；解析出的 username 放
request attribute（`pfAuthUsername`），ChatService 不消费、会话行为不变。

### D6 前端（T4）
`static/index.html`：顶栏登录/注册入口（样式随现有页面）+ 弹层表单（登录↔注册切换）；
token 存 localStorage（`pfAgentAuthToken`），`authFetch()` 统一带 Authorization 头
（chat / feedback / me）；401 清 token + 引导重新登录；启动探测 `/api/auth/status`，
关态入口整体隐藏（现状零变化），有 token 时 `/me` 恢复登录态。

### D7 compose 与文档（T5）
- `docker-compose.yml`：pg 移出 profile 成默认服务；app `depends_on` ollama + pg
  （`condition: service_healthy`）；environment 默认 `PF_CHAT_MEMORY=jdbc` +
  datasource 指向 `pg` 服务 + `PF_AUTH_ENABLED/JWT_SECRET/TOKEN_TTL_HOURS`（默认值与 yml 一致）。
- `.env.example`：PG 段落翻转为"默认 jdbc"；新增 `PF_AUTH_*` 段落（含生产必须覆盖密钥警告）。
- README：功能特性/快速开始/配置表/环境变量速览全部翻转（默认 PG、compose 自带、
  裸 mvn 需本机 PG 或显式 memory）；CI 单测计数 247→287；English Summary 同步。
- `docs/DEPLOYMENT.md`：环境变量表加 `PF_AUTH_*`；形态 1/2 按 PG 默认重写（含"升级即切库：
  内存会话本就不持久，无回归"）；三坑节变**四坑**，坑 ④ = JWT 默认密钥生产警告。
